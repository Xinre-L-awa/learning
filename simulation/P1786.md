# P1786 帮贡排序 题解

## 题意

帮派里有 $n$ 个人，每个人有四项信息：姓名、职位、帮贡、等级。职位之间是有序的，由高到低为 `BangZhu` $\succ$ `FuBangZhu` $\succ$ `HuFa` $\succ$ `ZhangLao` $\succ$ `TangZhu` $\succ$ `JingYing` $\succ$ `BangZhong`。

读完输入后要依次完成两件事：

1. **重新分配职位**：帮主 `BangZhu`、副帮主 `FuBangZhu` 的职位固定不动；其余所有人按「帮贡从高到低，帮贡相同则输入顺序靠前」排名，再按名次依次分职——第 $1\sim2$ 名护法 `HuFa`，第 $3\sim6$ 名长老 `ZhangLao`，第 $7\sim13$ 名堂主 `TangZhu`，第 $14\sim38$ 名精英 `JingYing`，再往后都是帮众 `BangZhong`。
2. **输出**：全体成员按「职位从高到低 → 等级从高到低 → 输入顺序靠前」排序，每行输出**姓名、职位、等级**三列，不输出帮贡。

上面这些名次区间由代码里的阈值 $2,6,13,38$ 反推得到；帮主、副帮主是代码按职位名整组排除的，并不去数人数（题面保证恰好 $1$ 位帮主、$2$ 位副帮主，所以「按名字排除」与「按人数排除」在合法数据上等价）。

## 思路

本题最关键的一句话是：**职位只由帮贡决定，而帮贡不参与最后的输出排序**。这两件事分属两轮排序，而且第二轮的排序关键字「职位」正是第一轮的产物——存在数据依赖，没有可靠的合并写法，所以老老实实先定职位、再定输出顺序。

### 第一轮：把「职位固定」的人摘出去

护法只有 $2$ 个坑，而这 $2$ 个坑是**所有非帮主、非副帮主的人**竞争出来的，所以候选池必须把这两类人整组剔除（判断条件就是职位名等于 `BangZhu` 或 `FuBangZhu`）。

如果偷懒把帮主、副帮主也丢进候选池，这两人就会按帮贡一起参与排名、占掉本该属于别人的名额，后面的人名次被顶后移位，分出来的职位整体错位——这是本题最典型的错法。错位多少取决于这两人自己的帮贡（若他们帮贡偏低，甚至可能完全不错位），所以这种错误靠几组样例很难发现。

候选池里存的是**下标**而不是 `Person` 本身：第一轮只对 `rest` 排序、不动 `p` 本身（`p` 仍按输入顺序排列），`p[i].idx` 天然就是「输入顺序」，第二轮还能继续拿来兜底。

### 第一轮的两个关键字

比较规则是「帮贡降序；帮贡相同则输入顺序升序」。第二关键字不能省：帮贡完全可能相同（极端情况下所有人的帮贡都是 $0$），而 `std::sort` 并不稳定，不写 `p[a].idx < p[b].idx` 兜底的话，同分成员的相对顺序由实现决定，评测就会判错。

### 名额边界：人数要换算成累计名次

副帮主已经被摘出去了，所以护法的 $2$ 个位置从第 $1$ 名开始算，后面依次累加：$1\le r\le 2$ 护法、$3\le r\le 6$ 长老、$7\le r\le 13$ 堂主、$14\le r\le 38$ 精英，其余帮众。判断时用的是**累加后的名次上界** $2,6,13,38$，而不是各职位的人数 $2,4,7,25$。

```cpp
string title_by_rank(int r) {
    if (r <= 2)  return "HuFa";
    if (r <= 6)  return "ZhangLao";
    if (r <= 13) return "TangZhu";
    if (r <= 38) return "JingYing";
    return "BangZhong";
}
```

这种链式 `if` 只判上界是安全的，因为前面的分支已经把更小的 $r$ 拦掉了；但若把上界写成 `r <= 2 / r <= 4 / r <= 7 / r <= 25` 就会出错——那四个数是各职位的**人数**，不是累计名次。

### 第二轮：职位权值 + 等级 + 输入顺序

用一个 `map<string,int>` 把职位串映射成权值 $7\sim1$（`BangZhu` 最高、`BangZhong` 最低），比一长串 `if` 更好写、也不容易拼错。三个关键字分别判断，最后用 `idx` 兜底，保证职位和等级都相同时仍按输入顺序输出。注意第二轮的关键字里**没有帮贡**：帮贡的使命在分配职位时就已经用完了。

## 复杂度

两次排序都是 $O(n \log n)$（每次比较都是 $O(1)$，`map` 只有 $7$ 个键，查找可视为常数），读入与输出是线性的。故总时间复杂度 $O(n \log n)$，空间复杂度 $O(n)$。

## 参考代码（C++17）

```cpp
#include <bits/stdc++.h>
using namespace std;

map<string,int> rank_of = {
    {"BangZhu",7},{"FuBangZhu",6},{"HuFa",5},
    {"ZhangLao",4},{"TangZhu",3},{"JingYing",2},{"BangZhong",1}
};

struct Person {
    string name, title;
    int cont, level, idx;
};

string title_by_rank(int r) { // r 从 1 开始（排除帮主副帮主后的名次）
    if (r <= 2)  return "HuFa";
    if (r <= 6)  return "ZhangLao";
    if (r <= 13) return "TangZhu";
    if (r <= 38) return "JingYing";
    return "BangZhong";
}

int main() {
    int n; cin >> n;
    vector<Person> p(n);
    for (int i = 0; i < n; i++) {
        cin >> p[i].name >> p[i].title >> p[i].cont >> p[i].level;
        p[i].idx = i;
    }

    // 第一轮：排除帮主/副帮主，按 (帮贡↓, 输入顺序↑) 排序，重新分配职位
    vector<int> rest;
    for (int i = 0; i < n; i++)
        if (p[i].title != "BangZhu" && p[i].title != "FuBangZhu")
            rest.push_back(i);

    sort(rest.begin(), rest.end(), [&](int a, int b){
        if (p[a].cont != p[b].cont) return p[a].cont > p[b].cont;
        return p[a].idx < p[b].idx;
    });

    for (int r = 0; r < (int)rest.size(); r++)
        p[rest[r]].title = title_by_rank(r + 1);

    // 第二轮：全部人按 (职位↓, 等级↓, 输入顺序↑) 排序并输出
    sort(p.begin(), p.end(), [](const Person& a, const Person& b){
        int ra = rank_of[a.title], rb = rank_of[b.title];
        if (ra != rb) return ra > rb;
        if (a.level != b.level) return a.level > b.level;
        return a.idx < b.idx;
    });

    for (auto& x : p)
        printf("%s %s %d\n", x.name.c_str(), x.title.c_str(), x.level);
    return 0;
}
```

## 易错点

1. **第一轮要排除帮主、副帮主**。候选池里混进这两人，他们会挤占按帮贡本该属于别人的名额，名次与职位整体错位（错位多少取决于这两人的帮贡），且错得非常隐蔽（人名对、职位不对）。
2. **帮贡相同必须按输入顺序**。不要指望 `std::sort` 的稳定性，显式写 `p[a].idx < p[b].idx` 才是正解。
3. **名额边界是累计名次，不是人数**。正确写法是 `r <= 2 / 6 / 13 / 38`；写成 `r <= 2 / 4 / 7 / 25` 会让第 $5$ 名直接被判成堂主。
4. **第二轮漏掉输入顺序兜底**。职位与等级都相同时不写 `idx`，输出就是多解的，评测会挂。
5. **输出只有三列**（姓名、职位、等级），不要顺手把帮贡也打印出来。
6. **职位字符串必须与题面逐字符一致**（`FuBangZhu` 的 `Fu`、`ZhangLao`、`BangZhong` 这些大小写），映射表里拼错一个字母，该职位就会被当成最小的权值。
7. `rank_of[a.title]` 用的是 `operator[]`：万一出现表里没有的职位串，它会静默插入权值 $0$（排到最后），并在排序过程中修改这张全局表。本题输入受题面保证不会触发，但更稳妥的写法是 `rank_of.at(title)` 或先 `find`。
8. **帮贡的存储类型**。代码用 `int` 存帮贡，可见数据范围在 `int` 以内；若换到范围更大的题面，需要改成 `long long` 再比较。

## 总结

两次「关键字不同、参与者不同」的排序模拟：先用帮贡定职位（候选人必须剔除职位固定者，同分按输入顺序），再用职位权值、等级、输入顺序定输出（同样要兜底输入顺序）。题目本身没有算法难点，失分点全在细节——排除谁、边界写成累计名次、以及每一处 tie-break。

# Ingenuity-2 题解

## 题意

有 $t$ 组数据，每组给出指令条数 $n$ 和一条长度为 $n$ 的指令串，字符取自 `N`、`S`、`E`、`W`。要把**每一条**指令指派给两个人之一（记作 `H` 和 `R`，输出串第 $i$ 个字符即第 $i$ 条指令的归属），要求两人各自至少分到一条指令，且所有指令执行完后两人最终坐标完全相同；输出任意一种合法指派，无解输出 `NO`。

方向与坐标的对应（`N` 使纵坐标 $+1$、`S` 使 $-1$、`E` 使横坐标 $+1$、`W` 使 $-1$）是解题前必须约定的建模前提——代码只统计四个方向各出现几次，并不体现符号本身；「每人至少一条」这一限制则由代码末的 `if (h_cnt == 0 || r_cnt == 0)` 体现；$n$ 的具体范围代码中没有体现。

## 思路

**顺序无关，只有四个计数有用。** 一个人的最终坐标只取决于他拿到的指令里四个方向各多少条，与先后次序无关。设整串中四种字符出现次数为 $c_N,c_S,c_E,c_W$，问题就退化成：给 `H` 分一个四元组条数，剩下的全归 `R`，使两人位移相等。答案不唯一，任意一种都行。

**把「两人位移相等」翻译成对差值的要求。** 记总位移
$$\Delta x = c_E - c_W,\qquad \Delta y = c_N - c_S .$$
若 `H` 的位移是 $(x,y)$，`R` 的位移就是 $(\Delta x - x,\ \Delta y - y)$，两者相等只有唯一解 $x=\Delta x/2,\ y=\Delta y/2$。所以必要条件是两个差值都为偶数，否则某人得走「半格」，直接 `NO`；它还顺带强制 $n$ 为偶数（$\Delta x$ 与 $c_E+c_W$ 同奇偶，$\Delta y$ 与 $c_N+c_S$ 同奇偶）。

**主构造：让 H 只拿「差值的一半」。** 既然 `H` 的位移被钉死为 $(\Delta x/2,\Delta y/2)$，最省事的做法是：

- 纵向：$\Delta y>0$ 时让 `H` 拿 $\Delta y/2$ 条 `N`，$\Delta y<0$ 时拿 $-\Delta y/2$ 条 `S`，$\Delta y=0$ 则纵向一条不拿；
- 横向：$\Delta x>0$ 时拿 $\Delta x/2$ 条 `E`，$\Delta x<0$ 时拿 $-\Delta x/2$ 条 `W`。

其余指令统统给 `R`，它的位移自动等于「总位移减 `H` 的位移」$=(\Delta x/2,\Delta y/2)$。这里的关键认识是：**成对的 `N`/`S`、`E`/`W` 净位移为 $0$，分给谁都不影响结果**，所以根本不必讨论「成对部分怎么平分、多出来的一半归谁」这类分支，把它们整体丢给 `R` 即可。这一步 `R` 也必然非空，因为 $|\Delta x|\le c_E+c_W$、$|\Delta y|\le c_N+c_S$，故 `H` 至多拿
$$\frac{|\Delta x|+|\Delta y|}{2}\le \frac{n}{2}$$
条，剩下至少 $n/2\ge 1$ 条归 `R`。

**补丁：`H` 可能一条都拿不到。** 这恰好发生在 $\Delta x=\Delta y=0$（每个轴上正反方向条数相等）时。要让 `H`「动了又不改变位移」，最少得塞给它一对互相抵消的指令：$c_N\ge1$ 且 $c_S\ge1$ 时给 `N`+`S`；否则 $c_E\ge1$ 且 $c_W\ge1$ 时给 `E`+`W`；两者都不成立说明串里没有成对指令，而 $\Delta x=\Delta y=0$ 又说明指令数为 $0$，输出 `NO`。补完还要再看 `R`：若这一对正好用光了全部指令（只有 $n=2$ 会这样）`R` 就空了，同样 `NO`。这类输入恰好是 `NS`、`SN`、`EW`、`WE`，它们本来无解——两条指令必须一人一条，而 `N` 与 `S`（或 `E` 与 `W`）落在不同位置。换个说法就是：把每个方向的指令两两配成「净零的一对」，这些对怎么分都不影响位移，同一方向多出来的部分必须一人一半（各 $\Delta/2$ 条），成对的部分则随意分；于是真正要判的只有「补完一对之后还有人一条指令都没有」这一件事，而补完仍然无解的确实只有 $n=2$ 的那四个串。

按这个思路写只有十来行（仅作思路示意，正式参考代码仍是 [ans.cpp](ans.cpp)）：

```cpp
int c[128] = {0};
for (char ch : s) c[ch]++;
int dx = c['E'] - c['W'], dy = c['N'] - c['S'];
if (abs(dx) % 2 || abs(dy) % 2) { cout << "NO\n"; continue; }
int q[128] = {0};                                 // H 每种指令的配额
if (dy > 0) q['N'] = dy / 2; else if (dy < 0) q['S'] = (-dy) / 2;
if (dx > 0) q['E'] = dx / 2; else if (dx < 0) q['W'] = (-dx) / 2;
if (!q['N'] && !q['S'] && !q['E'] && !q['W']) {   // H 空着，补一对净零指令
    if (c['N'] && c['S']) q['N'] = q['S'] = 1;
    else if (c['E'] && c['W']) q['E'] = q['W'] = 1;
}
int need = q['N'] + q['S'] + q['E'] + q['W'];
if (need == 0 || need == n) { cout << "NO\n"; continue; }  // 凑不出对 / 把 R 挤空
for (char ch : s) { if (q[ch]) { --q[ch]; cout << 'H'; } else cout << 'R'; }
cout << '\n';
```

**参考代码是同一结论的镜像写法。** [ans.cpp](ans.cpp) 没有把成对指令整体丢给 `R`，而是反过来整体留给 `H`：正反条数不等的轴上，`H` 拿「$t/2$ 条多的一方 $+$ 全部少的一方」（$t$ 为两侧条数之差），`R` 只拿剩下的 $t/2$ 条；正反条数相等的轴则整轴归 `H`。两人的位移因此仍各为 $(\Delta x/2,\Delta y/2)$，只是「成对部分」换了主人，所以两种写法给出的 `H`/`R` 串可以不同而都合法（`NSEW` 一例：上面的思路给 `HHRR`，参考代码给 `RRHH`）。镜像的后果是易空的一侧从 `H` 变成 `R`：代码里那两个补丁就是在 `r` 一条都没有时，把一对指令从 `h` 挪到 `r`；而 `H` 空只剩 $n=2$ 那种情形，最终由 `h_cnt == 0` 挡住。这也是为什么它的分支比上面的示意多——本质上是同一件事的另一种分法，不是别的算法。

## 复杂度

每组统计一遍字符、再扫一遍原串输出：时间 $O(n)$，额外空间 $O(1)$（不计输出串），总复杂度 $O(\sum n)$。参考代码用 `map<char,int>` 存计数，键数固定为 4，同样可视为常数空间，只是常数偏大。

## 参考代码（C++17）

下面是 [ans.cpp](ans.cpp) 的实现，为控制篇幅仅合并了空行与部分短语句，逻辑未改动。

```cpp
#include <bits/stdc++.h>
using namespace std;
using ll = long long;

int main() {
    ios::sync_with_stdio(false); cin.tie(nullptr);
    int t; cin >> t;
    while (t-- > 0) {
        int n; string s; cin >> n >> s;
        map<char, int> cnt;
        for (int i = 0; i < n; i++) cnt[s[i]]++;
        if (abs(cnt['N'] - cnt['S']) % 2 == 1 || abs(cnt['E'] - cnt['W']) % 2 == 1) {
            cout << "NO\n";
            continue;
        }
        map<char, int> h, r;
        bool f1 = true, f2 = true;
        if (cnt['N'] > cnt['S']) {
            int t = cnt['N'] - cnt['S'];
            h['N'] = t / 2 + cnt['S']; h['S'] = cnt['S'];
            r['N'] = t / 2; r['S'] = 0;
        } else if (cnt['N'] < cnt['S']) {
            int t = cnt['S'] - cnt['N'];
            h['S'] = t / 2 + cnt['N']; h['N'] = cnt['N'];
            r['S'] = t / 2; r['N'] = 0;
        } else {
            h['N'] = cnt['N']; h['S'] = cnt['S'];
            r['N'] = 0; r['S'] = 0;
        }
        if (h['N'] >= 1 && h['S'] >= 1) {
            if (r['N'] == 0 && r['S'] == 0) { r['S']++; h['S']--; r['N']++; h['N']--; }
            f1 = true;
        } else if (r['N'] > 0 || r['S'] > 0) {
            f1 = true;
        } else { f1 = false; }
        if (cnt['E'] > cnt['W']) {
            int t = cnt['E'] - cnt['W'];
            h['E'] = t / 2 + cnt['W']; h['W'] = cnt['W'];
            r['E'] = t / 2; r['W'] = 0;
        } else if (cnt['E'] < cnt['W']) {
            int t = cnt['W'] - cnt['E'];
            h['W'] = t / 2 + cnt['E']; h['E'] = cnt['E'];
            r['W'] = t / 2; r['E'] = 0;
        } else {
            h['E'] = cnt['E']; h['W'] = cnt['W'];
            r['E'] = 0; r['W'] = 0;
        }
        if (h['E'] >= 1 && h['W'] >= 1) {
            if (r['N'] == 0 && r['S'] == 0 && r['E'] == 0 && r['W'] == 0) {
                r['E']++; h['E']--; r['W']++; h['W']--;
            }
            f2 = true;
        } else if (r['E'] > 0 || r['W'] > 0) {
            f2 = true;
        } else { f2 = false; }
        if (!(f1 || f2)) { cout << "NO\n"; continue; }
        string ans = ""; int h_cnt = 0, r_cnt = 0;
        for (int i = 0; i < n; i++) {
            char ch = s[i];
            if (h[ch] > 0) { ans += 'H'; h[ch]--; h_cnt++; }
            else { ans += 'R'; r_cnt++; }
        }
        if (h_cnt == 0 || r_cnt == 0) { cout << "NO\n"; }
        else { cout << ans << '\n'; }
    }
    return 0;
}
```

## 易错点

1. **奇偶只判了一半、或判错对象。** 必须分别检查 $|c_N-c_S|$ 与 $|c_E-c_W|$ 为偶数，不能只看 $n$ 为偶数：例如 `NE` 的 $n=2$ 是偶数，但两轴差值都是 $1$，一人一条必然一个在 $(1,0)$、一个在 $(0,1)$，无解。判奇偶也别写 `dx % 2 == 1`，C++ 负数取模是负的（$dx=-3$ 时 `dx % 2` 得 $-1$），应写 `abs(dx) % 2 != 0`。

2. **忘了「每人至少一条」。** 这是本题唯一的构造细节：总位移为 $0$ 时主构造会让 `H` 空手，必须补一对净零指令；补完之后 $n=2$ 的 `NS`/`EW` 又会让另一个人空手，仍是 `NO`。只「平分差值」而不检查非空性，会输出一个人一条指令都没有的非法答案却当成合法。

3. **参考代码那种「逐分支打补丁」的写法可读性差、改动时容易出错，不建议照搬。** 它先按南北、东西两组各自平分差值，再在「`R` 某条轴一条指令都没拿到」时打两个补丁，隐患在于：
   - 两个标记 `f1`、`f2` 其实不承担判定职责。由各分支可推出 `f1` 为假当且仅当 $c_N=c_S=0$、`f2` 为假当且仅当 $c_E=c_W=0$，于是 `!(f1 || f2)` 只在整个串没有任何指令时才成立，基本是死分支；真正的判定被埋在末尾的 `h_cnt == 0 || r_cnt == 0`。读者很容易误以为奇偶之外的判定是在 `f1`/`f2` 处完成的。
   - 两个补丁的触发条件不对称：纵向补丁只要「`r` 在纵向没有指令」（`r['N'] == 0 && r['S'] == 0`）就搬一对 `N`+`S` 过去，横向补丁却要求「`r` 四个方向全空」才搬 `E`+`W`（条件长了一倍）。这依赖「先纵后横」的既定顺序：一旦交换两轴顺序、或改动某分支里 `h`/`r` 的初值，横向补丁就会在完全不同的时机触发，而末尾兜底检查又会把这些情况一起吞成 `NO`，很难察觉。
   - 它隐式依赖「前面已判定两轴差值都是偶数」，`t / 2` 才成立；若把奇偶判断挪后、或改成对 $n$ 的判断，这里会静默截断，得到看似合理其实错误的分配。

4. **另一种常见错法：把四个方向的条数分别「分半」**（$c_N/2$ 条 `N` 给 `H`、$c_S/2$ 条 `S` 给 `H`，依此类推）。这只在每个方向条数都为偶数时成立，条件过强：`NSEW` 四个方向各 $1$ 条时 `H` 只能拿 $0$ 条，会被误判成无解，而正确答案存在（一人 `N`+`S`，另一人 `E`+`W`）。

5. **写答案要按原串顺序扣配额。** 配额按字符种类记，输出时必须顺着原串扫：该字符还有配额就发 `H` 并减一，否则发 `R`——这样天然保证答案长度为 $n$、每种指令恰好用掉原串中那么多个；若按方向排序再回填，配额和实际指令很容易对不上。另外多组数据每组都要重建计数，把 `map` 换成全局 `int cnt[128]` 时最容易忘记清零。

## 总结

顺序无关 → 只看四方向计数 → 两人的位移都必须等于总位移的一半 → 让 `H` 只拿「差值的一半」、其余整体归 `R`（成对指令净位移为 $0$，无需讨论如何平分；参考代码反过来把成对部分给 `H`，等价）→ 最后补「`H` 空」「`R` 空」两种退化情形，每组 $O(n)$。

## 说明

两人用 `H`、`R` 标记和「每人至少分到一条指令」这两点由代码直接体现，方向到坐标的对应则采用通常约定（`N` 为纵坐标 $+1$）；具体数据范围与官方样例在代码中无法确定，故未写死。

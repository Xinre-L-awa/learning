# [NOIP 2006 提高组] 作业调度方案 题解

## 题意

有 $m$ 台机器、$n$ 个工件。每个工件有 $m$ 道工序，工序顺序固定，第 $k$ 道工序用哪台机器、耗时多少由输入给出。由代码可读出输入依次为：先读 $m$、$n$；再读长度为 $n\times m$ 的**安排顺序**（每个工件编号恰好出现 $m$ 次，出现一次表示“现在轮到给它安排下一道工序”）；然后依次读 $n$ 行 $m$ 列的机器号表、$n$ 行 $m$ 列的耗时表。安排时必须同时满足两条硬约束：同一工件的工序依次进行（后一道开工不早于前一道完工）；同一台机器同一时刻只能加工一道工序。按给定顺序逐道安排、每道在可行前提下尽早开工，求全部工序完工的时刻。由代码可推断所有耗时均为整数，时间轴长度被硬写成常量 $10005$。

## 思路

### 1. busy 表：把连续时间切成单位格子

所有耗时都是整数，起点也一定可以取整数——若有方案在两道相邻工序之间留下空隙，把后面那道整体左移不会破坏任何约束。于是时间轴可以离散成单位格子：

$$\text{busy}[x][t]=1\iff \text{机器 } x \text{ 在时间片 } [t,\;t+1) \text{ 内被占用}$$

这是**半开区间**约定：耗时 $dur$、起点 $start$ 的工序占用的格子是 $start,\dots,start+dur-1$，完工时刻正好是 $start+dur$。半开区间的右端点本身就是“可以重新开工的时刻”，所以 `last_end` 直接存 $start+dur$，后面不需要任何 $\pm1$ 修正。时间轴从 $0$ 编号，于是“某台机器在某段时间是否空闲”就退化成“一段格子是否全为 $0$”，判定只要一个循环。

### 2. 顺序固定 ⇒ 没有决策分支

安排顺序和每道工序用的机器都是输入给定的，每台机器上要加工哪些工序、按什么次序依次去安排，也由这个全局顺序唯一确定。但这**不等于时间上的先后**——先安排的只是位置先被钉死，后安排的仍可能插进它前面的空档。所以每道工序只剩**一个**自由度：开工时刻，而“尽早”把它逼成唯一值：

$$\text{start}=\min\{\,s\ge \text{last\_end}[j]\ :\ \text{busy}[ma][s..s+dur-1]\ \text{全空}\,\}$$

其中 $\text{last\_end}[j]$ 是工件 $j$ 上一道工序的完工时刻（初始 $0$）。**这个下界不能省**：它保证同一工件的工序串行而不是并行，少了它两道工序会叠进同一段时间。整题因此只是一次模拟，没有搜索也没有回溯——“能早不晚”之所以安全，是因为区间长度由耗时定死，往前挪只会让本工件后续工序的下界更小、让本机器留给后面的空闲整体前移。

### 3. 找空闲区间的两种写法

**写法一：逐格检查 + 右移一格重试**（本目录 `.cpp` 采用）

```cpp
int start = last_end[j];
while (true) {
    bool ok = true;
    for (int t = start; t < start + dur; t++) {
        if (busy[ma][t]) {ok = false; break;}
    }
    if (ok) break;
    start++;
}
```

从下界开始，把长度 $dur$ 的窗口整个试一遍；撞到占用就把起点加一重试。缺点很明显：每次失败只挪一格，刚验过的 $dur-1$ 个空位下一轮还要重验。

**写法二：连续计数，一遍扫过**（另一种常见写法，时间轴是 1-based 闭区间）

```cpp
int s = 0;
for (int j = las_time[now] + 1; ; j++) {
    if (mac[id][j] == 0) s++;
    else s = 0;
    if (s == cost) {
        for (int k = j - cost + 1; k <= j; k++) mac[id][k] = 1;
        if (j > ans) ans = j;
        las_time[now] = j;
        break;
    }
}
```

思路反过来：不试窗口，而是从左往右数“当前已经连续遇到几个空格”。计数器 $s$ 到 $cost$ 时右端点 $j$ 就确定了，窗口是 $j-cost+1\dots j$；时间轴只前进不后退，每个格子最多看一次。注意两套约定的差别：写法二的 $mac$ 是 1-based、$j$ 是窗口**右端点**（闭区间），所以 `las_time` 存最后被占用的格子，扫描从 `las_time+1` 起、答案取 `ans = j`；写法一是 0-based 半开区间，`start` 是左端点、`last_end` 是右端点（等于下一格的编号）。两者各自自洽，混用就整体错一格。

### 4. 两种找空闲区间的复杂度对比

设某道工序从初始下界到最后起点跨过的距离为 $\Delta$，耗时为 $dur$，时间轴扫描上界为 $T$。

- 写法一：最多重试 $\Delta$ 次、每次最多验 $dur$ 格，单道 $O(\Delta\cdot dur)$，最坏 $O(T\cdot dur)$。
- 写法二：每个格子只被扫一次，单道 $O(\Delta+dur)$，最坏 $O(T)$。

**结论：写法二的渐进界严格更优，它省掉的是“每右移一格就把整个窗口重验一遍”的重复工作，而不是“检查格子”这个动作本身。** 反过来说，写法一慢的根源不在逐格检查，而在 `start++` 一次只挪一格：把失败后的 `start++` 换成 `start = t + 1`（$t$ 是撞到的占用格）就能拿到和写法二相同的 $O(\Delta+dur)$——当前这个候选窗口自身就含 $t$，于是任何 $s'\in[\text{start},t]$ 的窗口也都含 $t$、全部非法（更小的 $s'$ 在前几轮已逐一否决），而跳过之后先前验过的格子再也不会被重复检查。所以要不要维护计数器纯粹是写法偏好；本题 $T$ 只有 $10^4$ 量级、$\Delta$ 实际很小，两种写法都能过。

## 复杂度

设 $L=\sum_{j,k}\text{time}[j][k]$，完工时刻不超过 $L$；代码把时间轴上界硬写成 $T=10005$，实际扫描深度不会超过完工时刻。两种写法都还要额外 $O(dur)$ 把窗口置 $1$，这一项相同且量级远小于扫描，实际 $\Delta$ 只等于“挡路那段占用有多长”、远小于 $T$，所以都是毫秒级。

- 空间：`busy` 是 $O(mT)$ 的布尔表，输入两张表 $O(nm)$，其余 $O(n)$。
- 写法一：单道 $O(\Delta\cdot dur)$，最坏每道 $O(T\cdot d_{\max})$，总计 $O(nm\,T\,d_{\max})$；改用跳格后降到 $O(nm\,T)$。
- 写法二：单道 $O(\Delta+dur)=O(T)$，总计 $O(nm\,T)$。

## 参考代码（C++17）

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int m, n;
    cin >> m >> n;
    vector<int> order(m * n);
    for (int i = 0; i < m * n; i++)
        cin >> order[i];

    vector<vector<int>> machine(n + 1, vector<int>(m + 1));
    vector<vector<int>> time(n + 1, vector<int>(m + 1));
    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= m; j++)
            cin >> machine[i][j];
    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= m; j++)
            cin >> time[i][j];

    vector<int> step(n + 1, 0);
    vector<int> last_end(n + 1, 0);
    const int MAXT = 10005;
    vector<vector<bool>> busy(m + 1, vector<bool>(MAXT, false));

    int ans = 0;
    for (int i = 0; i < n * m; i++) {
        int j = order[i];          // 当前工件
        int k = ++step[j];         // 当前是它的第几道工序
        int dur = time[j][k];
        int ma = machine[j][k];    // 用哪台机器
        int start = last_end[j];   // 起点下界：同工件上一道工序的完工时刻
        while (true) {
            bool ok = true;
            for (int t = start; t < start + dur; t++) {
                if (busy[ma][t]) { ok = false; break; }
            }
            if (ok) break;
            start++;
        }
        for (int t = start; t < start + dur; t++) {
            busy[ma][t] = true;
        }
        last_end[j] = start + dur;
        ans = max(ans, last_end[j]);
    }

    cout << ans;

    return 0;
}
```

## 易错点

1. **维度别读反**：代码先读 $m$（机器数）再读 $n$（工件数），`busy` 开 $m+1$ 行，`step`/`last_end` 开 $n+1$，机器表和耗时表按“工件 × 工序”存成 $(n+1)\times(m+1)$。当成“$n$ 台机器 $m$ 个工件”，两维会同时错。
2. **`int k = ++step[j];` 必须是前置自增**。写成 `step[j]++` 拿到的是旧值，第一道工序就会去读 `time[j][0]`，整条流水线错位。
3. **起点下界不能从 $0$ 搜**。`start = last_end[j]` 是同工件串行的唯一保证；改成 `start = 0` 后，同一工件的多道工序会被塞进同一时间段，答案偏小。
4. **时间轴约定要一致**。`busy[x][t]` 表示格子 $[t,t+1)$，放置 $dur$ 占 `start..start+dur-1`，记 `last_end = start+dur`；若记成 `start+dur-1`，下一道工序就会和上一道最后一格重叠。抄写法二时同理：它用 1-based 闭区间，`las_time` 是最后被占用的格子，扫描从 `las_time+1` 起、答案取 `j`，且遇到占用格必须 `s = 0` 重置，漏了这一句计数器会一路累加、任何位置都“凑够长度”。
5. **`MAXT` 是硬编码上界**。`vector::operator[]` 不做越界检查，时间轴开小了就是未定义行为且极难查；稳妥做法是按 $\sum \text{time}$（或“单台机器的总工时”）开动态大小，别照抄常量。
6. **答案是所有工序完工时间的最大值**，不是最后被安排的那道工序的完工时刻。代码每放完一道就 `ans = max(ans, last_end[j])`，天然覆盖；若只在循环外取某个工件的 `last_end`，遇到别的工件拖得更晚就会错。

## 总结

这题的关键不是算法套路，而是**把物理时间离散成一张布尔表**，再把两条约束翻译成两个条件：同工件串行 → 起点下界 `last_end[j]`；同机器互斥 → 窗口全空。翻译完，剩下的就是“从下界出发向右找第一段足够长的空区间”。两种写法只在“怎么找”上有别：逐格重试直观但会重扫，连续计数单调但要多维护一个计数器；把重试的步长从 $1$ 改成“撞墙就跳到占用格之后”，两者就统一到 $O(T)$。

## 说明

`.cpp` 里 `MAXT = 10005` 是按原始数据范围取的常量，代码依赖“答案不超过它”这一隐含前提；上文引用的连续计数写法用的是 1-based 闭区间、以右端点记录位置，与本目录 `.cpp` 的 0-based 半开区间不是同一套约定，对照阅读时以 `.cpp` 的代码为准。

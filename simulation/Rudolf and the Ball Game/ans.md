# Rudolf and the Ball Game 题解

## 题意

$n$ 个人按编号 $1\sim n$ 顺时针围成一圈，球一开始在编号 $x$ 的人手上。接下来有 $m$ 次投掷，第 $i$ 次投掷的距离是 $d_i$，方向用字符给出：`0` 表示顺时针，`1` 表示逆时针，`?` 表示两个方向都有可能。

问 $m$ 次投掷结束后，哪些编号的人可能拿到球。输出两行：第一行是人数 $k$，第二行是这 $k$ 个编号，按**升序**输出。有 $t$ 组数据。

输入格式：每组数据先读 $n\ m\ x$，随后 $m$ 行每行读一个距离 $d$ 和一个方向字符 $c$。

## 思路

### 状态是一个集合，不是一个点

因为方向可能未知，答案天然是一批人而不是一个人。最直接的想法是枚举所有 $2^{m}$ 种方向组合，这显然会爆炸。但注意：**同一个编号只要有可能出现一次，之后它的后续行为就完全一样**，重复的编号不需要区分来源。所以正确的状态是「当前所有可能持球的人构成的集合」，用集合整体推进，规模最多 $n$。

于是每一轮做的事情是：把当前集合里每个点都做一次「平移」，得到新集合。这正是本题本质——一次投掷是集合上的一个批量平移操作，而不是对某个单点的一次转移。

### 环上的下标：先转 0 下标再取模

把人编号映射到 $[0,n-1]$ 上的偏移量，平移就变成了纯加法，最后再映射回 $1\sim n$。顺时针走 $d$，偏移量加 $d$；逆时针走 $d$，偏移量减 $d$。两种情况分别是

$$p' = (p-1+d)\bmod n + 1 \qquad \text{（顺时针）}$$

$$p' = (p-1-d+n)\bmod n + 1 \qquad \text{（逆时针）}$$

**为什么逆时针要先 $+n$ 再取模？** 因为 C++ 的 `%` 是「截断取模」而不是数学上的非负取模：`-1 % 5` 得到 `-1` 而不是 `4`。如果不补 $n$，负的结果会直接变成非法下标（甚至负数下标）。补上一个 $n$ 就能保证被除数非负，从而 `%` 的结果落在 $[0,n-1]$。

只补一个 $n$ 够不够？被减掉的部分是 `d % n`（`ans_set.cpp` 里写成 `r % n`），它最大是 $n-1$，所以 `p-1-(d%n)+n ≥ p-1+1 ≥ 1 > 0`，一个 $n$ 就够了。正因为要配合这个「最多减 $n-1$」的前提，代码里没有直接把 `- d` 塞进去，而是先对 $d$ 取模。

### 每轮必须去重

$m$ 轮下来，如果不去重，状态数量会按「每轮最多 $\times 2$」的方式膨胀，$O(2^m)$ 直接超时；而且大量编号反复出现在候选里，对答案毫无贡献。`ans_set.cpp` 直接用 `set`——插入时自动去重、自动升序，一行代码同时解决去重和排序；`ans_vector.cpp` 用 `vector` 存下一层，配一个大小为 $n+1$ 的 `vector<bool> is` 做桶去重，把「是否已经在候选里」的查询降到 $O(1)$。

这里有个容易忽略的细节：`is` 必须在**每一轮开始时重新清零**，因为标记的有效范围只是当前这一轮的结果集，跨轮复用会把上一轮的编号误判成已经出现。

### 关于 `ans_vector.cpp` 按操作类型排序

`ans_vector.cpp` 在读完后做了一次 `sort`，把 `0`（顺时针）、`1`（逆时针）、`2`（`?`）三类操作按类型分块重排，**改变了原本的投掷顺序**。这看起来像是把题意改掉了，但它不影响答案，理由要落到式子上：

设第 $i$ 次投掷选择的方向符号为 $\varepsilon_i \in \{+1,-1\}$（`0` 只能取 $+1$，`1` 只能取 $-1$，`?` 两种都允许），那么最终位置（0 下标下）恒为

$$\Big(p_0 + \sum_{i=1}^{m}\varepsilon_i d_i\Big)\bmod n$$

这是一个**与求和顺序无关**的和式：可达集合就是 $x$ 加上每种合法符号组合的和（模 $n$），集合的并运算又可交换、可结合，所以把 $d_i$ 们换个顺序加，最终可达集合一模一样。

但要强调两点，否则很容易误读这段代码：

1. **不受影响的只有最终答案，中间集合是会变的**。排完序后第 $k$ 轮算出的集合，跟真实第 $k$ 次投掷后的集合并不相同，只是走完 $m$ 轮后两边会落到同一个集合。所以不能用这个代码去回答「第几轮之后谁可能持球」之类的问题。
2. 这个排序对正确性与效率都没有帮助（反而多了 $O(m\log m)$），属于「结果上可以这么做，但没有必要」的写法。它能成立的前提正是「每步只是给当前位置加一个与当前状态无关的 $\pm d$」；一旦某步的走向依赖当前持球人（比如按编号奇偶决定方向），排序就会立刻出错。

### 输出

`set` 天然有序，直接从头遍历即可；`vector` 版新集合的顺序取决于弹栈的先后（`cur.back()` 取元素），既不保证升序也不按编号排列，输出前必须再 `sort` 一次。两个版本都先输出人数再输出列表，且都处理了多组数据。

## 复杂度

设人数为 $n$、投掷次数为 $m$、数据组数为 $t$。

- `ans_set.cpp`：每轮候选数不超过 $n$，每个点两次插入，每次 $O(\log n)$，时间 $O(mn\log n)$；空间 $O(n)$。
- `ans_vector.cpp`：每轮候选数不超过 $n$，每点 $O(1)$，另有每轮清零桶的 $O(n)$ 和一次排序 $O(m\log m)$，时间 $O(mn + m\log m)$；空间 $O(n+m)$——它不像 `set` 版能边读边算，得先把 $m$ 个操作存进 `vector<Op>` 才能按类型重排。

## 参考代码（C++17）

```cpp
#include <bits/stdc++.h>
using namespace std;

void solve() {
    int n, m, x;
    cin >> n >> m >> x;

    set<int> cur;      // 当前可能持球的玩家：自动去重且有序
    cur.insert(x);

    for (int i = 0; i < m; i++) {
        int r;
        char c;
        cin >> r >> c;

        set<int> nxt;               // 下一轮的可能持球者
        for (int p : cur) {         // 对集合整体做平移
            if (c == '0') {         // 顺时针
                nxt.insert((p - 1 + r) % n + 1);
            } else if (c == '1') {  // 逆时针：先加 n 保证被除数非负
                nxt.insert((p - 1 - r % n + n) % n + 1);
            } else {                // 方向未知：两个落点都收进 nxt
                nxt.insert((p - 1 + r) % n + 1);
                nxt.insert((p - 1 - r % n + n) % n + 1);
            }
        }
        cur = nxt;
    }

    cout << cur.size() << "\n";
    for (auto it = cur.begin(); it != cur.end(); ++it)
        cout << *it << (next(it) == cur.end() ? "" : " ");  // 行末不留空格
    cout << "\n";
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int t;
    cin >> t;
    while (t--) solve();
    return 0;
}
```

## 易错点

1. **逆时针直接写 `(p - d) % n`**：C++ 负数取模仍为负，会得到非法下标。必须先 `+ n`（或被减数改成 `p - 1 - d % n + n`）再取模。注意补的 $n$ 的个数要够：若写成 `p - d` 且 $d$ 可能很大，一个 $n$ 未必够，所以 `ans_set.cpp` 用 `r % n` 先把减数压到 $n-1$ 以内。
2. **忘记每轮去重**：状态数按 $2^m$ 膨胀，还会做大量重复工作。`vector` 手写去重时最好配一个标记数组；每轮事后 `sort + unique` 也能过，只是每轮多一次 $O(n\log n)$。
3. **标记数组不按轮清零**：跨轮复用会把本轮合法编号误判为「已出现」，答案偏小。
4. **0 下标 / 1 下标混用**：`... % n` 得到 $[0,n-1]$，所以后面必须 `+1`（或单独把 `0` 改成 `n`）。`ans_vector.cpp` 里 `% n + 1` 之后那句 `if (p___ == 0) p___ = n;` 是永远不成立的多余判断；只有 `?` 分支里 `(p + n - d % n) % n` 这种直接得到 $[0,n-1]$ 的写法才真的需要它。照抄时容易被这两句误导。
5. **答案没排序**：题目要求升序。`set` 版自动满足，`vector` 版入桶顺序任意，输出前必须 `sort`。
6. **输出格式**：人数和列表各占一行，列表元素之间用单个空格；`ans_vector.cpp` 末尾会多一个空格，评测一般接受，但自己写时最好学 `ans_set.cpp` 用 `next(it) == cur.end()` 判断。
7. **多组数据没清状态**：`cur`、`nxt`、`is` 都要在每组数据内部重新构造，别搬到 `solve` 外面当全局变量还忘了清。
8. **误用排序写法**：`ans_vector.cpp` 的重排之所以成立，是因为每步只加一个与状态无关的 $\pm d$。一旦某步的方向依赖当前持球人，或者要求输出「第 $i$ 轮后的集合」，这种重排就会出错。

## 总结

本题的关键不是模拟某一个人的走位，而是意识到「可达位置集合」本身才是状态，且一次投掷只是集合上的批量平移。想清楚环形下标怎么取模、每轮怎么去重、答案怎么排序，两版代码都只是这个模型的不同容器实现：`set` 版写起来最不容易错，`vector` + 桶去重版理论常数更小，代价是要自己管好 $1\sim n$ 的边界和桶的清零。

# P4924 魔法少女小Scarlet 题解

## 题意

有一个 $n$ 阶方阵，初始时按行优先填入 $1,2,\dots,n^{2}$，即第 $i$ 行第 $j$ 列的元素是 $(i-1)n+j$。接下来有 $m$ 次操作，第 $k$ 次给定 $x,\ y,\ r,\ z$：以 $(x,y)$ 为中心、半径 $r$ 的正方形子矩阵（边长 $\text{len}=2r+1$）整体旋转 $90^{\circ}$，其中 $z=0$ 表示顺时针、$z=1$ 表示逆时针。求全部操作结束后的矩阵。

输入输出格式由代码可推断：先读 $n,m$，随后 $m$ 行每行四个整数 $x,y,r,z$；最后按行输出矩阵，同一行的 $n$ 个数用一个空格隔开，行末立即换行。

## 思路

### 一、先把子矩阵的位置换算清楚

矩阵存储用的是 $1$ 到 $n$ 的坐标，而旋转公式在 $0$ 到 $\text{len}-1$ 的局部坐标下最自然，两种坐标必须显式换算，否则整体错位一格。设子矩阵左上角为 $\text{top}=x-r$、$\text{left}=y-r$，则**读源值**时用全局位置 $(\text{top}+i,\ \text{left}+j)$，而旋转后的**新位置**直接在局部坐标 $(i,j)$ 下写进 `tmp`，两边的 $i,j\in[0,\text{len})$。

代码里读源值是 `a[top+i][left+j]`，写进 `tmp` 是 `tmp[ni][nj]`，写回是 `a[top+i][left+j] = tmp[i][j]`；凡落在 `a` 上的下标都要补偏移，而 `tmp` 只用 $[0,\text{len})$ 内的局部下标，正体现了"读全局、算局部"的分工。

### 二、旋转公式是怎么推出来的

关键观察：**矩阵旋转 $90^{\circ}$ = 先转置，再沿某一个方向翻转一次。** 转置的作用是交换行列，即 $(i,j)\to(j,i)$；翻转则决定方向。

**顺时针**：第一行会变成最后一列。转置后 $(i,j)\to(j,i)$，此时原来靠左的元素跑到了上面的行，还需要把列序倒过来，即列号 $i\to\text{len}-1-i$，于是

$$
(i,j)\ \xrightarrow{\ \text{转置}\ }\ (j,i)\ \xrightarrow{\ \text{左右翻转}\ }\ (j,\ \text{len}-1-i)
$$

**逆时针**：第一行会变成第一列，但顺序是自下而上（原来的最左元素落到该列最下方）。转置后同样得到 $(j,i)$，但这次要倒的是行序，即行号 $j\to\text{len}-1-j$，于是

$$
(i,j)\ \xrightarrow{\ \text{转置}\ }\ (j,i)\ \xrightarrow{\ \text{上下翻转}\ }\ (\text{len}-1-j,\ i)
$$

**用四个角自检**，这是最快也最可靠的验证方式：

| 原来的位置 | 顺时针后应在 | 代入 $(i,j)\to(j,\text{len}-1-i)$ | 逆时针后应在 | 代入 $(i,j)\to(\text{len}-1-j,i)$ |
| --- | --- | --- | --- | --- |
| 左上 $(0,0)$ | 右上 $(0,\text{len}-1)$ | $(0,\text{len}-1)$ ✓ | 左下 $(\text{len}-1,0)$ | $(\text{len}-1,0)$ ✓ |
| 右上 $(0,\text{len}-1)$ | 右下 $(\text{len}-1,\text{len}-1)$ | $(\text{len}-1,\text{len}-1)$ ✓ | 左上 $(0,0)$ | $(0,0)$ ✓ |

表中心 $(r,r)$ 按公式恒映射到自身，与"旋转不改变中心"相符，可以再看一组中轴点确认没有把方向写反。

### 三、为什么写成「目标下标 = 源值」

代码里是 `tmp[ni][nj] = a[top+i][left+j]`，即左边写**目标**位置、右边读**源**值。这样做的收益在写回时体现：写回是 `a[top+i][left+j] = tmp[i][j]`，纯粹的逐格拷贝，不需要任何坐标运算。

如果反过来写成 `tmp[i][j] = a[源]`，就必须把上面两个公式求逆（等价于再转 $270^{\circ}$），多一次推导就多一处容易写错的符号。旋转是双向可逆的置换，"正向送出去，原样搬回来"永远比"逆着取回来"省事。

### 四、为什么必须用 tmp 中转

旋转是一个置换，绝大多数元素要换到别的位置去。若直接在 `a` 上就地覆盖，顺时针第一步把左上角写进右上角时，右上角原本的值还没被读走，就已经被摧毁了——后面所有需要它的位置都会读到脏数据。所以必须另开一块缓冲区：先从 `a` 只读地生成旋转结果到 `tmp`，再整体写回 `a`。

就地旋转在理论上并非不可能（可以按 $4$ 元轮换环逐组旋转，中心点不动），但循环边界、环起点和奇偶中线的分类讨论极易出错，对这道题完全不值得。

关于 `tmp` 的两个细节：

1. **每次操作复用同一块全局 `tmp`，且从不清零。** 这是安全的——写回时只读 `tmp[0..len)` 的方阵区域，而这整块区域在本次操作中恰好被逐格写满了，没有一格残留旧值。反过来，如果每次操作前还把 `tmp` 清一遍，反而白白多花 $O(n^{2})$，比旋转本身还贵。
2. **`tmp` 必须留出完整的 $\text{len}\times\text{len}$ 缓冲区，不能像滚动数组那样只压到一两行。** 因为读和写是两个完全独立的嵌套循环，而且一行的元素会散到整列上去，彼此不存在可以压成常数的依赖关系。

## 复杂度

- 初始化填充：$O(n^{2})$；最后输出：$O(n^{2})$。
- 单次操作：写 `tmp` 一遍、写回一遍，两块都是边长 $\text{len}=2r+1$ 的方阵，即 $O(\text{len}^{2})=O(r^{2})$。
- 总计 $O\!\left(n^{2}+\sum_{k=1}^{m} r_{k}^{2}\right)\subseteq O(n^{2}+m\,r_{\max}^{2})$，习惯上记作 $O(n^{2}+m r^{2})$。
- 空间：两个 $505\times505$ 的 `int` 数组，约 $2\ \text{MB}$，即 $O(n^{2})$。

注意复杂度里的 $r$ 是**单次操作的半径**，不是常数；$r$ 取到最大时单次操作就要扫遍整个矩阵。本题 $n$ 的数量级由 `MAXN = 505` 可推断在 $500$ 上下，$n^{2}\le 250000$ 完全在 `int` 范围内，元素值不需要开 `long long`。

## 参考代码（C++17）

```cpp
#include <bits/stdc++.h>
using namespace std;

const int MAXN = 505;
int n, m;
int a[MAXN][MAXN];
int tmp[MAXN][MAXN];   // 复用临时数组

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    cin >> n >> m;

    // 初始填充 1 ~ n^2，从左到右、从上到下
    int val = 1;
    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= n; j++)
            a[i][j] = val++;

    while (m--) {
        int x, y, r, z;
        cin >> x >> y >> r >> z;

        int len = 2 * r + 1;
        int top = x - r;     // 子矩阵左上角行
        int left = y - r;    // 子矩阵左上角列

        // 把子矩阵按旋转规则放入 tmp
        for (int i = 0; i < len; i++) {
            for (int j = 0; j < len; j++) {
                int ni, nj;
                if (z == 0) {
                    // 顺时针 90°
                    ni = j;
                    nj = len - 1 - i;
                } else {
                    // 逆时针 90°
                    ni = len - 1 - j;
                    nj = i;
                }
                tmp[ni][nj] = a[top + i][left + j];
            }
        }

        // 写回原矩阵
        for (int i = 0; i < len; i++)
            for (int j = 0; j < len; j++)
                a[top + i][left + j] = tmp[i][j];
    }

    // 输出最终矩阵
    for (int i = 1; i <= n; i++) {
        for (int j = 1; j <= n; j++) {
            cout << a[i][j] << (j == n ? '\n' : ' ');
        }
    }

    return 0;
}
```

## 易错点

1. **全局坐标与局部坐标混用。** 读源值时忘了加 `top`/`left`，或写回时又多加了一次偏移，都会让"旋转中心"整体平移。原则：公式里只出现 $[0,\text{len})$，一旦要落到 `a` 上就必须补偏移。
2. **顺时针与逆时针写反。** 症状是每次操作都在往反方向转，但矩阵看上去仍然"像是转过了"，很难一眼看出。务必用左上角做自检：**顺时针后左上角应出现在右上角**。若它跑到了左下角，说明把逆时针的公式用在了顺时针上。
3. **`len` 与 `r` 搞混。** 边长是 $2r+1$，既不是 $r$ 也不是 $2r$；若把边长当成 $2r$ 来用，循环就会漏掉最后一行/列。还要注意 `len-1`（数值上恰好等于 $2r$）若误写成 `len`，下标会越界。
4. **就地旋转。** 把 `tmp` 省掉、直接在 `a` 上对角线交换，四角会互相污染。本题必须中转。
5. **写回时又套了一次旋转**，即第二次循环里也算了 `ni`/`nj`。这样等于把结果又转了一次，最终方向错 $90^{\circ}$。写回就应该是原样拷贝。
6. **只写 `tmp` 忘了写回 `a`。** `tmp` 里看着是对的，但 `a` 一格都没动，输出还是初始矩阵。
7. **输出格式。** 行末不能有多余空格，且最后一行也要有换行；`(j == n ? '\n' : ' ')` 这种写法比循环外单独输出更不容易漏。

## 总结

这题是纯粹的模拟：把"整体旋转"拆成"行列互换 + 一次翻转"，就得到了只含加减法的坐标映射 $(i,j)\to(j,\text{len}-1-i)$ 与 $(i,j)\to(\text{len}-1-j,i)$；再用 `tmp` 做一次双向搬运，把置换安全地落地。全程没有任何需要贪心或搜索的地方，唯一的难点是坐标细节必须一次写对。

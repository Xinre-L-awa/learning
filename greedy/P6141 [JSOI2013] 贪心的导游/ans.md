# P6141 [JSOI2013] 贪心的导游 题解

## 题意

给定长度为 $n$ 的数列 $a$，以及 $m$ 次询问。每次询问给出 $u,v,p$，求

$$\max_{u \le i \le v}\bigl(a_i \bmod p\bigr)$$

输入第一行是 $n,m$，第二行是 $n$ 个整数，随后 $m$ 行每行三个整数 $u,v,p$；对每个询问输出一行答案。

从代码可以推断出两件事：数组下标与询问里的 $u,v$ 使用同一套从 $0$ 开始的编号（扫描指针从 $-1$ 起步），且元素值不超过 $1000$（`last` 直接用值当下标，长度 $1001$ 正好覆盖值域 $0 \sim 1000$）。代码对 $u>v$ 的询问会先交换，因此实际处理的区间始终满足 $u \le v$。

## 思路

### 第一步：把「区间里有没有某个值」压成一次比较

对每个可能的值 $val$ 维护一个 `last[val]`，表示「值 $val$ 最近一次出现的下标」。有了它，判断

$$\exists\, i \in [u,v],\ a_i = val$$

只需要看一句话：`last[val] >= u`。原因是 `last[val]` 记录的是**最近**的位置：如果最近位置 $\ge u$，而 `last` 里又只有 $\le v$ 的位置，它自然落在 $[u,v]$ 内；反过来，区间里若真有 $val$，它的位置 $\ge u$，而 `last` 取的是 $\le v$ 的最近位置，也必然 $\ge u$。两边合起来，「最近位置 $\ge u$」与「区间内存在」等价。

这一步是整道题的关键：把一个二维的区间存在性问题，降到 $O(1)$ 的一次整数比较。后面所有的技巧都是围绕「如何让 `last` 恰好只包含位置 $\le v$ 的信息」展开的。

### 第二步：离线按右端点排序，让 `last` 只朝前走

如果对每个询问都重新构建一遍 `last`，复杂度立刻退化成 $O(nm)$。注意到询问之间唯一的差别是右端点 $v$：把询问按 $v$ 升序排序后，用指针 `cur` 从左往右单调扫描数组，每前进一位就执行

```cpp
last[a[cur]] = cur;
```

于是处理第 $k$ 个询问时，`last` 里装的恰好是「下标 $\le v_k$ 的最近出现位置」，正好满足第一步要求的前提；同时因为扫描只覆盖到 $v_k$，不会混入右端点之后的信息，`last[val] >= u` 就精确等价于区间内的存在性。排序打乱了询问原来的次序，所以结构体里存了 `id`，答案按 `id` 写回 `ans`，输出时仍按输入顺序。

`cur` 全程只前进、不回退，所以这一整段扫描的总代价是 $O(n)$，而不是 $O(nm)$——这就是「离线排序」换来的东西：用一次全局有序的扫描，代替 $m$ 次重复劳动。

### 第三步：从大到小枚举余数，第一个成立的就是答案

要求的是最大值，于是按从大到小的顺序枚举余数 $r = p-1, p-2, \dots, 1$，对每个 $r$ 检查所有满足

$$val \equiv r \pmod p,\qquad 0 \le val \le 1000$$

的 $val$（也就是 $r,\ r+p,\ r+2p,\dots$），只要其中任意一个满足 `last[val] >= u`，就说明区间内存在一个数除以 $p$ 余 $r$，而它一定是答案：所有比 $r$ 大的余数都已经被前面的轮次否决过了。

这就是「贪心」的体现——不是对数据做贪心选择，而是**用枚举的顺序把「求最大值」变成「求第一个满足条件的值」**：一旦成立立刻 `break`，既不需要二分，也不需要任何数据结构来维护最大值，判定本身已经是 $O(1)$，顺序枚举就是最优的检索方式。

### 为什么 $r=0$ 不用单独枚举

$0$ 严格小于任何 $r \ge 1$，只有在「所有非零余数都不成立」时它才可能是答案。代码把 `ans` 初始化为 $0$，循环里只处理 $r \ge 1$：如果 $p-1$ 到 $1$ 全都不成立，`ans` 保持 $0$；而此时区间非空（$u \le v$ 已保证），区间内至少有一个数，它的余数只能是 $0$，答案确实就是 $0$。用初值兜底，省掉一轮枚举，也避免了「区间里没有某个值」这种误判。

## 复杂度

设值域上界为 $V = 1000$（由 `last` 的长度 $1001$ 可推断）。

- 读入与排序：$O(n + m \log m)$。
- 指针扫描：每个下标只被更新一次，$O(n)$。
- 询问：外层至多 $p-1$ 个余数，每个余数要检查约 $V/p$ 个候选值，单次询问约

$$p \cdot \frac{V}{p} = V$$

次比较；$m$ 次询问合计 $O\left(\sum p \cdot \frac{1000}{p}\right) \approx O(1000m)$。乘法里 $p$ 与 $\frac{1}{p}$ 相互抵消，这正是这层枚举「看起来是两层循环、实际是线性」的原因：余数越多，每个余数要检查的值就越少，两者成反比。

总复杂度 $O\left(n + m\log m + \sum_i (1000 + p_i)\right)$；$p$ 有千级上界时（本题 $p \le 10^3$）即 $O(n + m\log m + 1000m)$。空间 $O(n + m + 1000)$。

更严格地算，内层枚举把所有满足 $val \bmod p \ne 0$ 的 $val \in [1,1000]$ 各访问至多一次，因此内层总次数不超过 $1000 - \left\lfloor \frac{1000}{p} \right\rfloor \le 1000$；随 $p$ 增长的只有外层空转，至多 $p-1$ 次。所以单次询问是 $O(1000+p)$，$p \cdot \frac{1000}{p}$ 只是它的直觉形式——真正的原因是「每个值只被检查一次」。若 $p$ 远大于值域，内层几乎不执行、只剩外层空转（此时所有 $a_i < p$，余数就是元素本身），复杂度退化为 $O(p)$。

## 参考代码（C++17）

```cpp
#include <bits/stdc++.h>
using namespace std;

struct Q { int u, v, p, id; };

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m;
    cin >> n >> m;
    vector<int> a(n);
    for (int i = 0; i < n; i++) cin >> a[i];

    vector<Q> qs(m);
    for (int i = 0; i < m; i++) {
        cin >> qs[i].u >> qs[i].v >> qs[i].p;
        if (qs[i].u > qs[i].v) swap(qs[i].u, qs[i].v);   // 保险，题面没保证 u<=v
        qs[i].id = i;
    }

    // 离线：按右端点排序，从左往右扫一遍
    sort(qs.begin(), qs.end(), [](const Q& x, const Q& y) { return x.v < y.v; });

    vector<int> last(1001, -1), ans(m, 0);
    int cur = -1;
    for (const Q& q : qs) {
        while (cur < q.v) { cur++; last[a[cur]] = cur; }  // last[val] = <=v 的最后位置

        // 余数从大到小枚举，第一个成立的就是答案
        for (int r = q.p - 1; r >= 1; r--) {
            bool found = false;
            for (int val = r; val <= 1000; val += q.p)
                if (last[val] >= q.u) { found = true; break; }   // O(1) 判断
            if (found) { ans[q.id] = r; break; }
        }
    }

    for (int i = 0; i < m; i++) cout << ans[i] << '\n';
    return 0;
}
```

## 易错点

1. **`last` 必须初始化为 $-1$，不能初始化为 $0$。** 下标是从 $0$ 开始的，若用 $0$ 作初值，那么一次都没出现过的值会被当成「第 $0$ 位出现过」，于是 $u = 0$ 的询问会凭空多出许多成立的值，答案偏大。初值 $-1$ 才表示「从未出现」。
2. **`ans` 的初值 $0$ 承担了 $r=0$ 的兜底，不能随手改成 $-1$。** 外层循环只枚举 $r = p-1, p-2, \ldots, 1$，如果改成 `ans` 初始为 $-1$ 又忘了处理 $0$，就会出现输出 $-1$ 的情况。
3. **`last` 的长度 $1001$ 与值域上界 $1000$ 是硬编码绑定的。** 一旦元素值超过 $1000$，`last[a[cur]] = cur` 直接越界写，属于未定义行为；同理内层 `val <= 1000` 也要跟着改。这两处必须同步修改。
4. **指针必须单调前进，不能每个询问都从 $0$ 重扫。** 只有在询问按右端点排好序之后，`while (cur < q.v)` 才能保证 `cur` 全程只前进，扫描总量是 $O(n)$；若把 `cur` 重置成每个询问重扫一遍，复杂度立刻变回 $O(nm)$。另外，忘记排序并不会让复杂度变差，但会让答案错——`last` 里会残留比 $v$ 大的位置，`last[val] >= u` 就不再等价于「区间内存在」。
5. **区间方向不保证。** 代码里对 $u>v$ 做了 `swap`；若删掉这行，反序询问就成了非法区间（$u>v$ 时 `last` 里只有 $\le v$ 的位置，`last[val] >= u` 必然为假），答案会恒为 $0$。
6. **$p=1$ 的边界。** 数据保证 $p \ge 2$，但代码在 $p=1$ 时也不会错：此时 `r` 从 $0$ 起就小于 $1$，外层循环一次都不进，答案保持初值 $0$；而任何数模 $1$ 都是 $0$，恰好正确——这也反过来印证了第 $2$ 条中初值 $0$ 的必要性。
7. **输出用 `'\n'` 而不是 `endl`。** $m$ 次刷新输出流足以让程序明显变慢，`ios::sync_with_stdio(false)` 也需要配合 `'\n'` 才有意义。

## 总结

本题的骨架是「离线按右端点排序 + 记录每个值最近出现位置」这一经典套路，它把区间存在性判定摊平成 $O(1)$；再叠上「余数从大到小枚举」，让最大值问题不必借助任何数据结构。两层枚举看似 $O(p \cdot V)$，但由于候选值个数与 $p$ 成反比，乘积恒为值域大小 $1000$，于是单次询问是常数级开销。三个观察——存在性可比较、右端点可排序、最大值可顺序取——各解决一个维度，合起来就是 $O(n + 1000m)$。

## 说明

目录把本题归在 `greedy` 下，但代码主体其实是「离线排序 + 最近位置数组 + 枚举」，贪心只体现在「余数从大到小、首个成立即答案」这一处；另外元素值域上限 $1000$ 与询问区间下标从 $0$ 开始，都是依据代码中的 `vector<int> last(1001, -1)` 和 `cur = -1` 推断的，题面未在代码中体现。

# P1199 [NOIP 2010 普及组] 三国游戏 题解

## 题意

$n$ 名武将（$n$ 为偶数，题面给出 $4 \le n \le 500$），任意两名武将之间有一个非负的「默契值」，且任意两对武将的默契值互不相同。默契值只给上三角：第 $i+1$ 行是 $i$ 号武将与 $i+1,i+2,\dots,n$ 号武将之间的默契值。

小涵先选一名武将，之后两人轮流从自由武将中取人，直到武将分完。计算机的选将策略是定死的：轮到它时，把每个自由武将逐个与小涵军中的**每一名**武将配对，找出默契值最大的那一对，把其中的自由武将拿走。

分完后双方各拿出本方军队中默契值最高的一对来比，高者获胜（默契值互不相同，不会平局）。问：是否存在让小涵必胜的选将顺序？若存在，第一行输出 `1`，第二行输出所有获胜走法中小涵那对武将默契值的最大值；若不存在，只输出 `0`。

## 思路

### 先把游戏变成图

武将当作点，默契值当作完全图的边权。两人轮流取点，各取 $n/2$ 个；一方的得分就是**自己所取点集内部的最大边权**，比的是谁的点集里最大边权更大。

于是整个问题只剩一个自由度：小涵先手取点的顺序。他要让自己点集内的最大边权尽量大，同时压过计算机的点集。

### 关键结构：大边一定两两不共端点

记

$$M = \max_{1 \le i \le n} \operatorname{secondmax}(i),$$

其中 $\operatorname{secondmax}(i)$ 是第 $i$ 行（$i$ 号武将的全部默契值）中的次大值。把权值 $> M$ 的边叫做**大边**。

对任意武将 $y$，它的边里最多只有一条能是大边：若有两条，它的次大值就 $> M$，与 $M$ 的定义直接矛盾。因此

- 大边构成一个**匹配**：任意两条大边没有公共端点；
- 若 $(x,y)$ 是大边，它一定是 $x$ 的最大边，也是 $y$ 的最大边。

### 想拿一行的最大值？对手会先把它拆了

设武将 $i$ 的最大搭档是 $j$，$w = \max$ 第 $i$ 行。小涵想拿到 $w$，就必须同时拿到 $i$ 和 $j$。若 $w \le M$，这一行每条边都不超过 $M$，本来就无利可图；若 $w > M$，$(i,j)$ 就是一条大边。可小涵选了 $i$ 之后，$(i,j)$ 立刻成为计算机眼中的一个候选配对（它正是按「与小涵军中某人的默契值」挑人的），$j$ 只要还是自由武将就会被顺手摘走。

把这句话说严格，有下面这个归纳断言：

> 每轮小涵选完武将 $y$、计算机行动之后，小涵军中每个武将的最大搭档都不再是自由武将。

证明：设小涵刚选完 $y$，且 $y$ 有大搭档 $b$（即 $(y,b)$ 是大边）。若 $b$ 已被取走，结论已经成立，故只需考虑 $b$ 仍自由的情形，此时 $(y,b)$ 是计算机的候选之一。若计算机取的最大边是 $(x,c)$ 而 $x$ 是小涵更早选的武将，由归纳假设 $x$ 的最大搭档已被取走、不再自由，那么 $c$ 至多是 $x$ 的次大搭档，$\mathrm{val}(x,c) \le M$；但 $(x,c)$ 是当前最大边，不小于 $\mathrm{val}(y,b) > M$，矛盾。所以当前最大边必须以 $y$ 为端点，计算机取到的是 $y$ 边权最大的候选搭档；而 $y$ 只有一条边 $>M$，就是 $(y,b)$，故 $c=b$。

由此：**小涵永远拿不到任何一条大边**，他点集内的最大边权 $\le M$。这也正是答案取「次大」而不是「最大」的根本原因——一行里唯一可能超过 $M$ 的边就是这行的最大值边，而它一定会被拆掉；于是每行只剩次大值可指望，对各行取最大即得 $M$。

### 次大值 $M$ 确实拿得到

取使次大值最大的武将 $i^*$。第一轮小涵选 $i^*$：此时小涵军中只有它一人，计算机的候选只有 $i^*$ 的搭档，必定取走 $i^*$ 的最大搭档 $b$。第二轮小涵选 $i^*$ 的次大搭档 $k$，拿到 $\mathrm{val}(i^*,k) = M$。之后无论怎么走，小涵这一对的默契值都已经是 $M$，所以 $M$ 可达，答案就是 $M$。

### 为什么第一行恒为 $1$

小涵已经有 $M$，只需保证计算机拿不到 $\ge M$ 的一对。拿到 $M$ 之后，小涵剩下的回合只做一件事：若计算机刚取走的武将 $c$ 有一条大边 $(c,c')$ 而 $c'$ 还自由，就取走 $c'$。大边两两不共端点，每轮至多出现一个这样的威胁，小涵刚好处理得完，于是计算机军中永远不存在大边，它的最大边权 $\le M$；又因为默契值互不相同、值为 $M$ 的那条边在小涵手里，计算机那对的权值严格小于 $M$。所以小涵必胜，第一行恒为 `1`，题面里「没有必胜走法输出 $0$」的情形不会出现。

### 代码怎么落地

输入只给上三角。第 $i$ 行的 $j<i$ 部分直接查已经建好的第 $j$ 行：$\mathrm{val}(i,j) = \mathrm{val}(j,i)$。补成完整的一行后，这一行是 $n-1$ 个默契值加一个对角线 $0$（构造函数里清零），升序排序后 $v[n]$ 最大、$v[n-1]$ 就是次大，对所有行取 $v[n-1]$ 的最大值。

用题面举例的那张 6 武将表格验算：各行次大值依次为 $28,20,28,16,32,26$，最大者 $32$ 就是这一局的答案。

## 复杂度

补全矩阵 $O(n^2)$；每行排序 $O(n\log n)$，共 $n$ 行，故时间复杂度

$$O(n^2 \log n)$$

空间上每行存 $n+1$ 个整数（结构体里是长度 504 的定长数组），共 $O(n^2)$。$n \le 500$ 时 $n^2 \approx 2.5\times10^5$，非常宽松。

## 参考代码（C++17）

下面的代码即 `ans.cpp`，仅一处改动：回填下三角的循环上界由 `j < i` 改成 `j < i - 1`（原写法越界，原因见「易错点」第四条），另加了几行注释。

```cpp
#include <bits/stdc++.h>
using namespace std;

struct P {
    int v[504];
    int idx;
    P(int idx) : v{}, idx(idx) {}
    void set(int i, int val) {
        v[i] = val;
    }
};

int main() {
    int n;
    cin >> n;
    vector<P> h;                        // h[i-1] 就是 i 号武将这一行
    h.reserve(n);
    for (int i = 1; i <= n; i++) {
        P p(i);                         // 构造时 v[] 全为 0，对角线保持 0
        for (int j = i + 1; j <= n; j++) {
            int v;
            cin >> v;                   // 只读上三角：i 与 i+1..n
            p.set(j, v);
        }
        for (int j = 0; j < i - 1; j++) {   // 用已建好的行补下三角
            p.set(j + 1, h[j].v[i]);
        }
        h.push_back(p);
    }

    int ans = 0;
    for (auto& p : h) {
        sort(p.v + 1, p.v + n + 1);      // 排 1..n：v[n] 最大，v[n-1] 次大
        ans = max(p.v[n - 1], ans);
    }
    cout << 1 << '\n';
    cout << ans;

    return 0;
}
```

## 易错点

- **不要取每行的最大值（更不要取全局最大值）**。每一行里唯一可能超过 $M$ 的就是这一行的最大值边，它的另一端会被计算机按策略摘走；小涵的上限是各行的次大值，答案只能是「次大值的最大值」。
- **第一行固定是 `1`**。不要写博弈搜索，也不要判断后输出 `0`：这题永远存在必胜走法。
- **次大的下标是 `v[n-1]`，不是 `v[n-2]`**。排序区间是 $v[1..n]$，共 $n$ 个数（$n-1$ 个默契值 $+\ 1$ 个对角线 $0$），最大在 $v[n]$，次大在 $v[n-1]$。
- **对角线必须留在 $0$**。原文件补下三角时写作 `for (int j = 0; j < i; j++) p.set(j + 1, h[j].v[i]);`，上界多了一格：此时 `h[i-1]` 还没 `push_back`，读到的是未初始化内存，会把对角线 $v[i]$ 写成随机值。对角线同样参与排序，脏值一旦大于次大值就会顶掉答案。正确边界是 `j < i - 1`（参考代码已按此给出），这样 $v[i]$ 保持构造时的 $0$。
- **排序区间**写 `p.v + 1` 到 `p.v + n + 1`，$v[0]$ 不参与；写成 `sort(p.v, p.v + n)` 会漏掉最大的那一格。
- 默契值只比较、不求和，`int` 足够（题面上限 $10^9$），不必开 `long long`。

## 总结

结论一句话：**先手必胜，答案是每行次大值的最大值**。难点不在代码，而在看出「权值大于 $M$ 的边两两不共端点」这个匹配结构：计算机的策略恰好是抢走小涵军中某人的最强搭档，所以任何一行的最大值都会被对面拆掉，小涵只能退到次大值；而次大值他在第二轮就能稳稳拿到，计算机则因大边是匹配、永远凑不成一条大边，只能更小。既然只关心本方点集内的最大边权，补全矩阵后逐行排序即可。

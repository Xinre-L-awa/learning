# P2672 [NOIP 2015 普及组] 推销员 题解

## 题意

由代码可推断的输入格式：第一行 $n$；第二行 $n$ 个整数 $s_1,\dots,s_n$，表示到第 $i$ 户的距离；第三行 $n$ 个整数 $a_1,\dots,a_n$，表示第 $i$ 户的疲劳值。输出 $n$ 行，第 $x$ 行为「恰好访问 $x$ 户」时的最大总疲劳。

若选中的客户集合为 $S$（$|S|=x$），总代价是
$$
F(S)=\sum_{i\in S} a_i + 2\cdot\max_{i\in S} s_i .
$$
第二项是「走到最远的那家再原路返回」的路程代价：路上只由最远点决定，中间路过谁都不额外计数；而 $a_i$ 是逐户累加的。目标就是对每个 $x$ 求 $\max F(S)$。

## 思路

一句总纲：$a_i$ 是「按户结算」的加项，$2s$ 只有一项、且由最远点决定。所以先把 $a$ 排序，再把「谁当最远点」单独拿出来分类。

### 预处理：按 a 降序排序

把客户按 $a$ 降序排序后，$a$ 的前缀就是「能拿到的最大的若干个 $a$」。记

- $\text{sum}[i]=\sum_{j\le i}a_j$：前 $i$ 户的 $a$ 之和；
- $q[i]=\max_{j\le i}2s_j$：前 $i$ 户里最远的距离代价；
- $h[i]=\max_{j\ge i}\bigl(2s_j+a_j\bigr)$：后缀中「自己当最远点」能带来的最大打包收益。

排序会打乱 $s$ 的顺序，这一点后面还会用到：排序只保证 $a$ 递减，$s$ 变成任意顺序。

### 情况一：最远点落在前 x 户里（走进前缀内）

取任意 $x$ 户，若其中 $s$ 最大的那户排序后位于前 $x$ 位，那么这批 $a$ 之和不超过 $\text{sum}[x]$（前 $x$ 名就是最大的 $x$ 个 $a$），距离代价不超过 $q[x]$，于是
$$
F \le \text{sum}[x]+q[x].
$$
这个上界取得到：直接选前 $x$ 户，让其中 $s$ 最大的那户当最远点，收益恰好是 $\text{sum}[x]+q[x]$。所以
$$
f_1(x)=\text{sum}[x]+q[x]
$$
是一个紧的候选。

### 情况二：最远点落在第 x 位之后（走到更远处）

若最远点排序后在第 $j$ 位且 $j\ge x$，则其余 $x-1$ 户都不是第 $j$ 户；而前 $x-1$ 名本就在 $j$ 之前，所以其余 $x-1$ 户的 $a$ 之和最多是 $\text{sum}[x-1]$。再加上最远点自己打包的 $2s_j+a_j$，得
$$
F \le \text{sum}[x-1]+(2s_j+a_j) \le \text{sum}[x-1]+h[x].
$$
同样可构造：任取 $j\ge x$，选「前 $x-1$ 户 $+$ 第 $j$ 户」，收益至少是 $\text{sum}[x-1]+2s_j+a_j$（要是前 $x-1$ 户里藏着一个更远的人，$2s$ 只会更大，那种集合的最远点落在前 $x-1$ 位，已经由情况一覆盖）。对 $j$ 取最大即
$$
f_2(x)=\text{sum}[x-1]+h[x].
$$

### 合起来

最远点的下标要么 $\le x$，要么 $\ge x$（等于 $x$ 时两边都成立），两种情况覆盖了所有集合，并且各自都能构造出来，于是
$$
f(x)=\max\bigl(\text{sum}[x]+q[x],\ \text{sum}[x-1]+h[x]\bigr).
$$
直观解释：情况一是「不换人，就在 $a$ 最大的前 $x$ 个里挑」；情况二是「为了一个更远的客户，让出一个 $a$ 名额」——式子里的 $\text{sum}$ 从 $x$ 掉到 $x-1$，换来后缀里一个更大的 $2s+a$。注意 $h$ 已经把那一户的 $a$ 算进去了，所以不能再补一个 $a$。

### 为什么不写成增量递推

$f(x)$ 对每个 $x$ 独立做一次 $\max$，不依赖 $f(x-1)$。原因是「多一位客户」并不总是「往原方案里塞一个人」：也可能要踢掉原来的人、换一个更远的当最远点（情况二）。替换关系一变，增量就失去意义。

## 复杂度

排序 $O(n\log n)$，三个前后缀数组与答案循环都是 $O(n)$，总时间 $O(n\log n)$，空间 $O(n)$。每个 $x$ 独立计算，不需要额外数据结构。

## 参考代码（C++17）

```cpp
#include <iostream>
#include <cstdio>
#include <cmath>
#include <algorithm>
using namespace std;

int n, sum[100010], q[100010], h[100010]; // sum: a 的前缀和; q: 前 i 个 2s 的最大值; h: 后缀 2s+a 的最大值
struct node {
    int s; // 距离
    int a; // 疲劳
} v[100010];
bool cmp(node x, node y) { return x.a > y.a; }

int main() {
    scanf("%d", &n);
    for (int i = 1; i <= n; i++) scanf("%d", &v[i].s);
    for (int i = 1; i <= n; i++) scanf("%d", &v[i].a);
    sort(v + 1, v + 1 + n, cmp);                                  // 按疲劳降序
    for (int i = 1; i <= n; i++) sum[i] = sum[i - 1] + v[i].a;     // 前缀 a 之和
    for (int i = 1; i <= n; i++) q[i] = max(q[i - 1], 2 * v[i].s); // 前 i 个的最大 2s
    for (int i = n; i >= 1; i--) h[i] = max(h[i + 1], 2 * v[i].s + v[i].a); // 后缀 2s+a
    for (int i = 1; i <= n; i++)
        printf("%d\n", max(sum[i] + q[i], sum[i - 1] + h[i]));
    return 0;
}
```

## 易错点

### 1. 朴素贪心：以 $2s+a$ 最大的那家为基准

`ans.cpp` 的做法是：先取 $\arg\max(2s_i+a_i)$ 当基准户 `idx`，认为最优解一定以它为最远点，再把 $x$ 变大当成「往基准集合里补 $a$ 最大的剩下的人」。它隐含两个假设：

1. 最远点只能是基准户，或者顺着原下标相邻地往后挪一格（用 `2*(s[cur_r+1]-s[cur_r])` 一格一格累加距离）；
2. 下标越大 $s$ 越大。

假设 1 恰好丢掉了情况二的核心：最远点可以「跳」到任意 $j\ge x$ 的位置，代价是让出第 $x$ 个 $a$ 名额——这就是替换关系。假设 2 更无根据：代码从头到尾没重排过 $s$，它直接按输入顺序累加相邻两项之差 $2(s_{i+1}-s_i)$，等于默认「后面的户一定比前面的远」；一旦后一户反而更近，这个增量就是负数，距离代价当场算错。

至于 $x\le\text{idx}$ 这一段：正解此时确实退化成情况二（`idx` 是全局最大、必落在后缀里，故 $h[x]=2s_{\text{idx}}+a_{\text{idx}}$；而情况一不会超过它——若 $q[x]=2s_j$、$j\le x$，则 $\text{sum}[x-1]+a_x+2s_j\le\text{sum}[x-1]+a_j+2s_j\le\text{sum}[x-1]+a_{\text{idx}}+2s_{\text{idx}}$），但错解并不等于情况二：`pref[x-2]` 只在原下标 $1..\text{idx}-1$ 里挑最大的 $x-1$ 个 $a$，凑不出 $\text{sum}[x-1]$（最大的那几个 $a$ 可能就长在 `idx` 自己身上或它后面），所以这一段它只会偏低、不会偏高。下面那个反例恰好没踩到这个坑，看着才像「前半段对」；真实情况是两段都偏，只是偏的方向不同。

### 2. 一个可以直接复现的反例

自拟输入（$n=4$）：
$$
s=(1,2,3,40),\qquad a=(100,99,1,1).
$$
按 $a$ 降序排列后顺序不变，$2s+a=(102,103,7,81)$，最大值在第 $2$ 位，故基准户为 `idx=2`。

| $x$ | 最优集合 | 正解 | `ans.cpp` 输出 |
| --- | --- | --- | --- |
| 1 | $\{2\}$：$103$ | $103$ | $103$ |
| 2 | $\{1,2\}$：$199+4$ | $203$ | $203$ |
| 3 | $\{1,2,4\}$：$200+80$ | $280$ | $206$ |
| 4 | $\{1,2,3,4\}$：$201+80$ | $281$ | $282$ |

$x=3$ 时正解放弃排序第 3 位（$a=1,\ s=3$），改让第 4 位（$a=1,\ s=40$）当最远点，正是情况二；错解只会把最远点定格在第 3 位，于是差了 $2\cdot(40-3)=74$。$x=4$ 时错解反而偏大，因为它的 `prefff` 存的是「后缀前 $k$ 大的累加和」，却被当成增量逐次加上去，$a_3$ 被重复计入了一次。也就是说这个错解既会漏解、也会多算。

### 3. 细节坑

- 情况二的系数是 $\text{sum}[x-1]$，少写这个 $-1$ 就会把最远点的 $a$ 算两遍。
- 后缀最大值要按 $2s_j+a_j$ 取，不能只按 $2s_j$ 取，否则最远点自己那份 $a$ 就丢了。
- $h[n+1]$、$q[0]$ 靠全局数组默认补零；换成未初始化的局部数组会读到脏值。
- 比较函数写成 `a >= b` 会破坏严格弱序，只能用 `>`；`a` 相等时排序先后任意，但结论不受影响（等值可交换）。
- 原代码的 `sum/q/h` 用 `int`：`sum` 是 $n\cdot a$ 量级、$2s+a$ 是 $2s$ 量级，若把值域放大就都得换 `long long`。

## 总结

把「逐户累加的 $a$」和「只由最远点决定的 $2s$」拆开：前者靠排序加前缀和，后者靠「最远点排在第几位」分两类枚举。整个答案由两个紧的候选取 $\max$ 得到、不做增量，就不会掉进「该换人却只会加人」的坑。

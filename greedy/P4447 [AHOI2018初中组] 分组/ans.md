# P4447 [AHOI2018初中组] 分组 题解

## 题意

把给定的 $n$ 个整数分成若干组，要求每一组内部**数字互不重复且连续**（组内元素排序后是公差为 $1$ 的等差序列），每个数恰好使用一次。

求所有组中「人数最少的那一组」最多能有多少人，也就是在所有合法分组方案中最大化 $\min(\text{每组人数})$。

从代码可以推断：输入是元素个数与这 $n$ 个数，输出只有一个整数（被最大化的那个最小值），不需要输出方案本身。

## 思路

### 把分组看成「接链」

一组合法的数，本质上就是一条**链**：$x,\ x+1,\ x+2,\ \dots$，链上相邻两个数差 $1$，且不重复。于是分组方案等价于：把每个数接到某条「以 $x-1$ 结尾」的链上，或者让它自己另起一条新链。

对单个元素 $x$ 来说，处境只有两种：

- 存在以 $x-1$ 结尾的链：$x$ 接上去，链长 $+1$，链尾变成 $x$；
- 不存在：$x$ 只能自成一链，长度为 $1$，链尾为 $x$。

还要注意一条链最多吃一个 $x$（组内不能有重复），所以同一个值出现多次时，是**多个副本各自去找链**，不能一次全部塞进同一条链。

### 排序的用处

链之间的依赖只有「$x$ 依赖 $x-1$」这一条，方向永远从小值指向大值。

排序后按顺序扫描，处理到 $x$ 时，所有小于 $x$ 的元素都已经处理完，之后不可能再冒出新的 $x-1$。也就是说，**以 $x-1$ 结尾的链集合在这一刻已经定型**，可以放心地在它上面做取舍，不必担心「后面还有 $x-1$」而反悔。相同数值在排序后连续出现，每个副本于是都能依次被分配到某条链上。

反过来，若乱序处理，处理 $x$ 时可能还有 $x-1$ 没出现，就只能让 $x$ 起新链，贪心得出的分组会因此变差（本可以接上的 $x$ 被迫自起一条新链）；注意变差的是贪心的结果，题目的最优值本身与处理顺序无关。

### 为什么每次接「最短」的链

最终答案是所有链长的最小值，这是典型的木桶问题：**只有当前最短的那条链变长，答案才有机会变大**。所以当 $x$ 面对多条以 $x-1$ 结尾的链时：

- 若接给其中较长的链，最短的那条这一轮一无所获，最终最小值不会比接给最短链更好；
- 反过来把 $x$ 让给最短的那条链，只是让长度分布更均匀，用一次交换就能对上任意其他方案，最小值不会变差。

更关键的是**先补短链没有任何代价**：一条链要变长只能吃一个 $x$，两种安排的差别只在于把这次变长的机会给了哪条链；而后续操作只看各链当前的长度和链尾，不看它是哪条链。把机会让给短链只是让长度分布更均匀，排序后逐位比较都不会更差。所以「接最短」是弱占优的选择，不存在「先喂长链、以后再补短链」的翻盘点（即使 $x$ 有多个副本，先喂给最短的那条同样不亏）。做法就是：每个 $x$ 取以 $x-1$ 结尾的所有链中最短的那条。

实现上用哈希表 + 小根堆：`mp[x]` 存**所有以 $x$ 结尾的链的长度**，堆顶即最短的那条。取堆顶、弹出、长度加一、再压入 `mp[x]`。

### 为什么不能按出现次数均分

一个常见的错误直觉是：同一个数不能进同一组，所以组数至少是最大出现次数 $c_{\max}$，答案就是 $\lfloor n / c_{\max} \rfloor$ 之类的均分值。

反例 $a = \{1,2,2,3,3,3\}$：$n=6$，$c_{\max}=3$，均分给出 $2$；但真正的最优是 $1$，例如

$$\{1,2\},\ \{2,3\},\ \{3\},\ \{3\}$$

四组人数分别为 $2,2,1,1$，最小值只有 $1$。

原因在于：链能不能延长，取决于相邻的数值是否还有「空闲的链尾」，而不是总数或频次之间的比例。$1$ 只有一个，所以以 $2$ 结尾的链最多两条，三个 $3$ 里也就只有两个能接上去，最后一个必须新起一条链；而后面没有 $4$ 可以续，长度就永远停在 $1$。所以只能逐值模拟接续过程，做不了除法。

### 步骤

1. 读入并排序；
2. 依次处理每个 $x$：若存在以 $x-1$ 结尾且非空的链堆，取出最短长度 $L$，弹出，把 $L+1$ 压入 `mp[x]`；否则把 $1$ 压入 `mp[x]`；
3. 遍历所有堆，取全部链长的最小值即为答案。

## 复杂度

排序是 $O(n \log n)$。每个数最多触发一次入堆，最多触发一次出堆，单次堆操作 $O(\log n)$，合计 $O(n \log n)$；外层哈希表的均摊单次操作 $O(1)$。

时间复杂度 $O(n \log n)$，空间复杂度 $O(n)$（任意时刻堆内元素总数不超过已处理的元素个数）。

## 参考代码（C++17）

```cpp
#include <bits/stdc++.h>
#include <unordered_map>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    vector<int> a(n);
    for (int i = 0; i < n; ++i) cin >> a[i];

    // 1. 排序
    sort(a.begin(), a.end());

    // mp[x]：以数字 x 结尾的所有组的长度，小根堆维护
    unordered_map<int, priority_queue<int, vector<int>, greater<int>>> mp;

    for (int x : a) {
        if (mp.count(x - 1) && !mp[x - 1].empty()) {
            // 找以 x-1 结尾的组，取最短的一条接上
            int len = mp[x - 1].top();
            mp[x - 1].pop();
            mp[x].push(len + 1);
        } else {
            // 没有可接的组，x 只能自开一组
            mp[x].push(1);
        }
    }

    // 2. 取所有组长的最小值
    int ans = INT_MAX;
    for (auto& [val, pq] : mp) {
        while (!pq.empty()) {
            ans = min(ans, pq.top());
            pq.pop();
        }
    }

    cout << ans << "\n";

    return 0;
}
```

## 易错点

- **只判 `mp.count(x-1)` 不判堆是否为空**：一条链接上新元素后会从 `mp[x-1]` 里被弹走，这个堆可能被搬空；此时直接 `top()` 就是在空堆上取元素，行为未定义。代码里的 `&& !mp[x - 1].empty()` 不能省。
- **忘记排序**：不排序时 $x-1$ 可能还没出现，会被误判成「没有可接的链」而多开新链，答案偏小。
- **把重复的 $x$ 一次性处理**：每个 $x$ 至多接一条链，重复值必须逐个遍历、逐个取堆顶。
- **最后统计取错对象**：要的是全部链长的最小值，需要遍历所有堆取 $\min$，不能只看某一个堆，也不能取堆的大小或最大值。
- **`ans` 的初值**：代码用 `INT_MAX` 初始化。若一个组都没建立（例如 $n=0$ 没读入有效数据），输出会是 `INT_MAX`；正常输入下不会出现，但要知道这个初值的来源。
- **用 `unordered_map` 而不是数组或 `map`**：值域跨度大，不能直接开桶计数；哈希表写法短，代价是多一层常数与哈希开销，`mp[x]` 的每次访问都可能触发建表。

## 总结

把「分组」重新解释成「沿值域接链」之后，问题只剩两件事：**按值从小到大扫**，保证每条链的信息都是终态；**每次把新数喂给最短的那条链**，对付木桶效应。前者是正确性的前提，后者是交换论证下的弱占优选择，二者合起来就是这道题贪心的全部。

# Rudolf and 121 题解

## 题意

给定长度为 $n$ 的数组 $a$（代码里下标从 $0$ 开始）。一次操作要选一个**有左右邻居**的中间位置 $i$，即 $1 \le i \le n-2$，然后

$$a_{i-1} \leftarrow a_{i-1}-1,\qquad a_i \leftarrow a_i-2,\qquad a_{i+1} \leftarrow a_{i+1}-1$$

问能否通过若干次（可以是 $0$ 次）这样的操作把数组变成全 $0$。

由代码可推断的输入输出格式：第一行整数 $t$ 表示数据组数；每组先读 $n$，再读 $n$ 个整数；每组输出一行 `YES` 或 `NO`。$n$ 与 $a_i$ 的具体范围不写死，下面只按代码的实际行为分析。

关于操作只有一个决定性事实：**它只会让元素变小，永远不会变大，也永远不会"撤销"**。整道题的推理都从这一条出发。

## 思路

### 1. 每个位置"只能被谁改"

设 $c_i$ 表示以 $i$ 为中心的操作执行次数。位置 $p$ 只会被三类操作影响：以 $p-1$ 为中心（它是右邻居，每次 $-1$）、以 $p$ 为中心（它是中间，每次 $-2$）、以 $p+1$ 为中心（它是左邻居，每次 $-1$）。于是"把数组清零"等价于求解

$$c_{p-1} + 2c_p + c_{p+1} = a_p \quad (0 \le p < n)$$

其中越界的 $c$ 视为 $0$，且要求所有 $c_i \ge 0$。注意 $c_0$ 与 $c_{n-1}$ 本身非法（端点不能当中心），它们是 $0$。

最关键的是最左端那一个方程：$p=0$ 时只剩 $2c_0 + c_1 = a_0$，而 $c_0$ 不存在，所以

$$c_1 = a_0$$

**没有别的可能**。因为位置 $0$ 只有中心 $1$ 能减它，减多少次就得是多少次：少了它不为 $0$，多了它变负数且再也回不来。

### 2. 归纳：所有次数都被唯一确定

把上面这一步推下去。设 $c_1,\ldots,c_{p-1}$ 已经全部确定，那么位置 $p-1$ 此刻的剩余值（残差）是确定的；而位置 $p-1$ 只会被中心 $p-2$（右邻居，每次 $-1$）、$p-1$（中间，每次 $-2$）、$p$（左邻居，每次 $-1$）影响。前两者的次数已经定死，唯一还没定的贡献者就是 $c_p$，且它每次只把位置 $p-1$ 减 $1$。所以在中心 $p$ 也被处理之后，位置 $p-1$ 就**彻底定型、无人再碰**，它必须在这一刻等于 $0$，从而

$$c_p = \text{位置 } p-1 \text{ 的当前残差} \quad (p = 1,2,\ldots,n-2)$$

这正是代码做的事：把残差取出来当作这次批量操作的次数。从方程组角度看也一样：第 $p$ 行是 $c_{p-1}+2c_p+c_{p+1}=a_p$，按 $p=0,1,\ldots,n-3$ 从上到下看，每行里 $c_{p-1},c_p$ 都已被前面的行解出，只剩 $c_{p+1}$ 且系数恰为 $1$——每行刚好引入一个新未知量，于是 $c_1,\ldots,c_{n-2}$ 被依次唯一确定，方程组至多有一个候选解。**解唯一**，所以"存在性"问题退化成"把这唯一候选算出来、看它是否自洽"。

### 3. 唯一性带来的必要性：为什么不能随性做

既然次数被唯一确定，就没有任何自由度。由此得到几条在实现中必须遵守的纪律：

- **不能多减、也不能少减。** 少减会让某个位置残留正数；多减会让某个位置变负。而操作不可逆（只减不增），变负之后永远补不回来，这个候选解直接作废。
- **不能"从右往左、看到谁大就随手减几下"。** 这类做法错在**随手决定次数**，而不是错在方向本身：数组反转后 $1,2,1$ 的系数完全对称，从右端开始做同样的逐项归纳也会得到同一组 $c_i$（方程组唯一）。真正不能自由的是"次数"，它必须恰好等于那个残差，猜一次就废。
- 同理，"先随机挑一个中间位置减一减试试"也是错的：任何偏离唯一候选的操作都在消耗不可恢复的余量。

于是"中途出现负数"就是**确凿无解**：它意味着位置 $p-1$ 被之前的操作已经减穿了，而剩下的操作只会继续减它。

### 4. 一次扫描怎么实现

代码把"以 $i$ 为中心做 $a_{i-1}$ 次"直接**合并成一次批量减法**（线性叠加，逐次做与一次做结果相同，且操作可交换，顺序不影响最终数组）：

$$\text{若 } val = a_{i-1} > 0:\quad a_{i+1} \mathrel{-}= val,\quad a_i \mathrel{-}= 2val,\quad a_{i-1} \leftarrow 0$$

循环 $i = 1,\ldots,n-2$ 走完，下标 $0..n-3$ 已经被清零，只剩最后两个位置 $n-2,n-1$ 可能非零——它们没有"下一个中心"可以收拾，只能靠最后再扫一遍整个数组来验尸。`a[i-1] = 0` 等价于 `a[i-1] -= val`：中心 $i$ 恰好做 $val$ 次，每次减它 $1$，正好把它减到 $0$，所以这是操作本身的一部分，不是额外的补偿。

### 5. 全 $0$ 数组与 $n<3$ 的边界

- **全 $0$ 特判**：代码读入时用 `flag` 记是否有非零元素，确认全 $0$ 就立刻 `YES` 并 `continue`。这是条快速路径（不需要任何操作就是答案），即使不走它，通用流程末尾的扫描也会给出 `YES`，所以它不影响正确性。
- **$n < 3$**：循环 $i \in [1, n-2]$ 为空，一次合法操作都没有，答案只能是"本来就全 $0$"。代码的末尾扫描自然给出这个结论，全 $0$ 特判也覆盖了它。注意别想当然地认为"总能清空"。

### 6. 为什么要 long long

残差本身不会超过原始 $a_i$（只做减法，且在读之前保证非负），但**中间量**会掉到很深：单次扫描里同一个位置会被减两次，先作为右邻居被上一轮的 $val$ 减 $1$ 倍，再作为中间元素被减 $2\,val$。当 $a_i$ 的量级是 $10^9$ 时，位置 $i$ 的值最坏会掉到 $-2\times10^9$ 左右（取 $a=\{10^9,0,1,5\times10^8\}$，$a_1$ 会被减成 $-2\times10^9$），已经贴住 32 位有符号整数的下限 $-2.147\times10^9$；上限只要再抬高一点就必然溢出，而溢出是未定义行为，可能把本该 `NO` 的用例判成 `YES`。所以数组以及 $2\,val$ 这类中间量都统一用 `long long` 承接。

## 复杂度

- 时间：每组数据只做一次线性扫描（读入一遍、主循环一遍、收尾扫描一遍），$O(n)$；总复杂度 $O(\sum n)$。
- 空间：一个长度为 $n$ 的数组，$O(n)$。

## 参考代码（C++17）

```cpp
#include <bits/stdc++.h>
using namespace std;
using ll = long long;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int t;
    cin >> t;
    while(t-- > 0) {
        int n;
        cin >> n;
        vector<ll> a(n);

        bool ok = true;
        bool flag = false;
        for (int i = 0; i < n; i++) {
            cin >> a[i];
            if (a[i]) flag = true;
        }

        if (!flag) {
            cout << "YES\n";
            continue;
        }

        for (int i = 1; i < n - 1; i++) {
            if (a[i - 1] < 0) {
                ok = false;
                break;
            }

            if (a[i - 1] > 0) {
                ll val = a[i - 1];
                a[i + 1] -= val;
                a[i] -= 2 * val;
                a[i - 1] = 0;
            }
        }

        for (int i = 0; i < n; i++) if (a[i] != 0) ok = false;

        cout << (ok ? "YES" : "NO") << '\n';
    }

    return 0;
}
```

## 易错点

1. **只判"中途变负"，忘了收尾检查。** 循环只保证 $0..n-3$ 归零，最后两个位置没人能再动，必须整体再扫一遍判断全 $0$；否则会漏掉末尾残留正数的情况。
2. **负数检查的位置。** 代码在每轮开头检查 $a_{i-1}$，管的是"最近几轮被减过的那个位置"。$a_{n-2}$、$a_{n-1}$ 变负不会被这个 `if` 抓到，只能靠末尾扫描兜底——而末尾用的是 `!= 0`，负数也满足"非零"，同样会被判为不合法，所以逻辑是完整的；但若把收尾检查写成"只查 $a_{n-1}$"就会漏。
3. **`break` 之后别提前输出。** 代码 `break` 只置 `ok = false`，仍走统一的收尾扫描与输出，避免在两个出口间写重复的判断。
4. **用 `int` 承接中间值**（见思路第 6 节）：被减位置的中间值能到 $-2\times10^9$，紧贴 `int` 下限，上限稍大就溢出；溢出是未定义行为，之后 `a[i-1] < 0` 的判断会完全失真。
5. **误以为"必须至少操作一次"或"操作次数可以自己挑"**：次数由残差唯一决定，$0$ 次也合法；全 $0$ 直接 `YES`。
6. **以为负数之后还能救**：所有操作只减不增，没有补偿手段。看到负数就应当立刻断定 `NO`，不必继续模拟。
7. **$n < 3$ 时误判为 `YES`**：此时不存在合法中心，答案完全取决于原数组是否已经全 $0$。

## 总结

核心是"从最左端开始，每个位置的清除方式被唯一锁死"：$c_1 = a_0$，之后 $c_p$ 恒等于位置 $p-1$ 的残差。所以只需按这个唯一候选扫一遍，中途出现负数或结束仍非全 $0$ 就输出 `NO`，否则 `YES`。$O(n)$ 时间，注意 `long long` 与两处检查的配合。

# 石头剪刀布 题解

## 题意

**题意说明（依据代码实现）**：多测构造题。第一行是测试组数 $t$，之后每组给出三个非负整数 $x,y,z$，表示**对手**会出的石头、剪刀、布各多少张（出手顺序完全未知）。我方一共要出 $x+y+z$ 张牌。

要求输出一个长度恰为 $x+y+z$ 的字符串，只由 `P`（布）、`R`（石头）、`S`（剪刀）组成，使得对对手的每一类出拳，我方都准备了**该类数量一半（向上取整）**的克星：

| 对手出拳 | 数量 | 我方克星 | 至少准备 |
| --- | --- | --- | --- |
| 石头 `R` | $x$ | 布 `P` | $\lceil x/2 \rceil$ |
| 剪刀 `S` | $y$ | 石头 `R` | $\lceil y/2 \rceil$ |
| 布 `P` | $z$ | 剪刀 `S` | $\lceil z/2 \rceil$ |

这三条都是**下界**（"至少"）；除去这三种克星占用的回合，剩下的回合不受任何约束，随便填什么牌都合法，代码统一填 `R`。每组答案输出一行、连续无空格。

若原题面还附加了别的说法（例如对任意排列的胜场下界），一律以代码行为为准：代码只保证上面三条"每种克星至少占一半"的计数下界，并据此拼出长度正确的串。

## 思路

### 一、把目标拆成三条互相独立的配额

题目问的其实是三件互不相干的事：为了对付 $x$ 张石头，我需要多少张布；为了对付 $y$ 张剪刀，我需要多少张石头；为了对付 $z$ 张布，我需要多少张剪刀。三者之间没有"同一张牌两用"的可能——一张牌只有一种属性，一个回合只出一张牌，所以三条配额可以直接相加，不存在冲突。这种"分别满足、再拼起来"的结构正是本解的关键。

### 二、$\lceil a/2 \rceil$ 的向上取整：为什么写成 `(a+1)/2`

"赢至少一半"翻译成计数就是

$$cnt \ge \frac{a}{2} \iff cnt \ge \left\lceil \frac{a}{2} \right\rceil \quad (a \in \mathbb{N}),$$

因为 $cnt$ 必须是整数，能取到的最小整数值就是 $\lceil a/2\rceil$。对非负整数，这个值用整数除法写出来就是

$$\left\lceil \frac{a}{2} \right\rceil = \left\lfloor \frac{a+1}{2} \right\rfloor = \texttt{(a + 1) / 2}.$$

验证一下两类情形：

- $a$ 为偶数，$a=2k$：$\lceil a/2\rceil = k$，恰好是一半，不多不少；
- $a$ 为奇数，$a=2k+1$：$\lfloor a/2\rfloor = k$，只有 $k$ 张，而 $k < (2k+1)/2 = k+0.5$，**严格不到一半**；必须取 $\lceil a/2\rceil = k+1$ 才是"至少一半"。

所以 `(x+1)/2` 不是随手加一的技巧，而是"至少一半"这个要求本身决定的唯一取值；写成 `x/2` 在奇数时会少一张，直接导致该类别覆盖不足一半。

### 三、剩余回合为什么随便填

这是最容易想不通、也最值得说清的一点。原因有三个，缺一不可：

1. **需求是下界而不是等式。** 代码里三条配额满足后并没有"必须恰好用完 $x+y+z$ 个位置、且每个位置都得有用"的要求。多出的回合就是多出来的容量，出什么都不会让已经达成的配额失效。
2. **总回合数被对手的出牌总数锁死。** 我方必须出满 $x+y+z$ 张，一个不多一个不少，所以 `rem = x + y + z - p_cnt - r_cnt - s_cnt` 这些位置**必须**填东西。既然前三种克星已经凑够，这些位置填什么是纯粹的"填充"。
3. **补位只做加法，不挤掉任何东西。** 代码填 `R`，只是让石头数量变多；由于三条要求都是"至少"，多给不算错。填 `P` 或 `S` 同理（代码注释里也写明了这一点）。反过来说，往补位里塞更多同一类克星也并非必要：题目只要求该类克星不少于 $\lceil a/2\rceil$，这是个下界而不是"越多越有用"的目标，补位多出来的同类牌只是把张数加在已经达标的配额之上；而且"我方 `P` 撞上对手 `R`"的回合数最多是 $\min(\#P, x)$（$\#P$ 为我方 `P` 的张数），本来就被对手石头的总数 $x$ 封顶，配额之外的部分换不来新的东西。

对手的出拳顺序确实会影响我们最终**兑现**多少张克星（同一张 `P` 可能撞上石头也可能撞上布），但它改变不了一个事实：我方手里确实握着对手每一类数量一半以上的克星。题目要保证的"每一类至少赢一半"，落到代码能控制的量上，就是"我方为该类准备的克星数量不少于该类数量的一半（向上取整）"（「题意」一节已声明：以代码行为为准）。这是纯计数事实，与对手怎么排无关；但它只覆盖"我方握有多少张克星"，覆盖不到"这些克星在任意排列下能真正对上多少张"——后者确实依赖顺序，本解并不承诺。

### 四、正确性证明

**引理 1（一定可行）。** 对任意非负整数 $a$ 有 $\lceil a/2\rceil \le a$，于是

$$\lceil x/2\rceil + \lceil y/2\rceil + \lceil z/2\rceil \le x + y + z,$$

即 $rem \ge 0$，`string(rem, 'R')` 永远不会拿到非法长度；输出长度自动等于 $x+y+z$。

**引理 2（三条配额同时成立）。** 构造出的串中：`P` 恰有 $\lceil x/2\rceil \ge x/2$ 张，`S` 恰有 $\lceil z/2\rceil \ge z/2$ 张，`R` 有 $\lceil y/2\rceil + rem \ge \lceil y/2\rceil \ge y/2$ 张。补位没有减少任何一类克星的数量，所以三条下界同时被满足。

**引理 3（少一张就破界）。** 若 `P` 只给 $\lceil x/2\rceil-1$ 张：$x$ 为奇数时是 $(x-1)/2 < x/2$，$x$ 为偶数时是 $x/2-1 < x/2$，两种情形都严格不到一半，该类别覆盖不足；可见 $\lceil x/2\rceil$ 是刚好够用的临界值，不存在更省的写法。

**定理。** 由引理 1、2，代码对每组数据输出的串长度正确、三条下界全部成立，满足题目要求。

### 五、构造顺序

1. 按 $x,y,z$ 分别算出三种克星的数量 `p_cnt, r_cnt, s_cnt`；
2. 用总数减去三者之和得到待填回合 `rem`；
3. 依次拼上 `p_cnt` 个 `P`、`r_cnt` 个 `R`、`s_cnt` 个 `S`，再把 `rem` 个 `R` 补在末尾。

之所以直接"分段拼接"而没有交错摆放，是因为题目只约束计数、不约束位置；分段写法最简单，也最容易看出长度是否自洽。

## 复杂度

设该组数据的 $n = x+y+z$（即输出串长度）。

- 时间复杂度：每组 $O(n)$，只做常数次整数运算和常数次字符串拼接（合计 $n$ 个字符）；$t$ 组合计 $O(\sum n)$，即与输出总量成正比，已达到理论下界（答案本身就要输出这么多字符）。
- 空间复杂度：每组 $O(n)$，用于暂存答案串；除答案外只用到常数个 `int` 变量。

## 参考代码（C++17）

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int t;
    cin >> t;
    while (t-- > 0) {
        int x, y, z;
        cin >> x >> y >> z;

        // 针对每一种出拳，至少准备一半的克星（向上取整）
        int p_cnt = (x + 1) / 2; // 克制石头(R)用布(P)
        int r_cnt = (y + 1) / 2; // 克制剪刀(S)用石头(R)
        int s_cnt = (z + 1) / 2; // 克制布(P)用剪刀(S)

        // 计算还有多少回合没分配
        int rem = x + y + z - p_cnt - r_cnt - s_cnt;

        string ans = "";
        ans += string(p_cnt, 'P');
        ans += string(r_cnt, 'R');
        ans += string(s_cnt, 'S');

        // 剩下的回合随便填什么都可以（这里全填 R，填 P 或 S 也一样能过）
        ans += string(rem, 'R');

        cout << ans << '\n';
    }
    return 0;
}
```

## 易错点

1. **把向上取整写成 `x/2`。** 整除是向下取整，$x$ 为奇数时 $1$ 张之差就会让该类别不到一半。必须写 `(x + 1) / 2`，或等价地写 `(x % 2 ? x / 2 + 1 : x / 2)`。
2. **漏读多测。** 代码外层有 `while (t-- > 0)`；只读一组 $x,y,z$ 会 WA（或只输出第一组）。
3. **克制关系写反。** 布克石头、石头克剪刀、剪刀克布：$x$ 的克星是 `P`，$y$ 的克星是 `R`，$z$ 的克星是 `S`。字母顺序一错，三条配额全部打偏。
4. **忘了补位导致长度不足。** 只输出三种克星共 $\lceil x/2\rceil+\lceil y/2\rceil+\lceil z/2\rceil$ 个字符，一般小于 $x+y+z$；必须补 `rem` 个。
5. **`rem` 被算成负数可能运行期报错。** `std::string(rem, ch)` 传入负长度会抛异常；本解中 $\lceil a/2\rceil \le a$ 保证了 $rem \ge 0$，但如果把配额写得比原数量还大就会踩坑。
6. **输出格式。** 每组输出一行连续的 `P/R/S` 串，不要加空格、不要拆成多行、不要输出多余提示文字。
7. **误以为补位必须是 `R`。** 补位填什么都可以；代码统一填 `R` 只是方便，评审时不要把它当成额外约束。

## 总结

一句话：把"每一类至少赢一半"拆成三条互不相干的下界，每条用 $\lceil a/2\rceil = \texttt{(a+1)/2}$ 取到刚好够用的张数，剩下的回合因为总数被 $x+y+z$ 锁死而必须填满，填什么都不会破坏下界，于是随便填。构造的难点不在实现，而在说清"为什么下界凑齐后剩余位置是自由的"。

# Money Buys Less Happiness Now 题解

## 题意

有 $m$ 天依次到来，第 $i$ 天有一件价格为 $c_i$ 的「快乐」，每件快乐提供的价值都相同（都是 $1$）；由代码可推断每个 $c_i$ 至多入选一次，即每天至多买一件。目标是让买到的件数尽量多。

钱是固定发放、按天累积的：由代码里 `if (sum > 1LL * (i - 1) * x)` 这个判断可推断，第 $i$ 天做决定时手上可用的额度是 $(i-1)x$——第一天额度为 $0$，此后每过一天额度增加 $x$，花掉的钱不会回来。于是约束是：对每个前缀，累计支出不超过当时的额度，即对任意 $i$，

$$\sum_{j \in S,\ j \le i} c_j \le (i-1)x ,$$

其中 $S$ 是最终选中的购买天集合。

输入输出形态由代码可推断：第一行为测试组数 $T$；每组先给 $m$ 与 $x$，随后 $m$ 个 $c_i$（被边读边处理，不必存下来）。每组输出一行一个整数，即最多能买到的件数。

## 思路

### 先贪心接受，再反悔

从第 $1$ 天扫到第 $m$ 天，先无条件把 $c_i$ 塞进一个大根堆，等于说「这一件我买了」，同时把它的价格加到 `sum` 上。然后检查额度：如果 `sum > (i-1)*x`，说明当前这套「已选集合」已经买不起了，必须退掉一件——退掉堆中**最贵**的那件，把它的价格从 `sum` 里减回去。

所以每天只有三个动作：入堆、加和、超支就弹堆顶。扫描结束后，堆的大小就是答案。

### 不变量：堆里始终是最优集合

记第 $i$ 天结束后堆中的集合为 $A_i$（当作多重集看，不同天的价格可能相同），$k_i=|A_i|$；记 $\sigma_i(t)$ 为 $A_i$ 中最便宜的 $t$ 件之和。再记 $\mathrm{opt}_i$ 为只用前 $i$ 天最多能买的件数，$\mathrm{cost}_i(t)$ 为只用前 $i$ 天恰好买 $t$ 件的最小花费。

要维护的不变量是：$A_i$ 合法，$k_i=\mathrm{opt}_i$，且

$$\sigma_i(t)=\mathrm{cost}_i(t)\qquad(1\le t\le k_i).$$

也就是说：**堆里最便宜的 $t$ 件，就是买 $t$ 件的最省买法**。其中 $t=k_i$ 那一档就是「件数最多、且同件数下花费最小」。

对 $i$ 归纳，$A_0=\varnothing$ 时都平凡成立。设 $A'=A_{i-1}\cup\{c_i\}$，$s'=\operatorname{sum}(A_{i-1})+c_i$。先固定两条随时可用的事实：无论弹不弹，$A_i$ 都是 $A'$ 或「$A'$ 去掉一个最大元素」，所以对 $t\le k_i$，$\sigma_i(t)$ 恰好等于「$A'$ 里最便宜的 $t$ 件之和」；于是

$$\sigma_i(t)\le\sigma_{i-1}(t)\quad(t\le k_{i-1}),\qquad \sigma_i(t)\le\sigma_{i-1}(t-1)+c_i ,$$

前者因为 $A'\supseteq A_{i-1}$，后者因为「$A_{i-1}$ 最便宜的 $t-1$ 件 + 第 $i$ 天这件」本身就是 $A'$ 里 $t$ 件元素的组合。

**情形一（不弹）：$s'\le(i-1)x$，$A_i=A'$，$k_i=k_{i-1}+1$。** 合法性：前 $i-1$ 天的前缀沿用 $A_{i-1}$，第 $i$ 天的总和就是 $s'$。件数：一天至多买一件，故 $\mathrm{opt}_i\le\mathrm{opt}_{i-1}+1=k_i$；又 $A_i$ 本身合法，故 $\mathrm{opt}_i\ge k_i$，于是 $k_i=\mathrm{opt}_i$。花费：任取前 $i$ 天的合法 $t$ 件方案 $S$（$t\le k_i$）——若 $i\notin S$，$S$ 是前 $i-1$ 天的合法 $t$ 件方案且 $t\le k_{i-1}$，由归纳 $\operatorname{sum}(S)\ge\sigma_{i-1}(t)\ge\sigma_i(t)$；若 $i\in S$，$S\setminus\{c_i\}$ 是前 $i-1$ 天的合法 $t-1$ 件方案，由归纳 $\operatorname{sum}(S)\ge\sigma_{i-1}(t-1)+c_i\ge\sigma_i(t)$。另一方面 $A_i$ 最便宜的 $t$ 件是 $A_i$ 的子集，合法方案的子集仍合法（前缀和只减不增），花费正好 $\sigma_i(t)$，故 $\mathrm{cost}_i(t)=\sigma_i(t)$。

**情形二（弹堆顶）：$s'>(i-1)x$，$A_i=A'\setminus\{M\}$，其中 $M=\max A'$，$k_i=k_{i-1}=k$。** 合法性：$\operatorname{sum}(A_i)=\operatorname{sum}(A_{i-1})+c_i-M\le\operatorname{sum}(A_{i-1})\le(i-1)x$（$i=1$ 时 $A_0=\varnothing$，两边都是 $0$；$i\ge2$ 时用 $A_{i-1}$ 的合法界 $\operatorname{sum}(A_{i-1})\le(i-2)x\le(i-1)x$），其余前缀和只减不增。件数：任何前 $i$ 天的合法 $k+1$ 件方案都必含第 $i$ 天（否则它在前 $i-1$ 天就买了 $k+1>\mathrm{opt}_{i-1}$ 件），其前 $i-1$ 天部分是合法 $k$ 件方案，花费 $\ge\sigma_{i-1}(k)=\operatorname{sum}(A_{i-1})$，于是总花费 $\ge\operatorname{sum}(A_{i-1})+c_i=s'>(i-1)x$，违反第 $i$ 天的额度约束，矛盾；故 $\mathrm{opt}_i\le k$。又 $A_{i-1}$ 在前 $i$ 天仍合法（同一个界，$i=1$ 时它是空集），故 $\mathrm{opt}_i\ge k$，于是 $k=\mathrm{opt}_i$。花费：按 $i\notin S$ / $i\in S$ 与情形一同样两分，仍得 $\operatorname{sum}(S)\ge\sigma_i(t)$；而 $A_i$ 最便宜的 $t$ 件合法、花费恰为 $\sigma_i(t)$，故 $\mathrm{cost}_i(t)=\sigma_i(t)$。

（为什么要把每一档 $t$ 都写进不变量：要证明 $t=k_i$ 这一档（即「件数最多 + 同件数花费最小」）时，$i\in S$ 的子情形会用到上一层的 $t-1=k_i-1$ 那一档；只维护 $t=\mathrm{opt}_i$ 这一档，归纳就断链了。）

### 为什么「退最贵的」不会让答案变差

由不变量取 $t=k_i$ 可知：弹完之后，$A_i$ 是前 $i$ 天里「件数最多、且同件数下总花费最小」的集合。剩下的问题是为什么偏要弹**最大**的那件：$A_i$ 是从 $A'$ 里删一件得到的，删哪一件都还剩 $k$ 件，但删掉最贵的那件让总花费降得最多；而在件数相同的前提下，花费越小状态越强——第 $j$ 天还能不能买，只取决于「已经买了多少件」和「已经花了多少钱」（剩余的额度是 $(j-1)x$ 减去已花金额），所以同件数、花费更少的集合，往后每一天可选的购买集合都是花费更多者的超集，不可能更差。

换一个说法：每件的价值都是 $1$，件数固定时自然希望总花费最小；退最贵的等价于「用省下的钱把后面一件更便宜的换进来」，这正是反悔贪心（regret greedy）的标准形态——**先贪心接受，发现不可行就执行一次代价最小的反悔**。

### 为什么用堆而不是排序

「该退哪一件」依赖的是**当前已经选中的集合**，它随扫描不断变化，而且元素是流式到达的，时间顺序不能重排。若改成排序：先得读完全部 $c_i$（丢掉流式的优势），排序后也拿不到「哪一件已经入选」这个动态信息；每次超支就重新排序或线性扫一遍最大值，代价会退化到 $O(m^2)$。大根堆只提供我们真正需要的操作——随时取出当前最大值——插入与弹出各 $O(\log m)$，且堆里恰好只存当前最优集合，最后堆的大小天然就是答案，不需要额外统计。

### 为什么一次弹出就够

代码用的是 `if` 而非 `while`，这不是侥幸。弹出前 $\operatorname{sum}(A_{i-1}) \le (i-2)x$（$A_{i-1}$ 合法；$i=1$ 时 $A_0=\varnothing$，和为 $0$，弹完仍是 $0=(i-1)x$，结论照样成立）：若弹的是 $c_i$，弹完和为 $\operatorname{sum}(A_{i-1}) \le (i-2)x$；若弹的是旧元素 $M$，由 $M \ge c_i$ 得弹完和 $\le \operatorname{sum}(A_{i-1}) \le (i-2)x$。两种情况都立刻回到 $\le (i-1)x$，一次弹出必然足够。

## 复杂度

- 时间：每组 $O(m \log m)$。每个 $c_i$ 入堆一次、至多弹出一次，均为 $O(\log m)$；读入是 $O(m)$。多组总计 $O\left(\sum m \log m\right)$。
- 空间：$O(m)$，只存一个大根堆（输入边读边处理，不需数组）。

## 参考代码（C++17）

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int T;
    cin >> T;

    while (T--) {
        int m;
        long long x;
        cin >> m >> x;

        priority_queue<long long> pq;  // 大根堆：已选集合
        long long sum = 0;             // 已选集合的总花费

        for (int i = 1; i <= m; ++i) {
            long long c;
            cin >> c;

            pq.push(c);   // 先贪心接受
            sum += c;

            // 第 i 天的可用额度是 (i-1)*x，超了就要反悔一次
            if (sum > 1LL * (i - 1) * x) {
                sum -= pq.top();   // 退掉最贵的那件
                pq.pop();
            }
        }

        cout << pq.size() << '\n';
    }

    return 0;
}
```

## 易错点

- **溢出**：`(i-1)*x` 与 `sum` 都可能大到超出 32 位，必须用 `long long`。代码写成 `1LL * (i - 1) * x`，保证乘法一开始就在 64 位上进行；`x`、`sum`、`c` 都声明成 `long long` 是同一道理（`sum` 尤其关键，把它写成 `int` 就会在累加时溢出）。
- **判断要用 `>` 而不是 `>=`**：恰好花满额度（$\text{sum} = (i-1)x$）是合法的，不需要退。
- **弹出时必须同步减 `sum`**：只 `pop` 不减和，之后所有判断都会错，且堆大小仍是错的（会多留元素）。
- **第 1 天额度为 $0$**：所以任何 $c_1 > 0$ 都会在第一天被立刻弹出，这不是 bug，而是「第一天还没攒到钱」。若把额度误写成 $i\cdot x$，第一天就能直接买，答案会整体偏移。
- **不要每轮复用堆或 `sum`**：多组数据，堆和 `sum` 都要在每组开始时重新初始化。
- **不要用「弹出次数」推答案**：每组数据里弹出了多少件并不等于买了多少件（同一天可能先进后出），答案只由最终 `pq.size()` 给出。

## 总结

解法是典型的反悔贪心：按天推进，先假设买下当天这件，再用「超支就退掉已选集合中最贵的一件」把不可行的前缀修回合法。由于每次只多引入一件、且退最贵者能保证「同件数下花费最小」，堆的大小最终就等于答案。上面那条不变量——堆里最便宜的前 $t$ 件就是买 $t$ 件的最省方案——支撑了整个做法，堆则把「反复取当前最大值」的代价压到 $O(\log m)$。

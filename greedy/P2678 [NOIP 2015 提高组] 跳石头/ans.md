# P2678 [NOIP 2015 提高组] 跳石头 题解

## 题意

一条长为 $L$ 的河，左岸在位置 $0$，右岸在位置 $L$，河中间有 $N$ 块石头，位置为 $a_1<a_2<\dots<a_N$（输入已经递增）。人只能在石头与两岸之间跳跃。

现在最多移走 $M$ 块石头，要求让「所有相邻落脚点之间的最小距离」尽可能大，输出这个最大值。

需要最大化的是整个过程里**最短的那一跳**，而不是总路程。

## 思路

### 答案具有单调性

把判定写成函数：$f(d)=1$ 表示「存在一种移走不超过 $M$ 块石头的方案，使得每一次跳跃都不短于 $d$」。

若 $d$ 可行，设某一个可行的移走方案为 $S$，它的所有间距都 $\ge d$。对任意 $d'\le d$，同一个方案 $S$ 的所有间距本来就 $\ge d\ge d'$，于是 $d'$ 同样可行。也就是说，「可行」这个性质对 $d$ 是单调的：小的 $d$ 更容易满足，合法答案恰好是一段前缀 $[1,\text{ans}]$。

所以不需要直接构造最优方案，只要会判断「某个 $d$ 是否可行」，再在这段单调前缀上二分即可。

### check：顺序扫描 + 能落脚就落脚

判定固定的 $d$ 时，从左往右扫石头，维护 $last$ 表示**上一次落脚的位置**（初值为 $0$，也就是左岸），以及移走计数 $cnt$：

- 若 $a_i-last<d$：这块石头即使落上去也不合格，只能移走，$cnt$ 加一，$last$ 保持不变；
- 若 $a_i-last\ge d$：落上去，令 $last\leftarrow a_i$。

扫完之后 $cnt\le M$ 就说明 $d$ 可行。整个判定是 $O(N)$ 的。

### 为什么「能落脚就落脚」最优

对固定的 $d$，贪心得到的 $cnt$ 是所有可行方案中**移走块数最少**的，因此 $cnt\le M$ 与「存在移走不超过 $M$ 块的可行方案」完全等价。用交换论证说明：

设贪心这一段的落脚点是下标 $j$，即 $j$ 是满足 $a_j-last\ge d$ 的最小下标。任取另一个可行方案，它在这一段也必须落在某块石头上，设下标为 $k$。由可行性有 $a_k-last\ge d$，而 $j$ 是满足该条件的最小下标，所以 $j\le k$。

- 若 $j=k$，两者一致；
- 若 $j<k$，把方案中的「保留 $k$、移走 $j$」换成「保留 $j$、移走 $k$」，移走块数不变；并且方案的下一次落脚点 $k'$ 满足 $a_{k'}-a_j>a_{k'}-a_k\ge d$，仍然合格——因为 $a_j<a_k$，落脚点提前只会让下一跳变长。

于是总存在一个移走块数相同的最优方案，它这一段落的落脚点正是 $j$，与贪心一致。随后把 $j$ 当作新的起点，对剩余部分重复同样的论证即可归纳下去。结论是：**绝不主动多移一块石头**，能落脚就落脚，得到的就是最少移走数。

### 为什么把终点 $L$ 也放进数组

最后一次落脚到右岸的那一跳同样必须 $\ge d$。如果只扫 $N$ 块石头，最后一段「最后落脚点 $\to L$」永远不会被检查，这是这类题最典型的错误。

把 $L$ 写到 `dis[N]`，让下标 $N$ 这块「石头」就是右岸，循环体一次写完，无需在循环后再补一段特判，也无需在判完后单独处理 $L-last<d$ 的情况——终点被当成数组元素统一处理，是这份代码最省事的地方。

注意右岸这块「石头」其实移不掉：当 $L-last<d$ 时，代码也给 $cnt$ 加一，这个计数的真实含义是「把最后那块落脚石也移走」。移走它后，新的最后一跳是 $(L-last)+(last-last_{prev})>d$，仍然合格（$last$ 那块既然曾被落脚，就满足 $last-last_{prev}\ge d$），所以这一次计数正好是一次最少代价的修复，不是 bug。

### 二分范围与 ans 初值

- 下界取 `left = 1`：位置都是整数且互不相同，$d=1$ 时任何间距都 $\ge 1$，移走数为 $0$，必然可行，所以答案至少是 $1$；$d=0$ 没有讨论意义。
- 上界取 `right = L`：任意一跳不会超过整条河的长度，答案一定 $\le L$。更紧的上界需要额外分析，收益不大，直接用 $L$。
- `ans = 0` 只是哨兵：循环中只有判定成功时才更新 `ans`，而 $d=1$ 一定成功，所以 `ans` 必然至少被赋值一次。先写 $0$ 是为了防止漏初始化后被误用。
- 循环用闭区间写法 `while (left <= right)`：可行则记录 `ans = mid` 并往大搜 `left = mid + 1`，不可行则往小搜 `right = mid - 1`。每次把 $mid$ 本身排除掉，既不会死循环，也不会漏掉边界答案。

## 复杂度

判定一次 $O(N)$，二分共 $O(\log L)$ 次，因此时间复杂度 $O(N\log L)$，空间复杂度 $O(N)$（存石头位置与终点）。

## 参考代码（C++17）

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int L, N, M;
    cin >> L >> N >> M;

    // dis 存储起点到各石头的距离
    vector<int> dis(N + 1);
    for (int i = 0; i < N; ++i) {
        cin >> dis[i];
    }
    // 把终点也当作一块石头，方便统一处理
    dis[N] = L;

    // 二分答案，范围 [1, L]
    int left = 1, right = L;
    int ans = 0;

    while (left <= right) {
        int mid = left + (right - left) / 2;

        int cnt = 0;      // 记录移走的石头数量
        int last = 0;     // 记录上一次落脚的石头位置（起点）

        // 遍历每一块石头（包括终点）
        for (int i = 0; i <= N; ++i) {
            // 如果当前石头到上次落脚点的距离小于 mid，必须移走
            if (dis[i] - last < mid) {
                cnt++;
            } else {
                // 否则可以落脚，更新落脚点
                last = dis[i];
            }
        }

        // 如果移走的石头数 <= M，说明该 mid 可行
        if (cnt <= M) {
            ans = mid;      // 记录当前可行答案
            left = mid + 1; // 尝试更大的距离
        } else {
            right = mid - 1; // mid 太大，缩小范围
        }
    }

    cout << ans << "\n";
    return 0;
}
```

## 易错点

1. **漏掉最后一段**：`dis[N] = L` 一定要写，循环必须是 `i <= N`。少了它，最后落脚点到右岸的距离不被检查，答案偏大。
2. **`last` 初值写错**：初值是 $0$（左岸），不是 `dis[0]`。写成 `dis[0]` 等于默认第一块石头必被落脚。
3. **判定写成 `< M`**：题目是「至多移走 $M$ 块」，判定必须写 `cnt <= M`。
4. **误改终点的计数**：把终点那一支的 `cnt++` 改成 `continue` 或 `break` 都会破坏答案——这次计数代表「连最后一块落脚石也移走」，它是修复最后一跳所花代价最小的唯一手段。
5. **二分写法与区间不匹配**：`while (left <= right)` 的闭区间写法要配 `mid + 1` / `mid - 1`。若照抄成 `while (left < right)` 又保留 `mid - 1`，会漏答案或死循环。
6. **单调方向搞反**：可行时应该是往大搜（`left = mid + 1`）。若在可行时缩小范围，最后记录的会是不可行的距离。
7. **数据范围**：本文不写死具体上限，由代码用 `int` 读入 $L$ 可推断 $L$ 及其相关运算落在 `int` 范围内；`mid` 用 `left + (right - left) / 2` 是稳妥写法。若换到 $L$ 更大的题，只需把 `L`、`dis`、`mid` 一并换成 `long long`，算法不变。
8. **输入有序性**：代码直接按读入顺序当作位置递增来扫描，不做排序；题目保证石头位置递增，复用到别的场景时要注意这一点。

## 总结

这类「最小值的最大值」问题，核心是把「求最优」转成「判定是否可行 + 二分」，再用一个贪心把判定压到线性：顺序扫描、能落脚就落脚、落不了就移走。贪心的正确性靠交换论证——落脚点取得越早，后面越宽松，所以贪心不会比任何可行方案多移石头。把终点并入数组，是为了让「最后一跳」也走同一条代码路径。

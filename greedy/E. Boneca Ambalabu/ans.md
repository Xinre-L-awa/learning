# E. Boneca Ambalabu 题解

## 题意

给定长度为 $n$ 的非负整数序列 $a_1,a_2,\dots,a_n$，其中 $0\le a_i<2^{30}$。要求在 $1\le k\le n$ 中选一个下标 $k$，最大化

$$\sum_{j=1}^{n}\left(a_k\oplus a_j\right)$$

其中 $\oplus$ 表示按位异或；对每个测试点输出这个最大值。

由题面给的数据规模，$n\le 2\cdot 10^{5}$，且所有测试点的 $n$ 之和也不超过 $2\cdot 10^{5}$。代码把位宽固定按 $b=0\sim 29$ 处理，这与 $a_i<2^{30}$ 一致。答案的量级是 $n\cdot(2^{30}-1)\approx 2.1\times 10^{14}$，已经超出 32 位整数——这一点后面还会再踩一次。

## 思路

**第一步：先看清暴力的代价。** 枚举 $k$ 有 $n$ 种，每个 $k$ 又要扫 $n$ 个 $j$，合计 $n^2$ 次异或；$n=2\cdot10^5$ 时约 $4\times10^{10}$，必然超时。这个和式里唯一可利用的结构就是"异或"，所以突破口只能是把异或拆开。

**第二步：把异或按位拆开。** 异或的定义本身就是逐位独立的：两数异或结果的第 $b$ 位，只由它们各自的第 $b$ 位决定。而二进制数又是各位权值的和，于是对单个 $j$ 就有恒等式

$$a_k\oplus a_j=\sum_{b=0}^{29}2^b\cdot\left[\mathrm{bit}_b(a_k)\neq \mathrm{bit}_b(a_j)\right]$$

把它代回原式并交换求和次序（这一步只用到有限和的交换律，不含任何近似）：

$$\sum_{j=1}^{n}\left(a_k\oplus a_j\right)=\sum_{b=0}^{29}2^b\cdot\Bigl|\{\,j:\mathrm{bit}_b(a_j)\neq \mathrm{bit}_b(a_k)\,\}\Bigr|$$

**第三步：按位统计。** 记 $c_b$ 为整个数组中第 $b$ 位为 $1$ 的元素个数。固定 $k$、固定位 $b$ 之后，"第 $b$ 位与 $a_k$ 不同"的 $j$ 有多少个，只取决于 $a_k$ 这一位取什么：

$$\begin{cases}\mathrm{bit}_b(a_k)=0 &\Rightarrow\text{不同者即该位为 }1\text{ 的 }c_b\text{ 个},\\[2pt] \mathrm{bit}_b(a_k)=1 &\Rightarrow\text{不同者即该位为 }0\text{ 的 }n-c_b\text{ 个}.\end{cases}$$

于是每个候选的得分可以写成只依赖 $c_b$ 的形式：

$$S_k=\sum_{b=0}^{29}2^b\cdot\begin{cases}c_b, & \mathrm{bit}_b(a_k)=0,\\[2pt] n-c_b, & \mathrm{bit}_b(a_k)=1.\end{cases}$$

**为什么这个拆分是对的。** 三点缺一不可：其一，异或的第 $b$ 位只依赖两数的第 $b$ 位，不会与其它位产生任何耦合，所以"数多少对在该位上不同"就完整决定了该位的异或和之和；其二，对每个固定的 $j$，$a_k\oplus a_j$ 的二进制展开就是 $\sum_{b}2^b\cdot[\mathrm{bit}_b\text{ 不同}]$，各位权值互不重叠，逐位叠加恰好还原该整数（这是进制定义本身，不含任何近似）；其三，对每个 $j$ 的异或值求和，与先按位配对再求和，只是加法结合律与乘法分配律的重新组织。因此 $S_k$ 与真实的 $\sum_j(a_k\oplus a_j)$ 逐位相等，自然整体相等。

$b$ 只需枚举到 $29$：因为 $a_i<2^{30}$，更高位上两个数都是 $0$，异或必为 $0$，贡献恒等于零，多枚举也无害。

**顺带说清一个常见误区。** 从 $c_b$ 的表达式看，某一位"最优"的取法是让 $a_k$ 的该位与多数元素相反（即 $c_b$ 与 $n-c_b$ 中较大的一侧）。但各位并不能分开挑：$a_k$ 必须真的来自数组，它那 30 个位是绑死在一起的，所以不存在"逐位贪心拼出一个最优数"的捷径，可行做法只能是拿真实候选去评估。

**第四步：为什么枚举 $k$ 是 $O(30n)$ 且可以接受。** 预处理 $c_0,\dots,c_{29}$ 只需扫描一遍数组、每位做一次检测，代价 $30n$。此后计算单个 $S_k$ 只做 30 次"取位 + 查表 + 乘权值 + 累加"，与 $n$ 无关，所以把全部 $n$ 个候选都精确算一遍也只有 $30n$ 规模。预处理与枚举两步合起来约 $60n$：取 $\sum n=2\cdot10^5$ 时约 $1.2\times10^7$ 次基本运算，常数就是一次移位、一次按位与、一次乘法和一次加法，时间上非常宽裕。

也就是说，本解法**没有省略任何候选**：它保留了 $\max$ 的完整枚举，只是把每个候选的评估从 $O(n)$ 压缩到 $O(30)$。正确性因此不需要任何贪心交换论证，代价仅是多出一个 30 倍的常数因子。

小例子验证：$a=\{8,13,4,5,15\}$，$n=5$，逐位统计得 $c_0=3,\;c_1=1,\;c_2=4,\;c_3=3$。取 $k$ 指向 $8=(01000)_2$：第 $0,1,2$ 位为 0，贡献 $3\cdot1+1\cdot2+4\cdot4=21$；第 $3$ 位为 1，贡献 $(5-3)\cdot8=16$；合计 $37$，与直接枚举异或的结果一致。

## 复杂度

- 时间：每组 $O(30n)$（预处理 $O(30n)$，枚举候选 $O(30n)$），总计 $O\left(30\sum n\right)$。对 $\sum n\le2\cdot10^5$ 约为 $1.2\times10^7$ 次位运算与加法，远低于常见 $10^8$ 级的预算。
- 空间：$O(n)$ 存数组，外加 $O(30)$ 的位计数，不含输入缓冲。
- 对照：暴力 $O(n^2)$，$n=2\cdot10^5$ 时约 $4\times10^{10}$，肯定超时。

## 参考代码（C++17）

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int t;
    cin >> t;
    while (t-- > 0) {
        int n;
        cin >> n;
        vector<int> a(n);
        vector<int> cnt(31, 0);

        for (int i = 0; i < n; i++) {
            cin >> a[i];

            // 预处理：统计第 j 位上有多少个 1
            for (int j = 0; j < 30; j++)
                if (a[i] & (1 << j)) cnt[j]++;
        }

        long long ans = 0ll;
        // 逐个枚举作为 a[k] 的元素
        for (int k = 0; k < n; k++) {
            long long sum = 0ll;
            for (int j = 0; j < 30; j++) {
                int w = 1 << j;                            // 该位权值 2^j
                if (a[k] & w) sum += 1LL * (n - cnt[j]) * w;  // 该位为 1：与 0 配对
                else          sum += 1LL * cnt[j] * w;        // 该位为 0：与 1 配对
            }
            ans = max(ans, sum);
        }

        cout << ans << '\n';
    }

    return 0;
}
```

## 易错点

- **乘法必须在 64 位里做。** 若写成 `(n - cnt[j]) * w`，两个操作数都是 `int`，乘积先按 32 位算完再赋给 `long long`，溢出已经发生且属于未定义行为（`else` 分支的 `cnt[j] * w` 完全同理，$c_b$ 最多能到 $n$）。举个能真实触发的规模：$n=2\cdot10^5$，一半元素是 $2^{29}$、一半是 $0$，那么取 $a_k=2^{29}$ 时该位贡献为 $10^5\cdot2^{29}\approx5.4\times10^{13}$，远超 `int` 上限。写成 `1LL * (n - cnt[j]) * w`（或把权值直接声明为 `long long`）即可。
- **答案类型用 `long long`。** 上界 $n(2^{30}-1)\approx2.1\times10^{14}$，`int` 装不下。
- **位宽别写错。** 数据满足 $a_i<2^{30}$，故枚举 $b=0,\dots,29$。多写一位（`j < 31`）不会错，少写一位就会漏贡献；另外 `1 << 31` 在 `int` 上是未定义行为，权值取 `1 << j`（$j\le29$）安全，想更保险可用 `1LL << j`。
- **每组测试数据都要重新统计。** $c_b$ 是"本组数组"的统计量，跨组复用会直接算错；在每组里新建 `vector` 是最省心的写法。
- **答案初值取 0 依赖非负性。** 所有项 $a_k\oplus a_j\ge0$，所以 `ans = 0` 安全；若数值可能为负，初值必须改成极小值。
- **不要把"每位都取多数相反"当成可实现方案。** 那样的数未必存在于数组中，$a_k$ 只能从既有元素里挑，这正是必须枚举 $k$ 的根本原因。

## 总结

异或的价值在于**位独立**：把每个候选那 $n$ 次异或拆成 30 个"数一数有多少个 1"的查表问题，预处理一次 $c_b$ 后每个候选只需 $O(30)$。候选一个都不省，因此正确性无需贪心论证，总复杂度 $O(30n)$。

## 说明

本题目录归在 `greedy` 下，但代码实为"按位拆分统计 + 枚举全部候选"，并不含贪心选择；参考代码与 `ans.cpp` 同构，只做了两处改动：把内层两处乘法（`cnt[j] * t` 与 `(n - cnt[j]) * t`）都显式提升为 64 位（`1LL * ...`），并把内层权值变量与最外层测试数同名的 `t` 改名为 `w`；算法与结构未变。

# P3397 地毯 题解

## 题意

有一个 $n\times n$ 的方格图，依次铺上 $m$ 块地毯。每块地毯给出左上角 $(x_1,y_1)$ 与右下角 $(x_2,y_2)$（1-based），它把这两点围成的整个矩形覆盖一次。要求输出整张图，第 $i$ 行第 $j$ 列的数字表示该格被多少块地毯覆盖。

由代码可确定的两点约定：其一，整张表按 $(n+2)^2$ 的规模存，时间和空间都是 $O(n^2)$ 级别，与原题 $n,m\le 1000$ 的限制吻合（$1002^2$ 个 `long long` 约 8 MB）；其二，输出为 $n$ 行，每行 $n$ 个整数、以单个空格分隔、行末换行，且行末不留多余空格。

用一句话概括这件事的本质：**对 $m$ 个矩形做区间加 1，最后查询每个单点的值。**

## 思路

### 朴素做法的代价

最直白的写法是对每块地毯把矩形内的格子逐一 `+1`。最坏情况下（一块地毯覆盖全图）单块地毯是 $O(n^2)$，总计 $O(mn^2)$；当 $m,n$ 都在千级时这是个 $10^9$ 量级的数，必然超时。瓶颈在于「一次矩形加」被拆成了 $O(n^2)$ 次「单点加」，而最终我们只需要每个点的终值，中间过程完全不必逐格维护。

### 从一维差分到二维差分

一维差分的思想是：想让 $[l,r]$ 整体加 1，不必真的加 $r-l+1$ 次，只在 $d_l$ 处 `+1`、$d_{r+1}$ 处 `-1`；之后对 $d$ 求一遍前缀和，两个标记就把「从 $l$ 开始加」「到 $r$ 停止加」这两件事表达清楚了。差分把一个区间修改压缩成两个端点的修改。

二维要解决的是「矩形的两个方向都要有开关」。设差分数组 $d$，位置 $(i,j)$ 的最终答案就是 $d$ 在它左上方向的二维前缀和：

$$a_{i,j}=\sum_{p\le i}\sum_{q\le j} d_{p,q}$$

反过来说，$d_{x_1,y_1}$ 加上 1，会让**右下角整个区域**（所有 $i\ge x_1,\ j\ge y_1$）全部加 1，而不只是那个矩形。所以要一层层把多出来的部分减回去，这正是二维容斥：

- `d[x1][y1] += 1`：把 $(x_1,y_1)$ 及其右下角全部加 1，这是「起笔」。
- `d[x1][y2+1] -= 1`：矩形右边界之外的列不该被加，用这一笔抵消掉 $j>y_2$ 的那片影响。
- `d[x2+1][y1] -= 1`：同理抵消掉 $i>x_2$ 的那片影响。
- `d[x2+1][y2+1] += 1`：位于 $i>x_2$ 且 $j>y_2$ 的那块区域被上面两笔各减了一次（多减了），加回来一次。

四笔标记合起来，前缀和恰好只把矩形内部点亮。这就是「四角修改」的全部道理：**每块地毯只花 $O(1)$ 次修改。**

### 多开一格与 1-based 下标

四角里出现了 $x_2+1$ 和 $y_2+1$。当地毯贴到边界（$x_2=n$ 或 $y_2=n$）时，这两个下标就是 $n+1$。与其在每处修改前都判一次 `if (x2 + 1 <= n)`，不如直接开 $(n+2)\times(n+2)$ 的数组、只用 $1..n$ 的有效区域，让 $n+1$ 行/列充当「垃圾桶」：写进去的值永远不参与输出，自然也不会造成越界。同时整体采用 1-based 下标，读入的坐标无需减一，从根上消掉了差一错误。

### 一遍前缀和还原

标记打完以后，直接在原地做二维前缀和即可：按 $i$、$j$ 递增的顺序扫描，$d_{i,j}$ 需要用到 $d_{i-1,j}$、$d_{i,j-1}$、$d_{i-1,j-1}$，这三个位置都已经被更新成前缀和，所以一次正向遍历就能完成还原，不必另开数组。还原完的 $d$ 就是答案本身。

## 复杂度

- 时间：打标记 $O(m)$，二维前缀和还原 $O(n^2)$，输出 $O(n^2)$，合计 $O(m+n^2)$。
- 空间：差分数组 $(n+2)^2$ 个元素，$O(n^2)$。
- 与朴素做法的 $O(mn^2)$ 相比，省掉的是「同一块地毯内部的逐格枚举」，把 $m$ 次矩形修改压成了 $O(m)$ 次端点修改。

## 参考代码（C++17）

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n, m;
    cin >> n >> m;

    // 多开一行一列，避免边界特判（下标 1..n 使用，0 行/列不用）
    vector<vector<long long>> d(n + 2, vector<long long>(n + 2, 0));

    for (int k = 0; k < m; k++) {
        int x1, y1, x2, y2;
        cin >> x1 >> y1 >> x2 >> y2;

        // 二维差分：矩形 [x1..x2] × [y1..y2] 加 1
        d[x1][y1]         += 1;
        d[x1][y2 + 1]     -= 1;
        d[x2 + 1][y1]     -= 1;
        d[x2 + 1][y2 + 1] += 1;
    }

    // 二维前缀和还原
    for (int i = 1; i <= n; i++) {
        for (int j = 1; j <= n; j++) {
            d[i][j] += d[i - 1][j] + d[i][j - 1] - d[i - 1][j - 1];
        }
    }

    // 输出
    for (int i = 1; i <= n; i++) {
        for (int j = 1; j <= n; j++) {
            cout << d[i][j] << (j == n ? '\n' : ' ');
        }
    }

    return 0;
}
```

## 易错点

**1. 把差分数组当答案，只加不还原。** 本目录的 `ans.cpp` 就是这一类错误，而且错得比「忘了前缀和」更绕。它给每一行打了列方向的两个标记（`flag[i][y1-1]++`、`flag[i][y2-1]--`），然后试图在同一次扫描里直接出答案，核心是这一句 `ans[i][j] += flag[i][y1 - 1] + flag[i][j];`。

这一行把「标记」和「前缀和结果」混在了一起。`flag[i][y1-1]` 是最左边的 `+1` 标记，被当成常数 1 加给区间内每格；可 `flag[i][j]` 本身并没有被前缀和累加过，它在内部是 $0$、在右端点是 $-1$、在最左端点是 $+1$。于是矩形左边界列拿到 $1+1=2$，中间列拿到 $1+0=1$，右边界列拿到 $1+(-1)=0$。以 $n=3$、单块地毯 $(1,1)-(2,2)$ 为例，它输出

$$\begin{pmatrix}2&0&0\\2&0&0\\0&0&0\end{pmatrix}$$

而正确答案是

$$\begin{pmatrix}1&1&0\\1&1&0\\0&0&0\end{pmatrix}$$

—— 左边界多染一次、右边界整列漏染，染色边界整体错位。

这个错误最阴的地方在于**总量守恒**：设矩形占 $w$ 行、$h$ 列（$h\ge2$；$h=1$ 的退化情形见第 5 条），则每一行贡献 $2+0+(h-2)=h$，全图总和仍然等于 $w\cdot h$。只校验「染色总面积对不对」的检查会放过它，必须逐格比对才会暴露。

**2. 差分的 $-1$ 打在矩形内部而不是右边界之外。** 上面代码写的是 `flag[i][y2-1]`，正确位置应当对应「$y_2$ 的右边一格」（0-based 下是 `y2`），而 `y2-1` 恰好是矩形的最后一列本身；再加上它没做前缀和，这个「停止」标记就只作用在自己这一格上，把最后一列从 $1$ 减成了 $0$。二维版本的对应错误是 `d[x1][y2] -= 1`（应为 `y2 + 1`）：停止位提前了一列，矩形的最后一列同样变成 $0$，整块地毯实际少了右边界那一条。

**3. `flag` 每轮重建，钱花了却没买到正确性。** `ans.cpp` 在 `for (int k = 0; k < m; k++)` 内部重新 `vector` 出一个 $n\times n$ 的 `flag`，再对该矩形的每一行做一次扫描，单块地毯的代价是 $O(n^2)$，总复杂度退化成 $O(mn^2)$ —— 和完全朴素地逐格加 1 一样贵，结果却还是错的。差分数组应当只开一次，所有标记都叠加在它上面，最后统一还原一遍。

**4. 下标体系混乱、边界判断是假的。** `if (y2 - 1 < n)` 恒为真（因为 $y_2\le n$），它起不到任何保护作用，只是把「作者自己也拿不准下标怎么算」写进了代码。0-based 存储配 1-based 输入，$x_1-1$、$x_2-1$、$y_1-1$、$y_2-1$ 四处偏移一路机械减一，看着整齐，反而掩护了「`y2-1` 本该是 `y2`」这个语义错误；而真把 `y2` 改对后，0-based 的 $n$ 列数组又会在 $y_2=n$ 时越界。干净的做法是整体 1-based、数组多开两格。

**5. 单格地毯会被自己抵消。** 当 $y_1=y_2$ 时，`ans.cpp` 的 `++` 和 `--` 落在同一格上，净值为 $0$，这块地毯直接消失。不过抵消只在标记位置算错时才发生：正确的 1-based 差分里 $y_1$ 与 $y_2+1$ 是两个不同格子，单列地毯照样能正常覆盖，所以这不是差分的固有毛病。

**6. 下标越界与值类型。** 打标记时可能出现 $n+1$，数组开成 $n\times n$ 就会越界；`ans2.cpp` 开 $(n+2)^2$ 正是为此。至于数值，答案上限就是 $m$（千级），`int` 足够；用 `long long` 的代价只是内存翻倍（$n\le1000$ 时约 8 MB），换来更抗范围调整的余量。

## 总结

二维差分是「多一维的容斥」：矩形修改被压缩成四个角上的 $O(1)$ 次标记，前缀和负责把这些标记在正确的位置开、正确的位置关。记住三件事就够用：**四角修改、多开一格、只在最后还原一次**。缺了最后一步，差分数组就只是一堆无权重的标记，而不是答案。

## 说明

`ans.cpp` 文件开头已注明「这个答案是错的」，与代码行为一致，故参考代码选用 `ans2.cpp`；此外，该错误版本的实际症状是列方向边界错位（左列 $+2$、右列 $+0$）而非把格子染到矩形之外，因为写入循环仍被限制在矩形范围内。

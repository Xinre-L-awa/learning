# P1204 [USACO1.2] 挤牛奶 Milking Cows 题解

## 题意

输入 $n$ 个挤奶时间段 $[l_i, r_i]$，表示有一个农民在这段时间里给牛挤奶（区间之间可以重叠、包含、首尾相接）。按代码的读入方式，第一行是 $n$，随后 $n$ 行每行两个整数；输出一行两个整数：

1. 最长的、**至少有一个人**在挤奶的连续时长；
2. 最长的、**没有任何人**在挤奶的连续时长。

第二问的空闲只在「从开始挤奶到挤奶结束」之间统计：第一个农民开始之前的空闲、以及最后一个农民结束之后的空闲都不计入。题面对此有明确交代，两份代码也都是这么写的（见「易错点」第 2 条）。

USACO 原题样例：

```text
3
300 1000
700 1200
1500 2100
```

输出 `900 300`：$[300,1200]$ 连续 900 个单位时间有人挤奶，随后 $[1200,1500]$ 空闲 300 个单位时间。

## 思路

两个问题都能从「把所有区间按时间合并成若干极大连续段」得到：每个极大段的长度贡献给答案一，相邻两个极大段之间的空隙贡献给答案二。区别只在于怎么求出这些极大段。

### 解法一：排序 + 合并区间（ans.cpp）

**为什么要排序。** 输入顺序和时间的先后毫无关系，不排好序就无从判断「下一个区间能不能接上当前段」。按左端点 $l$ 升序排即可：合并只需要比较「当前段的右端点」和「候选区间的左端点」。

**为什么只按左端点排就够。** 设当前合并段是 $[s, s+t_1]$。排序后，所有左端点 $\le s+t_1$ 的区间都被视为可吸附，其中右端点最远的那个决定新的右端点；左端点更大的区间不可能是这个连续段的一部分。所以一趟线性扫描就能把一段吃完。

**为什么用「起点 + 长度」而不是「左右端点」。** 代码把区间存成 `s`（起点）和 `l = r - l`（长度），当前段也存成 `s` 与 `t1`，于是右端点统一写成 `s + t1`，加长写成 `t1 += 新右端 - 旧右端`。这样每段只维护两个量，比较全部落在 `s + t1` 上，不容易写错。

**为什么 ans1 在段末、ans2 在段间取值。** 内层 `while` 把所有能接上的区间吸附完，此时 `t1` 才是一个完整的极大段长度，所以 `ans1 = max(ans1, t1)` 必须在 `while` 之后。而空闲只能在两个极大段之间出现：`j` 指向下一段的第一个区间，`ts[j].s - (s + t1)` 就是空隙长度。`j == n` 说明当前是末尾段，后面没有「下一段」，因此不更新 ans2 —— 这就是**末尾段边界**：末尾空闲不计。

**起始就空闲的处理。** 外层循环第一次执行时 `t1 == 0`，直接用 `ts[0]` 初始化当前段，也就是从最早开始的挤奶时刻起算；空隙一律从当前段右端 `s + t1` 量到 `ts[j].s`，起点已经是最早的开始时刻（而不是时刻 0），所以开头的空闲天然不会被统计。

**n == 1 的处理。** 代码专门提前返回 `(长度, 0)`。其实去掉这个分支也是对的：合并完一段后 `j == n`，ans1 得到区间长度、ans2 保持 0。这个分支属于防御性写法，把「只有一个区间时没有空隙」这一点写得更显眼。

### 解法二：事件扫描（ans2.cpp）

**差分视角。** 每个区间在时间轴上就是一次 `+1`（开始）和一次 `-1`（结束），把所有端点按时刻排好序扫一遍，`cnt` 就是「当前时刻有多少人在挤奶」——这正是差分数组「前缀和还原原数组」的思想，只是不真的开数组。

**为什么同一时刻 `+1` 要排在 `-1` 前面。** 一个区间结束、另一个区间同一时刻开始时，如果先减后加，中途会短暂出现 `cnt == 0`，一个本应连续的挤奶段就被切断了。排序时用 `a.f > b.f`（`+1` 大于 `-1`）让加号在前，相接的区间就能连成一片。

**结算方式。** 扫描到时刻 `cur` 时，`cnt` 描述的是「上一事件到 `cur` 之前」这段的状态，所以先按 `[last, cur]` 结算，再执行 `cnt += ps[k].f` 并令 `last = cur`。同一时刻的多个事件里，只有第一个会产生非零长度（后面的 `cur == last`，长度为 0），因此逐个处理也是安全的。

**ans2 在这里是对的。** 当 `cnt == 0` 时，`[last, cur]` 内部不可能夹着任何事件（一有事件 `cnt` 就会变），所以这段恰好就是一个完整的空闲段，`cur - last` 是正确的空闲长度；`start != -1` 只是「至少已经开始过一次挤奶」的守卫。

**ans1 在这里是错的。** `ans1 = max(ans1, cur - last)` 取的是「相邻两个事件之间的跨度」，而不是「一个连续挤奶段的长度」。只要一个极大挤奶段内部还夹着别的事件（重叠、包含、相接都会造成这种情况），它就会被切碎。用上面的样例验证：事件序列为 `(300,+1),(700,+1),(1000,-1),(1200,-1),(1500,+1),(2100,-1)`，代码得到的段长依次是 $400,300,200,600$，输出 `600 300`，而正确答案是 `900 300` —— 真正的挤奶段 $[300,1200]$ 跨了三个事件间隔。事件扫描的正确做法是：`cnt` 由 0 变正时记下段起点，`cnt` 回到 0 时用「当前时刻 − 段起点」更新 ans1（代码里的 `start` 变量本来该干这件事，但它只赋值、且从不重置）。因此参考代码只放解法一。

**边界。** 起始空闲：第一轮 `cur == last`，长度为 0，不计。末尾段：最后一个事件之后不再结算，末尾空闲不计。`n == 1`：两个事件 `(l,+1),(r,-1)` 结算一次 `[l,r]`，得到 `r - l` 和 0。另外代码直接取 `ps[0].i` 初始化 `last`，隐含要求 $n \ge 1$。

## 复杂度

- 解法一：排序 $O(n\log n)$；合并阶段外层指针 `i` 每次跳到 `j`、内层 `j` 单调前进，每个区间最多被访问一次，故合并 $O(n)$。总时间 $O(n\log n)$，空间 $O(n)$。
- 解法二：$2n$ 个事件排序 $O(n\log n)$，扫描 $O(n)$，空间 $O(n)$。
- 若时间轴上界不大，也可以开差分数组再做前缀和，时间做到 $O(n + T)$（$T$ 为时间上界）；本文件夹的两份代码都没有用这种写法。

## 参考代码（C++17）

下面是 ans.cpp（排序 + 合并区间），对上面的样例输出 `900 300`：

```cpp
#include <bits/stdc++.h>
using namespace std;

struct T {
    int s, l;                  // 起点 s，长度 l = 右端 - 左端
};

int main() {
    int n;
    cin >> n;

    vector<T> ts;
    for (int i = 0; i < n; i++) {
        int l, r;
        cin >> l >> r;
        T t;
        t.s = l;
        t.l = r - l;
        ts.push_back(t);
    }

    if (n == 1) {              // 只有一个区间：挤奶长度就是它，空闲为 0
        cout << ts[0].l << ' ' << 0;
        return 0;
    }

    sort(ts.begin(), ts.end(), [](const T& a, const T& b){
        return a.s < b.s;      // 按起点升序，后续才有「接上」可言
    });

    int ans1 = 0, ans2 = 0;
    int t1 = 0, s = 0;         // t1：当前合并段长度；s：它的起点
    for (int i = 0; i < n; ) {
        if (t1 == 0) {
            t1 = ts[i].l;
            s = ts[i].s;
        }

        int j = i + 1;
        while (j < n && ts[j].s <= s + t1) {        // 左端点落在段内就吸附
            if (ts[j].l + ts[j].s > t1 + s) {       // 只有更靠右才延长
                t1 += ts[j].l + ts[j].s - (t1 + s);
            }
            j++;
        }
        ans1 = max(ans1, t1);                       // 段吞完了才是完整长度

        if (j < n) {                                // 后面还有段，才存在空隙
            ans2 = max(ans2, ts[j].s - (t1 + s));
        }
        t1 = 0;
        i = j;
    }

    cout << ans1 << ' ' << ans2;

    return 0;
}
```

## 易错点

1. **不能按区间长度排序。** 合并的前提是时间有序，按长度排序会让「能不能接上」完全失去意义；按左端点升序（或同时按右端点）才是对的。
2. **`ans2` 只应统计「段与段之间」。** 若让当前段的起点从「时刻 0」起算，就会把开头的空闲算进去；`j == n` 时也不能再去取 `ts[j]`——末尾之后没有区间，取了是越界，而且末尾本来就没有可算的空闲。开头和末尾都不进 `ans2`。
3. **`t1 == 0` 兼作哨兵，但并不依赖区间长度。** 每轮末尾都显式写了 `t1 = 0`，所以开头的 `if (t1 == 0)` 实际等价于「开一段新段」，与区间长度是否为正无关。真正要留意的是零长度区间：题面只保证时刻是非负整数，并没有说 $l < r$；若出现 $l = r$，它会成为一段长度为 0 的段，`ans1` 不受影响，但原本连续的空闲会被它切成两半，`ans2` 可能偏小（如 $[0,5],[7,7],[10,20]$ 会得到 3 而不是 5）——这段语义题面没有约定。
4. **`n == 1` 的分支是多余的。** 不加它循环同样会输出 `(l, 0)`；好处只是让「单区间没有空闲」显式化，别把它当成必须的补丁。
5. **事件扫描的 `+1`/`-1` 排序方向。** `a.f > b.f` 才是 `+1` 在前；写反了会让首尾相接的区间断开。但更要紧的坑是 ans1 的结算用错了量：应该是「当前时刻 − 本段起点」，`cur - last` 只算了相邻事件之间那一小截，重叠区间一多就会偏小。
6. **ans2.cpp 没有处理 $n = 0$。** `int last = ps[0].i;` 直接取首元素，本题目数据满足 $n \ge 1$，但换个题面就会越界。
7. **两种存法别混用。** ans.cpp 存「起点 + 长度」，端点运算一律写成 `s + t1`；混入一个「右端点」变量后极易出现差一。

## 说明

本目录名为 differential_algo，但两份代码分别是「排序合并」与「事件扫描」，都没有真正开差分数组，事件扫描只是用 $\pm 1$ 事件体现了差分思想；此外 ans2.cpp 的 ans1 结算与题意不符（样例上会输出 `600 300`），正文因此以 ans.cpp 作为参考实现，与之相关的讨论只放在「思路」「易错点」中。

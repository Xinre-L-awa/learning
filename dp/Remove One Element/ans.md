# Remove One Element 题解

## 题意

给定一个长度为 $n$ 的数组 $a$（由代码可推断 $n \ge 1$，元素按 `int` 读入）。你可以**至多**删除一个元素，也就是说删除后数组长度是 $n$ 或 $n-1$（允许一个都不删）。

要求剩下的数组里，**连续**且**严格上升**的子段最长能有多长，输出这个长度。

注意三个关键词：连续（取的是数组里相邻的一段，不是子序列）、严格上升（相邻两项必须满足 $a_{j} < a_{j+1}$，等号不算）、至多删一个（删零个或一个都合法）。

## 思路

最终答案对应剩下数组里的某一段连续区间 $[x, y]$。把视角放回原数组，只有两种可能：

1. 这一段在原数组里本来就是连续的一段（因为我们删掉的元素在它外面，或者根本没删）；
2. 被删掉的元素 $a_i$ 落在这段**内部**，于是这一段被切成两半 $[x, i-1]$ 和 $[i+1, y]$，删除 $a_i$ 之后两半拼接起来。

这两种情况分别对应下面的两部分计算，缺一不可。

### 预处理两个方向的最长上升段长度

设 $l_i$ 表示**以 $i$ 结尾**的最长严格上升连续段长度，设 $r_i$ 表示**以 $i$ 开头**的最长严格上升连续段长度。它们都是一眼可见的递推：

$$l_i = \begin{cases} l_{i-1} + 1, & a_i > a_{i-1} \\ 1, & \text{否则} \end{cases}$$

$$r_i = \begin{cases} r_{i+1} + 1, & a_i < a_{i+1} \\ 1, & \text{否则} \end{cases}$$

$l$ 从左往右扫一遍，$r$ 从右往左扫一遍，断点处一律重置成 $1$（自己单独成段）。这样 $\max_i l_i$ 就是「一个都不删」时的答案：任意一个连续上升段都以某个下标 $i$ 结尾，而 $l_i$ 至少覆盖该段的长度，所以取最大值就得到最长的那一段。

### 删除中间元素后的拼接

固定被删除的位置 $i$。删掉 $a_i$ 之后，$a_{i-1}$ 的右边邻居变成了 $a_{i+1}$，原本断开的两个上升段有机会接上：

- 左边一段由 $l_{i-1}$ 给出，它只用到了下标 $\le i-1$ 的元素；
- 右边一段由 $r_{i+1}$ 给出，它只用到了下标 $\ge i+1$ 的元素。

两段内部的相邻关系原本就满足严格上升，唯一需要检查的是新接出的那一处：

$$a_{i-1} < a_{i+1}$$

条件成立时，拼接后的长度就是 $l_{i-1} + r_{i+1}$，并且这是删除 $a_i$ 能得到的最优值——因为 $l_{i-1}$ 与 $r_{i+1}$ 本身都已取到最大，换成更短的左段或右段只会更差。所以枚举 $i$ 即可，不需要再枚举段的两端。

### 为什么「不删」必须先算进答案

上面的 $l_{i-1} + r_{i+1}$ 全部建立在「一定删了某个元素」的前提上，它表达不出一个没被切开的完整上升段。如果初始答案只由这些拼接值决定，就会漏掉最优解不删元素的情形。

最典型的反例是数组本身严格上升：正确答案是 $n$（一个都不删），而任何「删中间元素」的拼接最多只能拼出 $n-1$（删掉的那个位置凭空少了一格）。所以必须先把 $\max_i l_i$ 放进答案，再用拼接值去更新它。这也是代码里 `ans` 先扫 $l$ 再扫删除位置的原因。

### 为什么删首尾不会更优

删除 $a_0$ 之后，剩下的数组是原数组的一个后缀，它的任何一个连续上升段同时也是原数组的连续上升段（只是少了个开头），长度不可能超过 $\max_i l_i$，而这个值已经在「不删」里了。删除 $a_{n-1}$ 同理。

从另一个角度看，删首尾**根本制造不出新的相邻关系**，没有「两段拼一段」的收益，唯一的作用是把段剪短，所以不可能让答案变大。因此枚举删除位置时直接跳过首尾，只扫 $i \in [1, n-2]$，同时也避免访问 $l_{-1}$ 这种越界下标。

`ans` 的初值取 $1$ 也是同一个道理：$n = 1$ 时删除位置的循环区间是空的，但剩下一个元素仍然构成长度为 $1$ 的上升段，所以答案下界必须是 $1$。

## 复杂度

时间 $O(n)$：$l$ 一次正向扫描，$r$ 一次反向扫描，答案再扫两遍，都是线性的。

空间 $O(n)$：存数组 $a$ 与两个长度数组 $l, r$。其中 $l$ 其实可以边算边用，但为了写法直观保留成数组。

## 参考代码（C++17）

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<int> a(n);
    for (int i = 0; i < n; i++) cin >> a[i];

    vector<int> l(n, 0), r(n, 0);
    l[0] = 1;
    r[n - 1] = 1;

    // l[i]: 以 i 结尾的最长严格上升连续段长度
    for (int i = 1; i < n; i++) {
        if (a[i] > a[i - 1]) l[i] = l[i - 1] + 1;
        else l[i] = 1;
    }

    // r[i]: 以 i 开头的最长严格上升连续段长度
    for (int i = n - 2; i >= 0; i--) {
        if (a[i] < a[i + 1]) r[i] = r[i + 1] + 1;
        else r[i] = 1;
    }

    // 情况一：一个都不删
    int ans = 1;
    for (int i = 0; i < n; i++) {
        ans = max(ans, l[i]);
    }

    // 情况二：删除中间的 a[i]，两侧可拼接则合并
    for (int i = 1; i <= n - 2; i++) {
        if (a[i - 1] < a[i + 1]) {
            ans = max(ans, l[i - 1] + r[i + 1]);
        }
    }

    cout << ans;

    return 0;
}
```

## 易错点

- **漏掉「不删」的情形**。只对 $l_{i-1} + r_{i+1}$ 取最大值就输出，数组本身严格上升时会少 $1$。正确做法是先用 $\max_i l_i$ 打底。
- **拼接条件写成非严格**。必须判断 `a[i-1] < a[i+1]`；写成 `<=` 会把 $a_{i-1} = a_{i+1}$ 的情况也算成可以拼接，答案偏大。
- **枚举范围包含首尾**。删首尾既不会更优，又会访问 `l[i-1]` / `r[i+1]` 的越界下标；循环应为 `1` 到 `n-2`。
- **$r$ 端点未初始化**。$r$ 从右往左推，循环里 $i = n-2$ 时就要读 `r[n-1]`，所以进入循环前必须显式写出 `r[n-1] = 1`；漏掉它，靠右整条链上的值都会少 $1$。同理 `l[0] = 1` 也不能省。断点处还要显式赋 $1$，否则会沿用旧值。
- **$n = 1$ 的边界**。此时删除位置的枚举区间 $[1, n-2]$ 为空，一个候选都不产生，答案完全依赖 $\max_i l_i = l_0 = 1$，所以 `ans` 的初值取 $1$。
- **不要忘记 $l_{i-1} + r_{i+1}$ 是删掉 $a_i$ 后的长度**，被删的那个位置不计入长度，所以不是 $l_{i-1} + r_{i+1} + 1$。

## 总结

核心是把「删一个」这件动作用两个方向的前后缀 DP 拆开：$l$ 负责断点左边的长度，$r$ 负责断点右边的长度，中间靠 $a_{i-1} < a_{i+1}$ 一个条件判断能否接上。再补上「不删」的基线答案、去掉对首尾的无意义枚举，整个问题就是四遍线性扫描。

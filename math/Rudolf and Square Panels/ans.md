# Rudolf and Square Panels 题解

## 题意

题意说明（依据代码实现）：读入一个整数 $n$，求把 $n$ 表示成若干个完全平方数之和所需的**最少个数**，输出这个个数。

由拉格朗日四平方定理，答案只可能是 $1,2,3,4$ 之一。代码只读入一个 $n$（没有多测的 `t`），只输出一个整数。按代码口径，$1$ 也算完全平方数（$1=1^2$），且用来做加数的平方数都取自 $a^2\ (a\ge 1)$。

## 思路

从"最省"往"最费"逐级判定，一旦命中就立刻输出：

**第一级：$n$ 本身是完全平方数 → 1。** 一项就够，不可能比 1 更少。

**第二级：$n$ 是两个平方数之和 → 2。** 枚举较小的那个加数 $a$，检查 $n-a^2$ 是否为完全平方数即可。为什么枚举范围只要 $a^2<n$：若 $n=a^2+b^2$ 且不妨设 $a\le b$，则

$$2a^2 \le a^2+b^2 = n \implies a^2 \le \frac n2 < n,$$

所以需要枚举的 $a$ 其实都落在 $a^2\le n/2$ 里。代码用的界更宽（$a^2<n$，约 $\sqrt2$ 倍长度），多出来那段的 $a$ 只会把已经数过的 $(a,b)$ 反序再判一遍，不影响正确性与复杂度。$a$ 从 $1$ 开始，是因为 $a=0$（即 $n$ 是平方数）的情形已经在第一级处理掉了，不必重复判断。

**第三级：拉格朗日四平方定理封顶。** 任何正整数都能写成四个平方数之和，所以前两级都失败时，答案只可能是 $3$ 或 $4$，问题缩小为"区分 3 和 4"。

**第四级：勒让德三平方定理判 3 还是 4。** 定理给出：$n$ 能写成三个平方数之和，当且仅当 $n$ 不具有 $4^a(8b+7)$ 的形状。于是把 $n$ 中所有因子 $4$ 除掉，得到 $t$，再看 $t \bmod 8$ 是否为 $7$：

- $t \equiv 7 \pmod 8$：说明 $n=4^a(8b+7)$，三平方不可能；又已知不能用 1 个或 2 个（若能用 $1$ 个或 $2$ 个，补零就是 $3$ 个的表示，与"三平方不可能"矛盾），故答案恰为 $4$。
- 否则：三平方可行，故答案恰为 $3$。

**为什么因子 $4$ 必须除干净。** "$\equiv 7 \pmod 8$"这个特征会被因子 $4$ 掩盖：$n=28=4\cdot 7$，$28 \bmod 8 = 4$，看上去毫无问题，但它确实是 $4$ 个平方数（$28=25+1+1+1$）；必须除掉一次 $4$ 得到 $7\equiv 7\pmod 8$ 才能识别。只除一次也不够，$n=112=16\cdot 7$ 要除两次才露出 $7$，所以代码用的是 `while` 而不是 `if`。

**`isSquare` 里修正开方结果的写法。** 用 `sqrtl((long double)n)` 求整数开方，浮点结果可能在真值上下差 $1$（`long double` 也躲不开舍入），直接拿去比较会误判。代码因此做了双向修正：

- `while ((r + 1) * (r + 1) <= n) ++r;` —— 猜小了，往上顶；
- `while (r * r > n) --r;` —— 猜大了，往下压。

两个循环结束后必然有 $r=\lfloor\sqrt n\rfloor$，此时再判 $r^2=n$ 就是严格精确的整数判断，与浮点精度彻底脱钩。

## 复杂度

- 时间：第二级枚举 $a$ 至多 $\sqrt n$ 项，每项 $O(1)$，合计 $O(\sqrt n)$；第一、三、四级为常数级（除 $4$ 至多 $O(\log n)$ 次）。总体 $O(\sqrt n)$。
- 空间：$O(1)$，只用了几个 `long long` 变量。

## 参考代码（C++17）

```cpp
#include <bits/stdc++.h>
using namespace std;

using ll = long long;

bool isSquare(ll n) {
    ll r = sqrtl((long double)n);
    while ((r + 1) * (r + 1) <= n) ++r;
    while (r * r > n) --r;
    return r * r == n;
}

bool isSumOfTwoSquares(ll n) {
    for (ll a = 1; a * a < n; ++a) {
        if (isSquare(n - a * a)) {
            return true;
        }
    }
    return false;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    ll n;
    cin >> n;

    if (isSquare(n)) {
        cout << 1 << '\n';
    } else if (isSumOfTwoSquares(n)) {
        cout << 2 << '\n';
    } else {
        ll t = n;
        while (t % 4 == 0) t /= 4;

        if (t % 8 == 7) {
            cout << 4 << '\n';
        } else {
            cout << 3 << '\n';
        }
    }

    return 0;
}
```

## 易错点

1. **两平方和的枚举边界。** 若写成 `a = 0` 起、`a * a <= n`，就会重复处理 $n$ 本身是平方数的情况（此时 $b=0$，凑出的其实是"一个平方数"），与第一级语义冲突。代码 `a = 1` 配 `a * a < n`，两个端点同时正确。
2. **用 `(ll)sqrt(n)` 直接判平方。** 在 $n$ 是完全平方数时，`sqrt` 有时返回略小的值，取整后 $r^2\ne n$，答案直接错档。必须按代码那样把 $r$ 修正到 $\lfloor\sqrt n\rfloor$ 再比较。
3. **除 $4$ 写成 `if`。** `while (t % 4 == 0) t /= 4;` 必须是循环，`if` 只能剥掉一层 $4$，$n=16\cdot 7=112$ 之类的数据会误判成 $3$。
4. **求余的对象搞错。** 是除干净之后的 $t \bmod 8$，不是原 $n \bmod 8$。反过来，若先判 $n \bmod 8$ 再除 $4$，$28$ 这种会被漏掉。
5. **顺序不能换。** 必须先排除 1 个和 2 个平方数，才能用"不是 $4^a(8b+7)$ 就是 3"这句结论。例如 $n=4$ 若跳过第一级，$t=1$、$1\bmod 8=1\ne7$，会输出 $3$，而正确答案是 $1$；$n=2$ 若跳过第二级，也会错输出 $3$ 而正确答案是 $2$。
6. **开方修正里的乘法溢出。** `(r + 1) * (r + 1)` 在 $n$ 逼近 `long long` 上限（约 $9.2\times10^{18}$）时有溢出风险；本文不臆测题面给出的数据范围，只说明代码在常见规模（$n$ 不逼近上限）下无虞。

## 总结

答案 $1$ 与 $2$ 用"直接验证"拿下（$2$ 只需 $O(\sqrt n)$ 枚举一个加数），剩下的部分交给两个经典定理：拉格朗日四平方定理保证上界是 $4$，勒让德三平方定理给出"$3$ 还是 $4$"的判别式——去掉全部 $4$ 的因子后看余数是否为 $7$。

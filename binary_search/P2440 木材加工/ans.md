# P2440 木材加工 题解

## 题意

有 $n$ 根原木，第 $i$ 根长 $L_i$。要把它们切成若干段**长度完全相同**的小段，要求切出的总段数不少于 $k$，问小段长度最大是多少；连 $k$ 段长度为 $1$ 的小段都切不出来时输出 $0$。

由代码可推断的几点：

- 每根木头独立切割，剩下的边角料直接丢弃——代码里没有任何把两段拼起来、或者跨木头凑长度的逻辑；
- $L_i$ 存进 `int`、上界 `h` 也是 `int`，所以 $L_i$ 落在 `int` 范围内；
- "能切出多少段"用 `long long` 承接，说明它可能超过 `int`（最大可到 $\sum L_i$，即每段长度为 1 时）；
- 需要对 $k\ge 1$ 成立，否则答案没有上界，下面取的 $h=\max L_i$ 也不再是合法上界。

## 思路

### 判定：固定长度，能切多少段

若每段长度定为 $x$，第 $i$ 根木头最多出 $\lfloor L_i/x\rfloor$ 段，总段数为

$$f(x)=\sum_{i=1}^{n}\left\lfloor \frac{L_i}{x}\right\rfloor .$$

$x$ 可行当且仅当 $f(x)\ge k$。注意是 $\ge$ 而不是 $=$：多切出来的段可以不用，所以代码写 `t >= k`。

### 单调性：为什么能二分

$x$ 变大时 $\lfloor L_i/x\rfloor$ 只减不增，因此 $f$ 关于 $x$ 单调不增。可行的正整数 $x$ 于是组成一段前缀 $[1,X]$，$X$ 就是答案。合法集合是"前缀"这件事正是二分的依据：判定了中点，就能整体排除一半区间。代码用 `ans` 记住最后一次 `f(mid) >= k` 的 `mid`，循环结束时它就是 $X$（$X=1$ 是例外，见下文 `mid == 0` 一节）。

### 上界为什么是 $\max L_i$

取 $h=\max_i L_i$。当 $x>h$ 时每根木头都满足 $L_i<x$，于是 $\lfloor L_i/x\rfloor=0$，即 $f(x)=0<k$（由 $k\ge1$），所以答案必 $\le h$。

这个上界成立的关键是它只用了"**最长的那一根**"：$f$ 允许某些项为 $0$，短木头一根都不切也完全合法。

### 为什么不取 $\lfloor s/k\rfloor$（$s=\sum L_i$）

它其实也是合法上界：由 $\sum\lfloor L_i/x\rfloor\le s/x$ 与 $f(x)\ge k$ 可得 $x\le s/k$。但作为实现它更差：

- $k$ 很小时它比 $h$ 大得多（例如 1000 根长 10 的木头、$k=1$ 时 $s/k=10000$，而 $h=10$），二分区间白白变宽；
- 它把"总长度"和"根数"混在一起，整除细节容易写错，还要额外维护 $s$；
- 它的紧凑程度依赖 $n$ 与 $k$ 的关系，而 $h$ 的紧凑只依赖一句显然的事实（任何一段都来自某一根木头），解释起来干净得多。

顺带说，参考代码里的 `long long s` 和 `s += L[i];` 就是这一思路的残留，算了却没用上。

### 为什么必须防 $mid=0$

长度 0 不是合法小段；更实际的是 `f` 里做的是整数除法，$L_i/0$ 是未定义行为，本地会崩、评测上是运行时错误。所以 `mid == 0` 必须挡，代码用 `break` 挡住它。

但 `break` 只是一层除零保护，不能当成"答案必为 0"的判据：中点取到 0 时，区间只可能是 $[0,0]$ 或 $[0,1]$。

- $[0,0]$：$x=1$ 刚被判过且不满足，答案确实是 0，提前收场无害；
- $[0,1]$：$x=1$ 还没被判过（$h=1$ 时第一次中点就是 0），若 $f(1)\ge k$，真答案是 1，代码却输出 0。

后者不是纸上谈兵：$n=1$、$L=(10)$、$k=6$ 时 $f(1)=10\ge6$、$f(2)=5<6$，答案应为 1，参考代码输出 0。要彻底避开，把左端点取成 1（`int l = 1, r = h`）：既没有 0 做除数，也不会跳过 $x=1$，`ans` 仍从 0 起算，"无解输出 0"照旧成立。

## 复杂度

- 单次判定 $f(x)$ 扫一遍所有木头：$O(n)$。
- 二分区间长度 $h=\max L_i$，迭代 $O(\log h)$ 次；`h` 是 `int`，故不超过约 31 次。
- 总时间复杂度 $O(n\log h)$，额外空间 $O(n)$（存木头长度）。

## 参考代码（C++17）

```cpp
#include <bits/stdc++.h>
using namespace std;
using ll = long long;

ll f(const vector<int>& a, int k) {
    ll ans = 0;
    for (const int& i : a) {
        ans += i / k;
    }
    return ans;
}

int main() {
    int n, k;
    cin >> n >> k;
    vector<int> L(n);
    int h = 0;
    long long s = 0;
    for (int i = 0; i < n; i++) {
        cin >> L[i];
        s += L[i];
        h = max(h, L[i]); // 此处最初写的是 min(h, L[i] / k), 然后是 max(h, L[i] / k)，
                          // 前者只是保证每根木头都能切，后者在此基础上扩大了范围，但二者
                          // 没有考虑到当 l > L[i] 时，第i根木头切割结果为0
    }

    int l = 0, r = h, ans = 0;
    while (l <= r) {
        int mid = (l + r) / 2;
        if (mid == 0) break;
        ll t = f(L, mid);
        if (t >= k) {
            l = mid + 1;
            ans = mid;
        } else {
            r = mid - 1;
        }
    }

    cout << ans;
}
```

## 易错点

1. **上界收成"每根木头都至少切一段"**。用 $\min_i\lfloor L_i/k\rfloor$ 或 $\max_i\lfloor L_i/k\rfloor$ 收紧上界，等于要求"每根都出 $k$ 段"或"有一根出 $k$ 段"，而题目只要求总段数够。反例：$L=(100,3)$、$k=3$ 时答案是 $33$（长木头独自出 3 段），但 $\min_i\lfloor L_i/k\rfloor=1$；$L=(10,10)$、$k=4$ 时答案是 $5$（两根各出 2 段），但 $\max_i\lfloor L_i/k\rfloor=2$。两种界都会把真答案排除在区间外，这正是代码注释里说"当 $l>L_i$ 时第 $i$ 根木头切割结果为 0"的意思。
2. **漏掉 `mid == 0`**。这不只是少判一个特例，而是整数除零：本地会崩，评测上表现为运行时错误而不是 WA。另有一层：`mid == 0` 时顺手 `break` 并不等于"答案就是 0"（反例见上文 $L=(10)$、$k=6$）；把 `int l = 0` 改成 `int l = 1`，除零与丢 $x=1$ 两个隐患一起消失。
3. **计数用 `int`**。总段数可达 $\sum L_i$ 量级，必须 `long long`；累加总长度时同理。
4. **判定写成 `t == k`**。要求是"不少于 $k$ 段"，写成相等会漏掉大量可行长度。
5. **给"切不出的木头"特判**。$\lfloor L_i/x\rfloor=0$ 对求和无影响，不需要跳过，更不该因此缩小上界。
6. **`ans` 忘了初值 0**。所有 $mid\ge1$ 都不满足时，输出必须是 0。
7. 输出没有换行（`cout << ans;`），本题不影响判题，但别为此改动判定逻辑。

## 总结

长度越大越难满足 $k$ 段，答案具有单调性，所以"最大化长度"可以换成"二分长度 + $O(n)$ 判定"；判定只看 $\sum\lfloor L_i/x\rfloor\ge k$。上界取 $\max L_i$ 的理由是"比最长那根还长就一段都切不出来"，而不是"每根木头都切得动"。

## 说明

文件夹名与代码行为一致（二分答案求最大小段长度，无解输出 0）；代码中 `long long s` 及 `s += L[i]` 是早期用 $\sum L_i/k$ 作上界时的残留、不参与判定，`mid == 0` 的 `break` 只起除零保护作用，不能当作"答案为 0"的出口（`int l = 0` 改成 `int l = 1` 即可修正，其余逻辑不变）。

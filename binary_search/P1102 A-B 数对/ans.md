# P1102 A-B 数对 题解

## 题意

给出 $n$ 个整数和一个整数 $c$，统计满足下式的下标对数：

$$a_j - a_i = c$$

输入格式由代码可推断为一行 `n c`，再一行 $n$ 个整数；输出一个整数表示数对个数。不同位置的相同数值算作不同的数对——两份解都是按**位置**逐个累加，而不是按**数值**去重后累加。

难点只有一个：$n$ 可能很大（`ans2.cpp` 用 `LL a[200001]` 开静态数组，可推断 $n \le 2\times 10^5$），两两枚举的 $O(n^2)$ 会超时，必须把"枚举配对"降成"查某个值出现了几次"。

## 思路

**第一步：把差值等式变成一次查值。** 原式移项得

$$a_j = a_i + c$$

把原式看成 $A-B=c$ 并固定减数 $B=a_i$：能与之配对的 $A$ 只有唯一候选值 $B+c$。于是"数有多少对"就等于"数 $B+c$ 在数组中出现了多少次"，让每个位置都当一次 $B$ 即可：

$$ans = \sum_{i=1}^{n} \mathrm{cnt}(a_i + c)$$

其中 $\mathrm{cnt}(v)$ 表示 $v$ 在原数组中的出现次数。这一步改写的意义在于：把 $n^2$ 次两两比较，压成了 $n$ 次频次查询，问题从"找配对"变成"查频次表"。

**第二步：cnt 怎么算，两条路。** 这正好对应两份代码。

- `ans.cpp`：先 `sort`，再用 `lower_bound`/`upper_bound` 定位等于 $a_i+c$ 的连续区间 $[lo,\,hi)$，区间长度 $hi-lo$ 就是 $\mathrm{cnt}(a_i+c)$。排序的作用是把相同数值聚成一段，"值相等"因此变成"一段连续的相等"，二分才能找到这段的左端（第一个 $\ge$）与右端（第一个 $>$），两者相减就得个数。若数组无序，二分无从下手——这也是为什么"排序 + 二分"是绑定出现的。
- `ans2.cpp`：把等式再移项成

$$B = A - c$$

在**读入时**先用 `map` 统计原始数值的频次 $m[x]=\mathrm{cnt}(x)$，紧接着把 $a_i$ 就地减去 $c$（此后 $a_i$ 存放的是"若它是 $A$，配对的 $B$ 应该是谁"），最后单独一个循环查 $m[a_i]$ 累加。两个循环分工明确：第一个建表，第二个只查表，把 $n$ 次插入与 $n$ 次查询拆开处理，同一份答案公式换个载体实现。

**第三步：重复元素为什么不用特判。** 求和是对**位置**求和，不是对数值求和。若某数值出现 $f$ 次，它作为 $B$ 会被累加 $f$ 次，且每次加的都是完整的 $\mathrm{cnt}(B+c)$，所以该数值总共贡献 $f \times \mathrm{cnt}(B+c)$ 对——这恰好是"$f$ 个位置"与"$\mathrm{cnt}(B+c)$ 个位置"之间所有有序组合的数目。因此重复元素既不需要去重，也不能去重：去重后 $f$ 变成 1，就会漏掉 $f-1$ 倍的答案。两份代码里 `lower_bound` 区间长度与 `map` 频次，本质都是在保留这个"重数"。

**第四步：答案为什么必须是 long long。** 单个位置贡献的 $\mathrm{cnt}$ 最多到 $n$，总和是 $n^2$ 量级。按 $n \le 2\times 10^5$ 估，最坏可达约 $\frac{n}{2}\cdot\frac{n}{2}\approx 10^{10}$，远超 `int` 上限 $\approx 2.1\times 10^{9}$。两份代码都把 `ans` 声明为 `long long` / `LL`；`ans.cpp` 里 `hi - lo` 的类型是 `ptrdiff_t`，也是宽整型，不会在累加前就截断。此外 `ans2.cpp` 把 `c` 和 `a[i]` 都设为 `LL`：一旦输入量级大到 $a_i\pm c$ 越过 `int` 边界，`int` 会静默回绕，`map` 的键随之算错——它不报错，只交一个错的答案，比崩溃难查得多。

## 复杂度

| 解法 | 时间复杂度 | 空间复杂度 |
| --- | --- | --- |
| `ans.cpp`（排序 + 二分） | $O(n\log n)$：排序一次 $O(n\log n)$，$n$ 次二分每次 $O(\log n)$ | $O(n)$ 存数组 |
| `ans2.cpp`（map 计频） | $O(n\log n)$：$n$ 次插入 + $n$ 次查询，每次 $O(\log n)$ | $O(n)$，不同数值个数不超过 $n$ |

两者渐近复杂度相同，常数却差得多：`ans.cpp` 是连续内存上一次 `sort` 加二分，缓存友好；`ans2.cpp` 是红黑树逐结点分配，而且没有 `ios::sync_with_stdio(false)`、输出用了 `endl` 强制刷新，实际耗时常慢数倍。

## 参考代码（C++17）

解法一：排序后对每个 $B$ 二分出 $A=B+c$ 的出现区间。

```cpp
#include <bits/stdc++.h>
using namespace std;
using ll = long long;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n; ll c;
    cin >> n >> c;
    vector<ll> a(n);
    for (int i = 0; i < n; i++) cin >> a[i];
    sort(a.begin(), a.end());

    ll ans = 0;
    for (int i = 0; i < n; i++) {
        ll target = a[i] + c;                       // A = B + C
        auto lo = lower_bound(a.begin(), a.end(), target);
        auto hi = upper_bound(a.begin(), a.end(), target);
        ans += hi - lo;                             // 该 target 出现几次就贡献几对
    }
    cout << ans << '\n';
    return 0;
}
```

解法二：读入时用 `map` 记频次，同时把 $a_i$ 就地改成 $A-c$，再逐位查表。（下面照抄 `ans2.cpp` 原文，只去掉该文件整体多出的一层缩进。）

```cpp
#include <iostream>
#include <map>
using namespace std;
typedef long long LL;
LL a[200001];
map<LL,LL> m;//建立一个数字到出现次数的映射 map<num,times>
//A-B=C --> A-C=B
int main() {
    int n;
    LL c;
    LL ans=0;
    cin >> n >> c;
    for(int i=1;i<=n;i++) {
        cin >> a[i];
        m[a[i]]++;
        a[i]-=c;
    }
    for(int i=1;i<=n;i++) ans+=m[a[i]];
    cout << ans << endl;
    return 0;
}
```

## 易错点

1. **答案用 `int` 溢出。** 总数是 $n^2$ 量级，$10^{10}$ 装不进 32 位整型，`ans` 必须是 `long long`。两份代码的累加项本身够宽——`ans.cpp` 的 `hi - lo` 是迭代器之差（`ptrdiff_t`），`ans2.cpp` 的 `m[a[i]]` 直接是 `LL`——所以问题只会出在 `ans` 的声明上；同理，别在别处先把这个计数收进一个 `int` 变量再累加。
2. **只找一个位置，漏算重复元素。** 若把 `lower_bound` 的结果当作命中（找到一次就 `ans++`），同一数值的多份拷贝只算一次；必须用 `hi - lo` 取整段长度才是完整频次。
3. **两个二分必须查同一个目标值，且不能查成 `a[i]`。** `lo` 与 `hi` 的目标一旦不一致（例如一个查 $a_i+c$、一个查 $a_i$），相减得到的就不再是"某个值出现了几次"，甚至可能算出负数。而把目标写成 `a[i]` 本身是另一种错：它数的是"与 $a_i$ 相等的元素个数"，累加得 $\sum f^2$，对应的是 $A-B=0$ 而不是 $A-B=c$。顺带一提，写成 `a[i]-c` **也是对的**——那只是把求和从"枚举 $B$ 数 $A$"换成"枚举 $A$ 数 $B$"，总数不变（`ans2.cpp` 正是这么做的）；真正错的是查 `a[i]` 本身。
4. **`ans2.cpp` 的两步顺序不能交换。** 必须"先 `m[a[i]]++`，再 `a[i] -= c`"。若先减，频次表的键变成 $B$，后面查 `m[a[i]]` 仍查 $B$，等价于在数 $B-B=0$ 的数对，答案全错。
5. **`ans2.cpp` 的数组长度是写死的。** `LL a[200001]` 且下标从 1 开始，等价于要求 $n \le 2\times 10^5$；$n$ 更大就会越界写，表现为 RE 或莫名其妙的错乱，而不是报错提示。
6. **$c=0$ 时自配对也会被计入（本题 $c$ 是正整数，不会触发）。** 两份代码都是"每个位置查一次"，当 $c=0$ 时 $i=j$ 也会被数进去。若 $c>0$，则 $a_i+c>a_i$，自配对不可能出现，代码无需额外处理；只有 $c=0$ 的题目才要扣掉这 $n$ 个自配对（或改为不计自身位置）。
7. **`endl` 与未关闭的同步流。** `ans2.cpp` 用了 `endl`（每次刷新缓冲）且没写 `ios::sync_with_stdio(false)`，$n$ 大时 I/O 开销不可忽略；它不是逻辑错误，但常是它比 `ans.cpp` 慢的原因。

## 总结

核心只有一句移项：$A-B=C \iff A=B+C$，把"数配对"换成"数频次"。载体有两种——排好序的数组用 `lower_bound`/`upper_bound` 框出相等区间，或平衡树（`map`）直接把频次挂在值上；前者常数小、后者思路短。重复元素靠"按位置求和"自然保留重数，两者都无需特判；计数规模达 $n^2$，一律用 `long long` 收尾。

## 说明

文件夹名 P1102 A-B 数对与代码语义一致（统计 $a_j-a_i=c$ 的下标对），两份代码实现的是同一个公式，只是求和方向不同：`ans.cpp` 枚举减数 $B$ 去数 $B+c$，`ans2.cpp` 枚举 $A$ 去数 $A-c$，两者数的是同一批有序下标对，所以答案必然相同。

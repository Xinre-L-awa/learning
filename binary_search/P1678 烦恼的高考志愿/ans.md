# 烦恼的高考志愿 题解

## 题意

给定 $m$ 所院校的预计分数线 $a_1,a_2,\dots,a_m$，以及 $n$ 位学生的估分 $b_1,b_2,\dots,b_n$。为每位学生独立推荐一所院校，使「院校分数线与本人估分之差的绝对值」尽量小，求所有学生该最小差值之和。

由代码可推断，输入为：第一行两个整数 $m,n$；随后 $m$ 个整数是院校分数线；再随后 $n$ 个整数是学生估分。代码把估分放在循环里边读边算，说明各学生之间互不影响，只需逐项累加：

$$ans=\sum_{j=1}^{n}\ \min_{1\le i\le m}\bigl|a_i-b_j\bigr|$$

## 思路

### 1. 为什么要先排序

整个算法只有一种操作：对一个给定的估分，在分数线集合里找最近的值。而 `lower_bound` 的前提是区间有序，所以读完全部分数线后先 `sort` 一次。

排序还有第二个用处，也是更本质的：只有在有序数组上，「最近的分数线」才会落在可预测的位置上，从而把一次 $O(m)$ 的扫描降成一次二分。下面就来证明它只可能出现在两个位置。

### 2. 固定估分，最近值只可能在两处

设当前估分为 $x$，令

$$p=\operatorname{lower\_bound}(a,x)$$

即 $a_p$ 是第一个满足 $a_p\ge x$ 的元素。考察 $f(i)=|a_i-x|$：

- 当 $i<p$ 时必有 $a_i<x$，于是 $f(i)=x-a_i$。因为 $a_i$ 随 $i$ 单调不减，$f(i)$ 在 $[0,p)$ 上单调不增，最小值在 $i=p-1$ 处取得。
- 当 $i\ge p$ 时必有 $a_i\ge x$，于是 $f(i)=a_i-x$，在 $[p,m)$ 上单调不减，最小值在 $i=p$ 处取得。

也就是说，排序之后 $f(i)$ 关于下标是一个「先降后升」的 V 形函数，谷底只能落在 $p$ 或 $p-1$。于是

$$\min_{1\le i\le m}\bigl|a_i-x\bigr|=\min\Bigl(\bigl|a_p-x\bigr|,\ \bigl|a_{p-1}-x\bigr|\Bigr)$$

越界的项直接略去。这就是「只比较 `lower_bound` 位置和它前一个位置」的全部理由：不是在偷懒，而是由有序性保证了其余候选必然更差。注意 $f(i)$ 在整个数组上并不单调（而是先降后升的 V 形），所以仅凭 `lower_bound` 找到了 $a_p\ge x$ 就断定它最近是错的——$x$ 完全可能更靠近左边的前驱，这正是必须同时比较 $p$ 与 $p-1$ 的原因。

### 3. 三种落点对应三种候选集合

$p$ 只有三种可能，代码用 `if / else if / else` 一一列出：

| 落点 | 含义 | 存在的候选 |
| --- | --- | --- |
| $0<p<m$ | 落在中间 | $a_p$ 与 $a_{p-1}$，取较小者 |
| $p=m$ | $x$ 比所有分数线都大（落在末尾） | 只有 $a_{m-1}$ |
| $p=0$ | $x$ 不大于最小分数线（落在开头） | 只有 $a_0$ |

第一个分支同时要求 `it != a.end()` 和 `it != a.begin()`，正是「两侧都还在」；第二个分支处理右边没有元素的末尾情况，只能取最后一个；剩下的兜底分支就是左边没有元素的开头情况，只能取第一个。这样写的好处是三种边界全部显式写在代码里，既不用哨兵（如塞一个 $+\infty$），也不会误读到不存在的元素。

### 4. 为什么累加要用 `long long`

每一项 $|a_i-b_j|$ 单独看都不大，但答案是 $n$ 项之和。单个差值的量级最多与分数值域同阶，项数是学生人数：即使分数只有 $10^6$ 量级、学生只有 $10^5$ 个，最坏也能累到 $10^{11}$，早已越过 `int` 的 $2.1\times 10^9$。所以 `ans` 必须声明成 `long long`。

代码里 `min(abs(...), abs(...))` 的中间结果仍是 `int`，这没有问题：单个差值本身不会溢出，它只是被加进 `long long` 累加器。真正危险的是把累加器本身写成 `int`。

### 5. 每位学生独立决策

题目只要求「每位学生各自最近」的差值之和，并没有「一所院校只能推荐一名学生」的约束，因此不需要排序后双指针匹配，也不需要任何全局优化：逐个二分、各自取 min 即可。同一所学校被多名学生选中是完全合法的。

## 复杂度

- 排序：$O(m\log m)$。
- 每个学生一次 `lower_bound`：$O(\log m)$，共 $n$ 次。
- 总时间复杂度：$O(m\log m+n\log m)$，空间复杂度 $O(m+n)$（估分其实不必存，用一个临时变量即可）。

## 参考代码（C++17）

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int m, n;
    cin >> m >> n;
    vector<int> a(m), b(n);
    for (int i = 0; i < m; i++) {
        cin >> a[i];
    }
    sort(a.begin(), a.end());
    long long ans = 0;
    for (int i = 0; i < n; i++) {
        cin >> b[i];
        auto it = lower_bound(a.begin(), a.end(), b[i]);
        if (it != a.end() && it != a.begin()) ans += min(abs(*it - b[i]), 
                                                         abs(*(it - 1) - b[i]));
        else if (it == a.end()) ans += abs(*(it - 1) - b[i]);
        else ans += abs(*it - b[i]);
    }

    cout << ans;

    return 0;
}
```

## 易错点

1. **只查 `lower_bound` 的位置，漏掉它的前驱。** 反例：分数线 $\{0,100\}$，估分 $40$。下界落在 $100$，但 $|0-40|=40<60=|100-40|$，最近的是前一个元素。这是本题最典型的错误。
2. **把 `it - 1` 写成 `it + 1`。** 有序性保证「小于 $x$ 的部分」全在左边，前驱才是另一侧候选的代表；查后继没有依据，而且 `it` 指向末尾时还会越界。
3. **边界只处理一头。** `it == a.end()` 时不能解引用 `*it`，`it == a.begin()` 时不能解引用 `*(it - 1)`；代码用「中间 / 末尾 / 开头」三个分支分别只取存在的候选。另外代码隐含 $m\ge 1$：若分数线个数为 $0$，`begin()` 与 `end()` 重合，会一路走到 `*(it - 1)` 上解引用无效迭代器。
4. **累加器用 `int`。** 理由见上一节，$n$ 项相加必然溢出，必须 `long long`。
5. **`abs(*it - b[i])` 的潜在溢出。** 这里是先做 `int` 减法再取绝对值；若分数线接近 `INT_MAX`，减法本身就会溢出。当前数据量级下不会触发，要防守可写 `llabs((long long)*it - b[i])`。
6. **忘记 `sort`。** 在无序区间上 `lower_bound` 既不报错也不崩溃，只会返回无意义的位置，答案静默出错，比崩溃更难查。
7. **多做一步「给学校去重」或以为一校只收一人。** 相邻重复值不会影响取 min；而限制一校一人属于匹配问题，与本题代码的语义不符。

## 总结

- 有序数组上的最近值查询：一次 `lower_bound` 之后，候选只剩「下界位置」和「其前驱」两个，依据是 $|a_i-x|$ 关于下标呈 V 形。
- 三种落点（中间 / 末尾 / 开头）把候选集合收缩成两个或一个，用显式分支写出来最不容易错。
- 答案按学生人数累加，`long long` 是必需的，$O(m\log m+n\log m)$ 足够快。

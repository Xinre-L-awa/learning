# P1873 砍树 题解

## 题意

由代码可推断：第一行给出 $n$ 与 $m$，第二行给出 $n$ 棵树的高度 $h_i$。选定一个统一的锯口高度 $H$，第 $i$ 棵树能贡献的木材是

$$\text{wood}(H)=\sum_{i=1}^{n}\max(0,\,h_i-H)$$

要求在所有满足 $\text{wood}(H)\ge m$ 的 $H$ 里，取最大的那个并输出。题目数据 $1\le n\le10^6$、$1\le m\le2\times10^9$，且保证 $\sum h_i>m$，所以 $H=0$ 一定可行。注意两个版本都用 64 位及以上的累加方式处理高度总和，说明木材总量会远超 `int` 范围；`ans2.cpp` 更是直接把 $m$ 读成 `long long`。

## 思路

### 判定：给定高度能砍多少

一旦 $H$ 定死，只需要扫一遍数组把每棵树超过 $H$ 的部分累加，得到 $\text{wood}(H)$。这一步是 $O(n)$，没有任何技巧，但它就是整个算法的“探针”：只要这个探针能快速回答“$H$ 行不行”，剩下的问题就是“试几个 $H$”。

### 为什么可以二分：单调性

把 $\max(0,h_i-H)$ 看作 $H$ 的函数：$H$ 变大时它只会变小或不变（锯得越高，剩下的树桩越高，能砍走的木头越少）。有限个单调不增函数相加，结果仍然单调不增，所以

$$H_1<H_2 \;\Longrightarrow\; \text{wood}(H_1)\ge \text{wood}(H_2)$$

于是可行集合 $\{\,H:\text{wood}(H)\ge m\,\}$ 一定是一段前缀 $[0,H^\ast]$，不会出现“中间可行、更高又可行”的跳跃。题目要的正是这个前缀的右端点 $H^\ast$，即“最后一个可行值”——这正是二分答案的标准形状：判定条件在数轴上单调，答案落在可行与不可行的分界处。

### 二分怎么写

`lo = 0, hi = max(h)`，闭区间二分。每次取 `mid`，算一次 $\text{wood}(mid)$：

- $\text{wood}(mid)\ge m$：$mid$ 可行，但更大的高度也可能可行，所以用 `ans = mid` 记下当前最好答案，再往右找 `lo = mid + 1`；
- $\text{wood}(mid)< m$：$mid$ 已经砍不够了，由单调性所有更高的高度都不可行，往左收缩 `hi = mid - 1`。

用 `ans` 变量而不是直接输出 `lo-1`，是因为 `lo` 在退出时停在“第一个不可行位置”，而答案需要单独记录；在保证有解的前提下两者等价，但记 `ans` 更不容易在边界上写错。`mid` 写成 `lo + (hi - lo) / 2` 是防止 $lo+hi$ 溢出的习惯写法，本题数值不大，但保持这个习惯。

### 上界为什么取 max(h)

若 $H=\max h_i$，则每个 $\max(0,h_i-H)$ 都是 $0$，$\text{wood}=0$。所以：

- 当 $m>0$（正常输入）时，$\max h$ 必然不可行，答案严格更小，二分一定会往左走；
- 当 $m=0$ 这种边界时，$\max h$ 恰好是答案，二分一定会把 `ans` 更新到它。

两种情况 `hi = max(h)` 都覆盖，既不会把答案切在区间外，也不会多试一个明显无意义的高度。在 $m>0$ 的数据下，取更大的上界（比如 $10^9$ 或 `max(h)+1`）结果也对，只是多花常数次判定；但若沿用上面 $m=0$ 的边界，上界一旦放大，输出也会跟着放大到上界本身，而不是 $\max h$。取更小的上界则会漏解。

### `ans.cpp` 的问题：枚举次数与 `int` 溢出

`ans.cpp` 的判定加速做得很好：先排序，用前缀和 `pre` 存下排序后的高度和；对当前高度 `ans`，用 `upper_bound` 找到第一个严格大于 `ans` 的位置 `idx`，于是

$$\sum_{i}\min(h_i,\text{ans})=\text{pre}[idx-1]+\bigl(n-idx\bigr)\cdot \text{ans}$$

（前 `idx` 个元素都不超过 `ans`，贡献就是自身；后面的元素都被截到 `ans`），再用 `总和 - 这个值` 就得到 $\text{wood}$。单次判定的代价是 $O(\log n)$ 的 `upper_bound` 加 $O(1)$ 前缀和，非常漂亮。

但它的外层是 `while (true)` 里的 `ans++`：从高度 $0$ 开始一格一格往上试，退出时 `ans` 停在第一个不可行高度，所以最后输出 `ans - 1`。问题在于这个方法把“每次判定”优化到了极致，却没有优化“判定的次数”——最坏要从 $0$ 试到 $\max h$。按原题接近 $10^9$ 的高度上限，总代价

$$O(\max h \cdot \log n)$$

是 $10^9$ 级别的循环，每次还要做一次 `upper_bound` + 一次前缀和查询，常数再小也躲不过超时。换句话说，它把 $O(n)$ 的判定换成了 $O(\log n)$ 的判定，却把二分能带来的 $O(\log \max h)$ 次判定退化成了 $O(\max h)$ 次判定——判定次数是它在原题上限下的瓶颈。

但即使把高度上限降到洛谷当前题面的 $4\times10^5$，让枚举次数降下来，`ans.cpp` 仍有一个更直接的正确性问题：`idx == 0` 分支里的 `(n - idx) * ans` 是 `int × int`，而 `n` 可达 $10^6$、`ans` 可达 $\max h$，乘积最大到 $10^{15}$ 量级（按 $4\times10^5$ 上限也有 $4\times10^{11}$），远超 `int`。溢出后 `s` 变成无意义的值，`wood` 随之错误，循环可能在错误的位置停下，最终输出错解。另一分支写了 `(ll)(n - idx) * ans`，恰好说明作者只提升了其中一个分支——这不是“潜在风险”，而是这条路在大数据上会 WA 的直接原因。

另外两个细节：`ll s = pre[n-1];` 这一行在进入循环后立刻被覆盖，是死代码；`idx == 0` 的特判是为了避开 `pre[-1]`，此时所有树都高于 `ans`，$\sum\min=n\cdot\text{ans}$。

## 复杂度

- `ans2.cpp`（正解）：单次判定 $O(n)$，二分共 $O(\log \max h)$ 轮，总时间 $O(n\log \max h)$，空间 $O(n)$。以 $n=10^6$、原题 $\max h=10^9$ 计，约 $3\times 10^7$ 次加法，很快。
- `ans.cpp`：排序 $O(n\log n)$，之后最多枚举 $O(\max h)$ 个高度、每次判定 $O(\log n)$，总时间 $O(n\log n+\max h\log n)$，空间 $O(n)$（两份数组）。按原题 $10^9$ 的高度上限，枚举项主导并导致超时；按洛谷当前 $4\times10^5$ 上限，枚举约 $4\times10^5$ 轮（约 $8\times10^6$ 次比较），时间上不再是主要障碍，但上一节说的 `int` 溢出仍会让答案出错。

## 参考代码（C++17）

取自本目录的 `ans2.cpp`，即二分高度的正解。

```cpp
#include <bits/stdc++.h>
using namespace std;
using ll = long long;

int main() {
    int n; ll m;
    cin >> n >> m;
    vector<ll> t(n);
    for (int i = 0; i < n; i++) cin >> t[i];

    ll lo = 0, hi = *max_element(t.begin(), t.end()), ans = 0;
    while (lo <= hi) {
        ll mid = lo + (hi - lo) / 2;
        ll wood = 0;
        for (int i = 0; i < n; i++)
            if (t[i] > mid) wood += t[i] - mid;
        if (wood >= m) { ans = mid; lo = mid + 1; }  // 够，试着更高
        else hi = mid - 1;                            // 不够，降低
    }
    cout << ans;
    return 0;
}
```

## 易错点

1. **累加必须 64 位**。$n$ 棵树、原题每棵高度接近 $10^9$，总木材是 $10^{15}$ 量级；即便按洛谷当前 $4\times10^5$ 的高度上限，也有 $10^{11}$ 量级，`int` 一定溢出；`wood`、前缀和、高度数组都要 `long long`。
2. **$m$ 也要用 64 位读**。`ans2.cpp` 用 `ll m` 是对的；`ans.cpp` 用 `int m`（见 `int n, m;`），把两个版本对照着看就能体会这类题“输入规模天然要求 64 位”的习惯。
3. **二分的区间与更新方向要配套**。`wood >= m` 时答案可行但可能还能更高，所以是 `ans = mid; lo = mid + 1;`，方向写反会直接得到错误的最优值；`while (lo <= hi)` 配闭区间，别同时用 `lo < hi` 和 `mid + 1` 的写法混搭。
4. **`ans.cpp` 里的 `int` 溢出**：`(n - idx) * ans` 是 `int × int`，只有右边那个分支被 `(ll)` 提升过。当所有树都高于当前高度（`idx == 0`）且 `ans` 还很大时，这个乘积可达 $10^{15}$ 量级（按 $4\times10^5$ 上限也有 $4\times10^{11}$），远超 `int`，会溢出成无意义的值——这不是“潜在风险”，而是 `ans.cpp` 在大数据上会 WA 的直接原因；二分版本没有这个乘法，完全没有这个问题。
5. **不要在 `ans.cpp` 的思路上继续打补丁**。它的单次判定已经很快（$O(\log n)$），但 `(n - idx) * ans` 的 `int` 乘法会溢出；就算把乘法修好，逐个试高度的框架在高度上限大时仍会被判定次数拖垮。换成 `ans2.cpp` 的二分，既避开这个乘法，又把判定次数降到 $O(\log \max h)$。

## 说明

目录名为 `binary_search`，但 `ans.cpp` 实际是“从 0 开始逐格枚举高度 + 前缀和加速判定”的写法，不含二分；二分高度的是 `ans2.cpp`。`ans.cpp` 另有 `s = pre[n-1]` 的死赋值，以及 `(n - idx) * ans` 的 `int` 溢出——后者在 `n` 与 `ans` 都大时会让答案直接出错，不只是“隐患”。

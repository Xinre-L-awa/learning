# Beautiful Triple Pairs 题解

## 题意

给定长度为 $n$ 的序列 $a$。由代码可推断，这里讨论的三元组是**连续**的三个元素：

$$b_i=(a_i,\ a_{i+1},\ a_{i+2}),\qquad 0\le i\le n-3,$$

共 $n-2$ 个。若两个下标不同的三元组 $b_i,b_j$ 满足「恰好有两个位置上的数相同」（等价于恰好一个位置不同），就说它们构成一对美丽三元组对，求这样的对数。

多组测试数据：先读入组数 $t$，每组读入 $n$ 和长度为 $n$ 的序列，每组单独输出一行答案。

## 思路

### 一、只和「更早」的三元组配对

固定右端点 $j$，只统计 $i<j$ 的配对，这样每一对无序配对 $(i,j)$ 都恰好在 $j$ 这一步被数一次。问题于是变成：**对每个新三元组，数出它前面有多少个三元组与它恰好一位不同**，累加即可。下文说的「前驱」都指 $i<j$ 的三元组。

### 二、把「两位相同」拆成三个二维投影

对三元组 $(x,y,z)$ 定义三种「丢掉一个位置」的指纹：

$$P_{12}(x,y,z)=(x,y),\qquad P_{13}(x,y,z)=(x,z),\qquad P_{23}(x,y,z)=(y,z).$$

代码用 `map<tuple<int,int,int>, int> cnt` 存这些指纹，**第三维的 `0/1/2` 只是命名空间标记**，用来区分上面三种指纹（它不是被统计的数据）。另外用 `map<tuple<int,int,int>, int> c` 单独记录完整三元组 $(x,y,z)$ 出现了多少次。

### 三、容斥：每个前驱到底贡献几次

设当前三元组为 $b$，某个前驱为 $c$。三处查询分别是「与 $b$ 有相同 $P_{12}$」「相同 $P_{13}$」「相同 $P_{23}$」的前驱个数，所以 $c$ 对这次累加的贡献，恰好等于它和 $b$ **同时命中的投影个数**：

| $b,c$ 相同位置数 | 命中的投影数 | 说明 |
| :--: | :--: | :-- |
| 3（完全相同） | 3 | 三个投影全部命中 |
| 2（恰好一位不同） | 1 | 只命中「两个相同位置」对应的那一个投影 |
| 1 | 0 | 每个投影里都含有那个不同的位置 |
| 0 | 0 | 同上 |

关键在第一、二行：**恰好一位不同的对并不会被三组映射各算一次，而是只被算一次** —— 两位相同的组合唯一，只对应 $P_{12},P_{13},P_{23}$ 中的一个；另外两个投影都含有那个不同的位置，必然不命中。真正被重复计算的是**完全相同**的对：它同时命中三个投影，被算了 3 次。

于是设 $S$ 为三处查询结果之和，$n_3$ 为完全相同的前驱个数，$n_2$ 为恰好一位不同的前驱个数，就有

$$S=3n_3+n_2\quad\Longrightarrow\quad n_2=S-3n_3,$$

这正是代码里那几条 `ans += cnt[{x, y, 0}]`、`ans += cnt[{x, z, 1}]`、`ans += cnt[{y, z, 2}]` 与 `ans -= 3LL * c[{x, y, z}]` 的净效果；把这几行合并成一个赋值就是 `ans += cnt[{x,y,0}] + cnt[{x,z,1}] + cnt[{y,z,2}] - 3LL * c[{x,y,z}]`。所以减 $3$ 倍不是「多减」，而是把完全相同的那批从 3 次压回 0 次；恰好一位不同的那批本来就只记了 1 次，不需要再修正。

### 四、流程

1. 读入 $a$，令 $ans=0$，两个 map 清空（代码里直接定义在每组数据内部）。
2. 依次枚举 $i=0,1,\dots,n-3$，取出 $(x,y,z)=(a_i,a_{i+1},a_{i+2})$：
   - 先查询并累加 $cnt[(x,y,0)]+cnt[(x,z,1)]+cnt[(y,z,2)]$，再减去 $3\cdot c[(x,y,z)]$；
   - 然后把三个指纹和完整三元组的出现次数各 $+1$，供后面的下标使用。
3. 输出 $ans$。

用 `[]` 查询不存在的键会插入一个 $0$，对结果没有影响。

### 五、为什么要用 map、为什么是 long long

- **map**：序列元素被读入 `int`，值域可能很大，指纹没法直接当作数组下标，只能建「指纹 → 次数」的字典；`tuple` 自带字典序比较，`map` 可以直接用。若改用 `unordered_map`，必须自己为 `tuple`/`pair` 提供哈希函数，否则无法编译。
- **long long**：$n$ 个元素最多产生 $\binom{n-2}{2}$ 个配对，即 $O(n^2)$ 量级；$n$ 取 $2\times10^5$ 时答案已达 $2\times10^{10}$，远超 `int` 的约 $2.1\times10^9$。因此 $ans$ 必须是 `long long`，写成 `3LL *` 也是为了让这个乘法显式地在 64 位下进行。map 里的计数本身最多是 $n$，`int` 足够。

## 复杂度

单组数据：枚举 $n-2$ 个三元组，每个做常数次 map 操作，每次 $O(\log n)$，故时间为 $O(n\log n)$，空间 $O(n)$（`cnt` 至多 $3(n-2)$ 个键，`c` 至多 $n-2$ 个键）。总体是各组之和，即 $O(\sum n\log n)$。若换成哈希表，期望可以做到每组 $O(n)$。

## 参考代码（C++17）

```cpp
#include <bits/stdc++.h>
using namespace std;
using ll = long long;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int t;
    cin >> t;
    while (t--) {
        int n;
        cin >> n;
        vector<int> a(n);
        for (int i = 0; i < n; i++) cin >> a[i];

        ll ans = 0;
        map<tuple<int, int, int>, int> cnt;   // 三种二维指纹，第三维 0/1/2 是命名空间
        map<tuple<int, int, int>, int> c;     // 完整三元组 (x,y,z) 的出现次数

        for (int i = 0; i < n - 2; i++) {
            int x = a[i], y = a[i + 1], z = a[i + 2];

            ans += cnt[{x, y, 0}];
            ans += cnt[{x, z, 1}];
            ans += cnt[{y, z, 2}];

            ans -= 3LL * c[{x, y, z}];

            cnt[{x, y, 0}]++;
            cnt[{x, z, 1}]++;
            cnt[{y, z, 2}]++;
            c[{x, y, z}]++;
        }

        cout << ans << '\n';
    }
    return 0;
}
```

## 易错点

1. **标记位不能省。** 三种指纹必须落在互不相交的键空间里。例如 $b=(1,2,3)$、前驱 $c=(1,5,2)$：$b$ 的 $P_{12}=(1,2)$，而 $c$ 的 $P_{13}=(1,2)$，不带标记就会撞键，把只相同一个位置的 $c$ 误算进来。`0/1/2` 分别代表 $P_{12},P_{13},P_{23}$ 三个不同的「投影世界」。
2. **减的是 $3$ 倍，不是 $1$ 倍。** 完全相同的前驱在三次查询里共被累加 3 次，只减 1 倍会残留 $2\cdot(\text{完全相同的对数})$ 个非法配对。
3. **别只插一半。** 当前三元组必须同时写入三个指纹和 `c`。查询与插入的先后顺序在本写法里恰好是安全的（若先插入，当前元素自己在三处查询里各贡献 1、在 `c` 里也贡献 1，$-3$ 正好抵消），但只往 `cnt` 或只往 `c` 里插入就会破坏平衡，习惯上仍应先查询后插入。
4. **多组数据要换新容器。** 代码把两个 map 定义在 `while (t--)` 内部，天然互不干扰；若提到循环外而忘记 `clear()`，上一组的数据会污染下一组。
5. **答案量级。** 用 `int` 存 $ans$ 在 $n$ 较大时会溢出成负数，必须用 `long long`。
6. **边界。** $n<3$ 时 `i < n - 2` 不成立，循环体不执行，输出 $0$，不会越界。

## 总结

这套做法的本质是：**用「丢掉一个位置」的投影，把「两位相同」这一条件拆成三个可以用字典分别统计的二维匹配；再用 $S=3n_3+n_2$ 把完全相同的那批（被算了 3 次）一次性扣掉。** 之所以能「一减就干净」，是因为恰好一位不同的对只命中唯一一个投影，本来就只被计数一次。凡是「恰好 $k$ 位相同」的配对计数，都可以先统计「与某个投影相同」的总量，再按各类被重复的次数做线性修正。
